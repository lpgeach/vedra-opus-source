## A mistake: one update check went to GitHub

`e2e/updates.spec.ts` was included in the run against the package. Its first test presses Help → Check for Updates expecting a development build ("Updates are checked in installed copies"). A package does check, at its configured feed: this repository's GitHub releases. So that run most likely made one request to github.com:

- anonymous, with no project or personal data;
- answered "not found", since the repository is private.

The test failed (1 failed), as it should against a package. Session 108 had run only the Phase 11 test against a package, with `VEDRAOPUS_UPDATE_FEED` pointing at this machine.

**Rule from now on:** never run `updates.spec.ts` against a package. Give a package a local feed (`VEDRAOPUS_UPDATE_FEED=http://127.0.0.1:9/`) whenever a test might check for updates (pitfall #164).

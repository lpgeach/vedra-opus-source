## 2. The feedback website (`lpgeach/vedra-opus-feedback`, private)

Next.js 16.4.6, React 19.3, Zod 4.6.7, `@vercel/blob` 2.9.0, at `C:\Users\lukeg\Repositories\vedra-opus-feedback`. Its README says how it works and how to set it up on Vercel.

- **The form (`/`):**
  - kind, area of the app, summary, details, and steps (shown for bugs);
  - up to three screenshots, chosen or pasted. The browser scales them to 2000 px and WebP (JPEG where WebP can't be written), and the server checks their bytes: only PNG, JPEG or WebP;
  - a 1–5 rating, version and computer (filled in from `?v=&os=`, or the user agent), and optional name, email and permission to email.
- **Storage:** each submission is `feedback/<reference>.json` in a **private** Blob store, with screenshots under `attachments/<reference>/`. The IP address is used only for the rate limit, never stored. Locally, and in tests, a folder or memory store stands in. On Vercel without a store, the site refuses to save rather than write to a temporary disk.
- **The inbox (`/admin`):**
  - sign-in with `ADMIN_PASSWORD`; the cookie is an HMAC of its expiry, HttpOnly and SameSite=Strict;
  - filter by status and kind, read entries with their screenshots (served through a session-checked route), mark new, read or done, delete, and export CSV (with formulas defused) or JSON.
- **Spam:** a hidden field, a minimum time to fill in, and 5 per 10 minutes per address. The limit counts in memory per instance, so it is a best effort; the README suggests a Firewall rule.
- **Security headers:** nosniff, `X-Frame-Options: DENY`, same-origin referrer, `no-store` on admin pages, and `noindex`.
- **`npm audit`:** `@vercel/blob` brought in an old Zod (4.1.11, GHSA-mrhx-c7xc-m3w5) through `@vercel/cli-config`. An `overrides` entry points it at the site's own Zod 4.6.7; the audit now reports 0.
- **Not deployed:** that needs Luke's Vercel account. The steps are in the site's README.

**Verified (Windows):**

- **The built site, run locally with curl:**
  - the version and computer are filled in;

**Fixed on the way** (found by the build and the walk-through):

- **With no `ADMIN_PASSWORD` at build time, `/admin` and `/admin/login` were built as static pages.** Deployed that way, they would have stayed a redirect even after the password was set. The session check now reads the cookies first, so the pages are always rendered per request.
- **An empty form sent quickly got a fake "thank you".** The fill-time check ran before validation. Validation now comes first. Test added.
- **The form had no `method`.** A press before the page's script loaded would have sent the answers, including the email, in the address as a GET. It now posts to the API.
- **An empty `startedAt` read as 0**, so the submission looked slow, not bot-fast. Test added.

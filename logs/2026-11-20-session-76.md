## Found and fixed

- **Fields, sliders, dials and 360° images did not work inside a group in a course (P9.2, P9.4 and P9.10, with groups).**
  - A group's view gave each part only its state and visibility, and the player synced top-level objects only.
  - So a bound field or slider inside a group never showed its variable's changes, a dial did not turn, and a 360° image was never drawn.
  - **The fix:** the group's view now carries each part's value, control value and visited spots (`ObjectPart`), and the player finds and syncs those parts too.
  - **Tests:** an engine test, and player browser tests for a grouped slider and dial and a grouped 360° image in Chromium and Firefox. Both browser tests fail without the fix.
- **Pasting from another project failed for anything with media but a picture.**
  - `preparePaste` left out only pictures whose file the receiving project lacked. A sound, video, 360° image or web folder made the paste fail validation. This predates Phase 9 for sound and video.
  - **The fix:** it now leaves out any object whose media is missing, using the model's new `assetsOfObject`, and says so.
  - **Tests:** a clipboard test.
- **A narrow window scrolled the whole editor sideways** (found while finishing P9.11; fixed there, see session 75).

## Noted, not changed (for Luke)

- **A drop lands on the topmost object under the dragged object's middle, by its frame** (P9.7's rule).
  - A large object above the target catches the drop: for example a web object shown as a "new window" button, whose frame is bigger than the button.
  - The Phase 9 e2e met this and puts the web object first. A rule of "only objects named by a drop trigger count" would avoid it.
- **Lucide's notice in published courses** (P9.8): still the open question in `docs/licences.md`.

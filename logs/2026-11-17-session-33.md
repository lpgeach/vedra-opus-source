## Done

- **Brief** `docs/briefs/P5.5-cmi5.md`, written after the code (see Mistakes). The P5.4 brief is corrected:
  - a score is sent with passed and failed, not with completed;
  - the xAPI driver now sits on the shared LRS driver.
- **Player:**
  - `xapiDriver` became `lrsDriver` plus a **profile**: one transport (queue, retry, State API, keepalive) for any LRS-based standard.
  - The xAPI profile takes its auth from the launch; its behaviour is unchanged, and its 14 unit tests still pass.
  - `lms/cmi5.ts`, the cmi5 profile:
    - the launch needs `endpoint`, `fetch`, `actor`, `registration` and `activityId`;
    - it trades the fetch URL for a token, kept in `sessionStorage` so a reload reuses it;
    - it reads `LMS.LaunchData`, and plays untracked if that is missing;
    - every statement is built on the context template; cmi5-defined statements carry the cmi5 category, and completed, passed and failed also carry the `moveon` category and a duration;
    - Browse and Review modes send no completion;
    - when `moveOn` needs a pass, completing an ungraded course passes it;
    - never failed after passed;
    - the return URL.
  - `startCourse` returns a `CoursePlayer` with `exit()`. It tells the LMS the learner is leaving, then goes to the return URL. Nothing calls it until the "exit course" trigger (P8.6).
- **Publish:** `publishCmi5` writes `cmi5.xml`: one assignable unit, the unit id is the course id plus `/au`, and `moveOn` comes from the reporting pair. `isIri` is shared with xAPI.
- **Tests:**
  - Player unit tests: 9 for cmi5.
  - Publish unit tests: 3 for cmi5.
  - LMS browser tests: a new 7-test cmi5 spec.
  - `mock-lrs.ts` now also plays the cmi5 LMS: one-use fetch URLs, `putState` for launch data, and state keys that compare agents by content.

## What was done

- **Model, format 31:**
  - `drag: { returnToStart } | null` on every object; only one at the top of a layer may have it;
  - the trigger events `draggedOver` and `droppedOn` (object, target), `intersects` and `stopsIntersecting` (object, other);
  - `object.update` takes `drag` and refuses it inside a group; grouping clears it;
  - removing an object removes the triggers that name it as a target or other (`find.ts`);
  - migration 30 → 31 sets `drag: null` everywhere (groups, banks, masters); legacy fixture `v30-two-slides`.
- **Engine:**
  - `carry` and `drop` take a draggable object that is not a question's tile; its view says `draggable`;
  - the object under its middle shows Drag Over, gets "dragged over" when that object changes, and "dropped on" when it is let go there;
  - a drop keeps the object where it was let go (saved and resumed in the slide's `m`), or with `returnToStart` leaves it where it was;
  - intersections: the pairs triggers name are checked at the start of every flush, with each box where it is drawn (motion paths, drops, the carried position). A slide's first check only notes what overlaps.
- **Player:** nothing new was needed: its pointer dragging already carries any object whose view says `draggable`.
- **Editor:**
  - the Format panel's **Dragging** section (top-level objects): "Learners can drag it", then "Goes back after it is dropped";
  - the trigger wizard's four events, and their sentences ("when the learner drops Rectangle 1 on Rectangle 2", "when A intersects B").

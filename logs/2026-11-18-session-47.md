## Done

### Step A (commit `d1d41a6`)

- **Saved format 14:**
  - `Question` is now a discriminated union on `kind`;
  - the choice kinds are `multipleChoice`, `multipleResponse` and `trueFalse` (`isChoiceQuestion`, `ChoiceQuestion`);
  - the other kinds score and give feedback by question only;
  - new kinds: `fillInBlank` (entry, answers, caseSensitive), `numeric` (entry, conditions, with between inclusive), `matchingDropdown` (pairs of item text and dropdown, match, shuffle), `sequenceDropdown` (steps of dropdown and text);
  - new objects: `textEntry` (placeholder, numeric) and `dropdown` (options);
  - migration 13 → 14 (version only) and the `v13-two-slides` legacy fixture.
- **`model/src/questions.ts`:** what each kind is made of, so nothing else needs to know the kinds:
  - `questionObjects` (each named object with its role and type), used by validation and by the engine;
  - `questionPartIds`, used for unique ids;
  - `withoutObjects`, used by `object.remove`;
  - `renewPartIds`, used for copies.
- **`createQuestionSlide(kind, stage)`** lays out every kind.
- **Engine:**
  - **Marking:** `markAnswer(question, { chosen, values })` returns `{ answered, correct, score }` for every kind, with `readNumber` accepting a comma as the decimal mark.
  - **Input:** `engine.input(objectId, value)` takes what is typed or chosen, refused once the question is finished. `ObjectView.value`, `.options` (shuffled dropdown options) and `.locked` report it.
  - **Shuffling:** matching dropdowns when `shuffle` is set; sequence dropdowns always.
  - **Saving:** inputs go in `SavedQuestion.v`, kept on revisit and on resume.
  - **A fix:** a restored session now resumes the question even when the slide had nothing else saved (`enterQuestion(rt, forcedResume)`).
- **Suspend codec:** carries `v` (rule 17), and restores `c` only for choice questions.
- **Render:** text entries and dropdowns are real `<input>` and `<select>` elements in a course (`liveMedia`, now documented as "live in a course"), and boxes in the editor.
- **Player:**
  - `input` and `change` events go to `engine.input`;
  - `drawFields` keeps values, shuffled options and the disabled state in step;
  - typing in a field no longer counts as a key press, for triggers or for moving between slides.
- **Editor:**
  - **Insert → Question**, a menu of the seven step-A kinds, replaces P7.1's two buttons;
  - **Form View** has an answers section per kind (`QuestionAnswers.tsx`): choices; acceptable answers with case; numeric conditions; matching pairs that keep every dropdown's options in step; sequence steps;
  - `QuestionWords.tsx` is the shared field;
  - the type select is offered only between multiple choice and multiple response.

### Step B so far (in this session's last commit)

- **Model:** the kinds `wordBank` (words as tiles, a blank), `matchingDrag` (item tiles on target shapes, shuffle) and `sequenceDrag` (step tiles); `createTile` and `createDropTarget`; their layouts in `createQuestionSlide`. Tiles and targets are ordinary shapes.
- **Engine:** `markAnswer` cases for the three. `values` holds the object ids: of the word in the blank; of each item's target; of the steps in the order left.
- **Editor:** their names, and a plain "not editable here yet" note in Form View. They are **not** in the Insert menu yet, so authors cannot make them.

## Where this stopped

**Next, in order:**

1. **Step B, engine runtime.**
   - **`engine.drop(itemId, x, y)`**, with the drop point in stage units (the item's middle). It finds the target under the point:
     - **word bank:** only the blank takes a word, and a word already there goes back;
     - **matching drag:** a target holds one item, and one already there goes back;
     - **sequence drag:** dropping on another step's place swaps the two.
     - The item snaps to the target's middle. Dropped anywhere else, it goes back.
   - **Store** placements by part position in `SavedQuestion.v`, as object ids, which matches what `markAnswer` already expects. For sequence, the order starts as `o` (always shuffled).
   - **Draw** placements through `ObjectView.offset`, as `shuffleOffset` does. Report `ObjectView.draggable` for an unfinished question's tiles.
   - **Lock** when finished. **Shuffle** matching items' places when `shuffle` is set.
   - **Tests:** extend `graded.test.ts`, and add the suspend round trip.
2. **Step B, player.**
   - Pointer drag on elements whose view is `draggable`:
     - move the element with `translate` during the drag (screen pixels ÷ the stage's `data-scale`);
     - on release, call `engine.drop`;
     - a press without movement is still a click.
   - Browser tests in both browsers.
   - Note that keyboard dragging is not offered; the dropdown kinds are the accessible way for now, and P10.1 owns it.
3. **Step B, editor.**
   - Form View for the three kinds: words (with correct, add, delete); pairs (item and target words, add, delete); steps (in the right order, add, delete, move swapping tile places).

   - Extend `e2e/graded.spec.ts`.
4. **Step C, hotspot.**

## Found and fixed

- **CI never ran the player or LMS browser tests.** The browser job ran only `test:visual`, so the whole of Phase 5's browser testing, and P3.2's player tests, would not run in CI once it resumes. The job ("Browsers") now runs `test:player` and `test:lms` too. CI is still not triggered (`[skip ci]`).
- **`project.setTracking` (P5.1) was missing from the undo/redo property test.** The step has been added.
- **The 4 → 5 migration's result was not checked**, only that the old file loads. A test now checks that a v4 project gets the default publish settings and keeps its tracking.
- **Publish dialog, seen in screenshots:**
  - Its width changed with the target, so it jumped when switching. It now has a fixed width.
  - In a small window, the SCORM 2004 form pushed Cancel and Publish out of view. The buttons now stay pinned to the bottom.
  - The reporting choice was called "Reporting" here and "Tell the LMS the course is" in the Tracking dialog. Both now use the Tracking dialog's words.
- **The e2e suite filled `/tmp`.** One full run left about 1.3 GB, so the review's second full run hit the quota and 8 tests failed for that reason alone. Pitfall #37 had named the fix and it had never been made. Every Playwright config now has a global setup and teardown (`e2e/temp-dir.ts`) that gives each run one temporary folder and deletes it at the end. Checked: after e2e and LMS runs, nothing is left in `/tmp`.
- **Stale documentation:**
  - `skills/scorm-xapi.md` was still the generic text from project setup. It recommended a `scorm-builder` package and `localStorage`, neither of which we use. It is rewritten: the standards, where the code is, and the rules learned in Phase 5.
  - The README said the LMS drivers live in `publish` (they are in the player), and its command table was missing `test:player` and `test:lms`.
- The mocks the e2e test needed were made reusable: the SCORM 2004 mock API and `serveFolder()` now live in `packages/publish/browser/serve.ts`.

## What was found, and done

- **Media.**
  - **Kinds:** two MP4s were listed under `<media>`, so they were taken as pictures and refused. The kind now comes from the type.
  - **TIFF and BMP:** a TIFF was refused, as the app takes neither. Both are now converted to PNG by our ffmpeg, which decodes them.
  - **Guesses:** the 27 guesses were mostly Storyline's recompressed pictures, whose recorded `bytes` match no stored file. A part lists one media relationship per use, in order, so each use now votes for a file, and the votes break ties (pitfall #170). Pictures with a recorded pixel size are left to part B's size check.
- **Captions:** a video or sound names its caption file with `ccG`. They are read with `parseCaptions` and put on the media.
- **Shapes:** polygons, trapezoids, chevrons, arrows, the pentagon arrow, the X and the L are now polygons, using the proportions in `prstGeom` where Storyline stores them. Frames, cans and rounded, cloud and line callouts stay reported.
- **Triggers:**
  - jump to scene, falling back to the scene's first slide;
  - "when the state of these objects changes" (slide-, layer- or object-owned, over several objects with "all");
  - "between" as two conditions, and "equal, ignoring case" as `==`, reported;
  - triggers waiting for an animation the course no longer has are left out without a word, as Storyline never runs them;
  - a file outside the course is reported plainly.

## 2026-11-26: the first CI run on the public repository, and its fixes (`wp/ci-fixes`)

CI ran for the first time since 2026-11-16, on the public repository. It failed for three reasons, none of them a fault in the app:

1. **`scripts/build-ffmpeg.sh` with a relative output folder** (as CI passes it) built into its own temporary folder, then deleted it. Only `vo-decode` reached the artifact (152 KB), so Windows tried to build ffmpeg itself and stopped.
   - Since R1 (2026-11-23, after CI was turned off); local builds pass a full path.
   - Fixed: the script makes its output folder a full path first.
2. **The Verify job never installed Playwright's Chromium,** which the e2e tests open published courses in, so they failed at launch on Linux and macOS. Fixed: an install step.
3. **WebKit:**
   - The new B16 dial test read 51 for 50. WebKit puts the pivot a fraction of a pixel away, which at 60 px from it moves the value. The test now presses 140 px away (still on the dial), and still expects 50 exactly.
   - `video.spec.ts:234` is the known WebKit media-timing failure. It still fails, and wants its own look.

Checked here: the script's syntax and its path handling; the dial test in Chromium and Firefox. **Not checked:** WebKit and the whole CI, which run only on the public repository.

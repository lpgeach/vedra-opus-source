## Decisions (differences from the brief)
- `undo()` during a gesture cancels the gesture and stops, rather than also undoing the previous step.
- Changes have a fourth source, `cancel`, for abandoned gestures.
- An insert index past the end is an error rather than being clamped.
- Content inserted by a command is always checked against its schema and for id collisions; whole-project validation is opt-in (`validate: true`) because it is too slow for every step of a drag.
- Projects handed out by the history are deeply frozen. `createHistory` freezes the project it is given.

### Decisions
- Native dialogs are stubbed from tests via `answerDialogs` rather than a test-only path in the app.
- Zip entries are extracted only if their name is `project.json`, `meta.json` or `assets/<64 hex>.<ext>`, to fixed locations. Everything else is ignored.
- Save and save-as receive the document from the renderer, so they never depend on autosave timing.
- Every autosave message is fully validated in main before it is kept. This is simple and safe but will need revisiting for very large projects (not measured).
- Image dimensions come from a small header reader for PNG, GIF and JPEG; WebP and SVG are imported without dimensions.

Cause: killing only the main process on Windows leaves helper processes holding the single-instance lock. A retry loop (run 2) did not help; killing the whole process tree with `taskkill /T /F` (run 3) did. See skills/project-specific.md #14.

- This was a test-environment problem, but it has a real-world echo not investigated further: if Vedra Opus's main process is killed on Windows while helpers survive, the next launch may refuse to start until they exit.

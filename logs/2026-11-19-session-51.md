  - surveys are marked answered or not;

  - essays keep 4000 characters, one-line entries 1000.
- **Codec:** `r: 'a'` packs as 3. On unpacking it is accepted only when the slide is still a survey.
- **Render and player:** a multiline entry is a `<textarea>` in a course and a box with its placeholder at the top in the editor. The player handles textareas wherever it handled inputs.
- **Editor:**
  - Insert → Survey (a new icon of our own);

  - an answers editor for each kind;
  - Likert scale points and statements can be added and deleted, and the grid is laid out again;
  - `setWords` now keeps the first paragraph's attributes, so a centred label stays centred. This also applies to prompts.

## Found and left alone

- **Branch targets are not validated or cleaned when a slide is deleted.** This affects graded `branch.correct` and `branch.incorrect` (P7.1) and now `branch.answered`. A dangling target is not caught. It predates this package; worth taking up in the Phase 7 review.
- **Likert points have no accessible name of their own.** Each is a mark with no words. A screen reader hears an unnamed choice; worth giving each point its statement's and label's words (P7.5 or the Phase 7 review).
- **Long essays and SCORM 1.2.** An essay of up to 4000 characters can push SCORM 1.2's 4096-character suspend data over the limit. The codec then drops the question answers, as P7.2 designed.

## Mistakes this session

- **A heredoc turned `\n` into a real newline** in a test (rule #4 again). I fixed it with the Edit tool.
- **An expected value worked out in my head** (rule #12): I expected a 20px font where the code rightly gives 44 × 0.45 = 19.8px. The test now shows the arithmetic.
- **A scripted edit's anchor missed after Prettier re-wrapped the line** (rule #1). The script asserts every anchor before writing, so nothing half-applied.
- **I set paragraph alignment as `align`.** The renderer reads `textAlign`, and an unknown key is silently ignored. I caught it by grepping the renderer; it is now pitfall #105.
- **`answerOf` used `pickedFrom` to find chosen marks,** so Likert ratings were never seen. The Likert engine test caught it.
- **Vite started in one `wsl.exe` call does not outlive it.** That cost one false all-red dev-renderer run.

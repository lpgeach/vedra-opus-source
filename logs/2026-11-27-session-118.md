## The Windows slow close (`wp/windows-close-hang`, PR #153)

- **The evidence:** the trace from run 45900875886 (`smoke-report-windows-latest`, `ribbon-tabs.spec.ts:75`). The test body ended at 1.8 s, followed by 28 s in "Close context" until the test timed out. The test had inserted a hotspot and a button, so the project was unsaved, and the test answers the unsaved-changes prompt with Don't Save.
- **The cause:**
  - `confirmLeavingCurrent()` → `discardCurrent()` removed the working copy with a synchronous `rmSync` and did not wait for the autosave write the last edit had started.
  - On Windows, a folder with an open file in it cannot be removed, so `rmSync` throws.
  - The promise in the window's `close` handler (`index.ts`) then rejects, the window never closes, and the app stays open until it is killed.
- **The fix** (brief: `docs/briefs/windows-close-hang.md`):
  - Closing waits for the working copy's write under way.
  - `discardWorkspace()` retries the removal briefly, and never throws. A working copy that still cannot go is marked clean, so the next launch deletes it instead of offering it back.
  - The close handler catches a failure and leaves the window open, as for Cancel.
- **The test:** `session-close.test.ts`.
  - **On the old code, on this machine:** the close during a write logged "Autosave failed" (the folder was removed under the write), and a removal Windows refused rejected the close with `EPERM`.
  - **On the new code:** both pass, five runs in a row.
- **Not proved:** that CI's smoke test no longer stalls. Only a CI run on the public repository shows that, and it waits for Luke.
- **Merging:** the auto-mode permission check refused `gh pr merge`, so PR #153 is open for Luke to merge.

  - TipTap's `mergeAttributes` advisory, fixed only in TipTap 3.30.4 and later.

**What changed:**
- **TipTap 2.27.3 → 3.35.0:**
  - **Named imports:** every TipTap import is now named. In TipTap 3, `@tiptap/extension-font-family`'s **default** export is the TextStyle kit, so a default import would register the wrong extension (pitfall #178).
  - **StarterKit:** version 3 also brings Link, Underline, a trailing paragraph and list keys. They are turned off there. Link and Underline are still added with our own settings, and documents and keys stay as authors had them with TipTap 2.
  - **`setContent`:** it takes `{ emitUpdate: false }` instead of `false` (`whole-text.ts`).
  - **Packages:** `@tiptap/extension-paragraph` is declared (the editor imports it). `@tiptap/html` is removed (imported nowhere).
  - **The render package's parity test** loads 3.35.0 from esm.sh with the same settings. `?bundle` is dropped so the packages share one `@tiptap/core`.
  - **A test changed, not weakened:** `scripts/third-party-notices.test.ts` used TipTap as its example of a package with no licence file. TipTap 3 ships `LICENSE.md`, so the test now builds its own package with none to keep that case covered, and checks that TipTap's own file is used. `docs/licences.md` says the same.
- **Electron:** 45.3.2 → 45.5.0, still pinned exactly (pitfall #3).
- **In range:** typescript-eslint 8.74.0, electron-builder 26.18.1, Vite 8.4.0, Vitest 5.1.2, fast-check 4.11.0, Immer 11.2.13, `@types/node`, `@types/react`, eslint-config-prettier, `@fontsource/inter`.

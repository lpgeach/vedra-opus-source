## What was done

- **Crash reports, opt-in and kept here:**
  - Help → Keep Crash Reports (off by default) turns them on from the next start and says so;
  - the setting is in the app's own `settings.json`, not in any project;
  - when it is on, Electron's crash reporter starts before the app is ready, with uploading off;
  - Help → Show Crash Reports opens the folder they are written to.
  - Sending them anywhere is Luke's decision: it would send data off the machine, and needs somewhere to send it.
- **No telemetry, proved.** The app has never had any. An e2e now records every request the editor's and the preview's sessions make while editing, previewing and publishing, and checks none leaves the machine.
- **README:** a Privacy section saying both.

## Tests

- **Unit** (`settings.test.ts`): the setting round-trips, and is off for an older settings file or a damaged value.
- **e2e** (`privacy.spec.ts`):
  - **Crash reports.** It starts off. Turning it on saves it and says so. A deliberate window crash (`forcefullyCrashRenderer`) in the same run leaves no report. After a restart the menu shows it on, uploading is off, and Show Crash Reports asks for the crash folder (the file manager is stubbed, so nothing opens on the desktop). A deliberate crash then leaves a report.
  - **No requests leave the machine.** A session adds a text box, previews the project and publishes it to a folder. Requests through the app's own schemes were seen, and none was `http`, `https`, `ws` or `ftp`.

## The macOS VM

- **The lite image** (`default`, macOS 26.3, x86_64) cannot run LibreOffice: it lacks AVFoundation, which `libmergedlo.dylib` links ("Library not loaded"). It also lacks `du`. It was suspended again.
- **The `full` image** (GPU; macOS 26.3, build 25D125, x86_64) was used.
  - It was started with `wsm start -n full`, and its window was hidden straight away with `wsm gui stop -n full`. It showed on Luke's desktop for the 26 seconds the cold boot took.
  - Commands ran through `wsm exec -n full`, files went in with `wsm cp`, and Node v26.13.1 was already in `~/node`.

## What was done

- **The study, in the VM:**
  - the x64 dmg downloaded inside the VM, with its checksum as published;
  - mounted hidden, the app copied out with `ditto`;
  - the full build draws the smoke deck headless over SSH (30 s, all three words);
  - `otool -L` showed `libmergedlo.dylib` loads the Calc solver's libraries, Firebird, orcus and the Java glue, as on Windows.
- **Two trial trims:**
  - the first left two links dangling (Firebird's `intl` and `libjava_uno.jnilib`), so `codesign` could not verify the bundle;
  - the second, without them, verified after an ad-hoc re-sign;
  - both drew the smoke deck to SVG and PNG, before and after re-signing.
- **`npm run fetch:libreoffice` on macOS:**
  - unpacks the dmg with `hdiutil` and `ditto`, and trims it;
  - removes links left dangling (on every system);
  - checks Mach-O load commands (macOS only);
  - re-signs the bundle ad hoc and verifies it;
  - smoke-tests;
  - x64 and arm64 builds are pinned.
- **Packaging:** `electron-builder.yml` ships the macOS folder.
- **Found on the way:** the first version of the Mach-O reader also ran on Windows, and tripped on a file starting `CAFEBABE` (Java's class-file mark): "Attempt to access memory outside buffer bounds". It is now macOS-only and bounds-checked.

## Part 3: Phase 1 start (P1.1, P1.4)

### Done
- **P1.1** `packages/model`: Zod schema for format version 1 (project, theme, scenes, slides, layers, text/shape/image/button/group objects, states, variables, triggers, masters, assets), id generation, factories (`createEmptyProject` etc.), migration runner with a v0→v1 migration, `parseProject` / `serializeProject`, and reference validation (unique ids, assets, layouts, trigger targets, states).
- **P1.4** `fixtures/projects/{minimal,two-slides}`, `fixtures/legacy/v0-minimal`, and `fixtures/fixtures.test.ts`, which runs in `npm test`.

### Decisions made while building (within the plan's rules)
- Schema objects are strict: unknown keys are rejected, so nothing is silently dropped on a round trip.
- Ids are unique across the whole project (state ids excepted — they are names local to an object), so references never need a scope.
- Triggers may only reference objects and layers on their own slide.
- The trigger `else` branch is stored as `otherwise` (`else` is a reserved word).
- Group children keep stage-unit frames rather than group-relative ones.
- Player and tracking config are not in v1; they arrive, with migrations, in P5 and P8.

### Verification
- `npm run typecheck` (now also covers `e2e/` and `fixtures/`), `npm run lint`, `npm run format:check`: pass.
- `npm test`: 23 passed. `npm run e2e`: 3 passed.
- Typechecking `e2e/` for the first time exposed use of an undocumented Electron API (`getLastWebPreferences`); that test was removed as redundant with the behavioural sandbox test.

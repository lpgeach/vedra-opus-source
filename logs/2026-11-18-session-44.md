## Found and fixed

- **Motion offsets were lost on resume through an LMS.** This is P6.5 against P5.2. The engine keeps where paths left objects (`SavedSlide.m`), but the suspend codec packs each saved field by name and did not know `m`. So a SCORM, xAPI or cmi5 course resumed with every moved object back in its own place.
  - The codec now carries `m` as `[object, x, y]`. Old suspend data is unaffected; it simply has none.
  - The SCORM 1.2 publish-time estimate of the largest suspend data now counts offsets too.
  - A round-trip test: a path, through encode and decode, into a resumed engine. It fails without the fix.
- **I had edited an existing migration.** In P6.5 I rewrote migration 7 (captions) to use a new helper. `skills/model-package.md` says never to do that. It behaved the same, but migration 7 is now exactly as written in P6.4, checked against the file before P6.5.
- **Dialogs did not take the focus.** The Record Audio, Variables, Publish and Tracking dialogs only closed on Escape when the focus was inside them, and opened from a button it was not. Keyboard and screen-reader users also started outside them.
  - Each now takes the focus as it opens (`components/dialog-focus.ts`); the Speech dialog uses the same helper.
  - Two of these dialogs are older than Phase 6; the fix was the same one line.
- **Masters could get what never plays there.**
  - Insert → Zoom Region in Master View put a region on a master, and pasting an animated object into a master kept its animations. The engine plays neither.
  - Pasting into a master now drops zoom regions and animations, and says so (`forMasters`, unit-tested).
  - Insert → Zoom Region in Master View says zoom regions work on slides.
- **No visual test for the zoom-region marker** (added in P6.7). There is one now, `zoom-region-marker`, with one baseline shared by the browsers, as the others are.

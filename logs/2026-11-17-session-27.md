## Found and fixed

- **Triggers on objects inside groups never ran** (the engine looked only at top-level objects), and grouped objects had no states of their own. Now objects at any depth take input and run their triggers (innermost first, then each group), have their own automatic states, are reached by change state, disabled and scripts, and are drawn in their own states by the player (pitfall #72). Engine tests `groups.test.ts` (5), a player browser test.
- **"When the timeline reaches 0 s" and cue points at 0 s never fired.** Fixed for slides and layers; at the same moment cue points come before "reaches" times (now stated in the code).
- **The engine announced "pointer entered" for something already under the pointer** (after a redraw), which could fire such triggers twice. Now only real changes are announced.
- **Triggers panel buttons wrapped their labels onto two lines** in a narrow panel; now each label stays on one line.

## Mistakes this session, and what changed

- The session was interrupted mid-command. On resuming I wrote a fix for the 0 s case that duplicated one the lost part of the session had already made, so the event fired twice. Found by the tests; kept the more complete fix and the earlier test. New pitfall #74 and rule 9.
- My new pointer handling read the slide id after the click had moved to the next slide and reported the wrong slide; an existing player test caught it.
- A states e2e failed after the pointer change. Cause: its Hover state moved the button out from under the pointer, which flickers in any player; it had passed by timing. Changed the test to make the hovered button wider instead of moving it (pitfall #73). The behaviour it checks is unchanged.
- One Firefox launch failed for a moment under low memory; rerun alone, all its tests passed.

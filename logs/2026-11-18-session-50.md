- `npm run test:visual`: 153 passed (Chromium, Firefox, WebKit).
- `npm run test:player`: Chromium and Firefox pass. The first full run had four media-timing failures; a clean rerun had one:
  `packages/player/browser/video.spec.ts:234 — the timeline keeps the video’s time, and a change of state does not restart it` in WebKit only.

I investigated that WebKit failure without changing product or test code:

- A temporary assertion message showed the video element's `currentTime` and the engine playhead both frozen at the same value after the test set `playbackRate = 0.5`.
- The element was playing, readyState 4, not seeking, not ended, with data buffered.
- A standalone WebKit page using the same test fixture did advance at half speed, both muted and unmuted.
- With `playbackRate = 1` the player test advanced normally, overshooting the test's half-speed upper bound.
- All temporary edits were reverted; `git status` is clean in both the WSL clone and the Windows checkout.

This looks like a WebKit-in-WSL media-pipeline quirk in the player context, not a product bug or a bad assertion, so no check was weakened. It is recorded in `~/VEDRAOPUS-WSL.md`.

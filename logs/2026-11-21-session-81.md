## For Luke: a decision

**The default look fails WCAG 1.4.3.**

- A new button, and every question's Submit, Continue, tiles and drag items, has the theme's text colour (`#1c2024`) on accent 1 (`#2f6fed`). That is 3.6 : 1; 18-pixel text needs 4.5 : 1.
- The checker reports it, correctly.
- Part A's axe-core run did not. axe cannot see a fill drawn in SVG behind the words, and reports such text as "needs review", not as a failure.

**A fix I would suggest:** text on a solid fill that sets no colour of its own takes black or white, whichever contrasts more (as `textOnAccent` already does for the player). White on `#2f6fed` is 4.56 : 1.

I have not made the change. It would change how every existing project's buttons and shapes look, and the visual references with them.

## What was done

- **`accessibilityIssues(project)`** in `packages/model/src/a11y-check.ts`: a pure function, with no saved-format change, over every scene and bank slide.
  - **Alt text:** pictures, graphics and 360° images read by screen readers with no alt text. Also buttons, and anything a click trigger names, with no words and no alt text.
  - **Tab order:**
    - objects Tab reaches with the same name, counted on one layer with the base beneath it;
    - objects that lie outside the slide;
    - an author's order that leaves objects out (said once per slide).
  - **Contrast:** each run of text against its object's solid fill, the solid shape beneath it, or the slide's background.
    - 4.5 : 1, or 3 : 1 for large text.
    - Theme colours and colours with alpha are resolved.
    - Table headers and bands are as render draws them.
    - Gradients and pictures behind text are skipped, not guessed.
  - **Captions:** videos and sounds without captions, text-to-speech sounds included.
- **The right panel's Check tab** (`AccessibilityCheck.tsx`):
  - a count, then the problems under each slide's title, with Show (to the slide, the layer and the object);
  - each Show button is described by its own problem, so a screen reader can tell them apart;
  - it follows the project, undo included.
- **The Format panel's Accessibility section:** "Alt text", and "Decorative: screen readers skip it", for one selected object.

## Found while doing it

- **The editor had no way to set alt text or mark decoration.** The model has had both since Phase 0, and the course has read them since P10.1 part A, but no panel edited them, though P10.1's plan line names alt text. Part A should have caught this. It is added here, because the checker's advice cannot be followed without it.
- **A first version listed every wordless shape,** and so every feedback layer's panel. A wordless shape with no alt text reads as nothing, as decoration does, so it is no longer listed. The brief says why.
- **The two feedback layers' Continue buttons counted as a name clash.** They never show together, so names are now compared on one layer with the base beneath it.

## What was wrong, and the fixes

1. **Keys went nowhere right after editing started** (text-edit ×2, variables ×2, phase4-course). TipTap's `focus` command places the caret at once but gives the editor keyboard focus only on the next frame. The tests waited for the editor's text to show, then pressed Escape or Ctrl+A at once, inside that gap. On Linux headless, frames come at once. **Fix (app):** `focusTextNow(editor)` in `stage/text-editor-state.ts`, called after the command in `TextEditor`'s mount effect and in the ribbon's `apply` and `refocus` (pitfall #98).
2. **Insert variable lost in a dead editor** (variables, preview test, intermittent: 3 runs in 12). After an edit ended, the closing editor re-registered itself as the ribbon's active editor through a last transaction, and was then destroyed. The next Insert variable went into it. **Fix (app):** `setActiveTextEditor` ignores destroyed editors, and an editor destroyed while active clears itself and tells listeners (pitfall #99). After the fix: 20 runs in 20.
3. **Publish settings and Import Media never marked the project changed** (publish SCORM 1.2, a real bug on every OS). `PublishDialog` and `editor.importAssets` used `history.beginGesture`/`commitGesture` directly, which never tells main. So the project said "Saved", closing would not ask, and the publish test passed on Linux only because Save finished before the app closed. **Fix (app):** both go through `editor.beginGesture`/`commitGesture` (pitfall #100).
4. **Electron's security warning in preview** (javascript test). The preview's CSP has `'unsafe-eval'` on purpose (Run JavaScript triggers). Unpackaged Electron prints a warning about it on Windows (not seen on Linux), and the test counted every console warning. **Fix (test):** that one message is ignored, matched by its exact start; every other warning or error still fails the test. The packaged app never prints it.
5. **A test that pressed Escape without waiting** (variables, preview test). The second Insert variable is now followed by a wait for the editor to show it, as the `boxShowing` helper already does.

### Test windows off the desktop on Windows and macOS

`e2e/launch.ts` loads `e2e/transparent-windows.cjs` with `-r`, before the app folder (it is a Node option; Electron refuses `--import`). Every window is transparent, click-through, out of the taskbar and shown without focus. The app's `clipboard.readText`/`writeText` use a clipboard of the app's own. `windowsTransparent` says when this is on. The two-instance paste test skips then, as it does on Linux. The window-size test runs, and passed. `launchApp` also turns on focus emulation for every window, because these windows never get the system's focus. Pitfall #6a is updated.

**A lint setting was added:** `eslint.config.js` has a block for `e2e/**/*.cjs` (CommonJS, Node globals, `no-require-imports` off). A `-r` script must be CommonJS, and there was no `.cjs` file before. No rule changed for existing code.

- **Two fixes to bugs that predate this session, found while designing this package:**
  - **The starting point was not saved after the resume question.** `startCourse` saved straight after `mountPlayer` returned. While the question is showing the engine is null, so nothing was saved until the next slide change.
    - The player now has `onStart(engine)`, called once the course is playing, and `startCourse` saves there.
  - **Completion could go backwards.** This happened when a learner who had completed came back with "Start over", or on a new attempt, or in a course whose resume setting is "never". The fresh engine's first save told the LMS `incomplete`.
    - Both drivers now never write a lower status than the one the LMS holds, or one they have already written.
    - SCORM 1.2: no `incomplete` over `completed`, `passed` or `failed`.
    - SCORM 2004: no `incomplete` over `completed`, and no `unknown` over `passed` or `failed`.

## Not done or not verified

- **The 3rd edition's schema files.** Its `imsss_*.xsd` carry an IMS notice: anyone who distributes them must register with IMS first and receive a licence by email. Every published package would distribute them, so this is **Luke's decision**. Until then, 3rd-edition packages have no schema files and no `xsi:schemaLocation`. The 2nd and 4th editions' copies of the same schemas have no such notice.
- **Response formats differ between 1.2 and 2004** (for example, choice separators). The driver passes them through unchanged; P7 will format them from structured answers.
- **Not checked elsewhere:** SCORM Cloud (Luke, later), real LMSs, WebKit, macOS, Windows, CI.
- **No `adl.nav.request`** on exit. A single SCO has nowhere to go next. Some LMSs may then show their own "content ended" page.

## Mistakes this session, and what changed

- **A wrong expected value:** I expected `scaledScore(-20, -10, 10)` to be −1; it is −0.5. The code was right and the test was wrong. This keeps happening, so I added rule 12: write the arithmetic out before writing an expected number.
- **Unchecked scripted edits:** several Python edits did not assert their anchors (rule 1). I checked afterwards, with a grep per edit, that every one applied. The tests covered the code edits.
- **A false xmllint failure** (session 30, recorded there): validating with one schema reported a failure because the other schemas were not loaded. This session used a wrapper schema from the start.

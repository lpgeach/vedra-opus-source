## What was done

- **Importing:** already streamed. A unit test proves it: half a gigabyte imported, memory up by under 128 MB.
- **The media scheme:**
  - answers byte ranges (`206`, `Content-Range`; `416` for a range past the end), and always gives `Accept-Ranges` and `Content-Length`, so a long video seeks without being read whole;
  - streams from the file instead of fetching it whole;
  - remembers each asset's file name instead of listing the media folder for every request.
- **Huge pictures:**
  - the editor draws a picture larger than twice the stage's longer side from a copy scaled to that size, made once by main (`nativeImage`) and kept in the workspace's `previews/` folder;
  - the copy is never saved in the project file, and the published course uses the original.
- **A failed save** (a full disk, a folder that is gone) is now reported: "The project could not be saved: …". Before, the failure went unreported. The file on disk was already safe: a save is written beside it and renamed over it only when complete.

## Tests

- **Unit:**
  - `range.test.ts`: spans, open ends, last bytes, clamping, unsatisfiable and ignored ranges;
  - `large-media.test.ts`: the half-gigabyte import.
- **e2e** (`large-media.spec.ts`):
  - a 6000 × 4000 picture is drawn on the stage from a 2560-wide copy (`?fit=2560`);
  - a `Range` request returns 16 bytes with `206`, `Content-Range`, `Accept-Ranges` and the PNG signature;
  - Save As into a folder that is not there shows the error, and the project stays the file it was opened from.

## Why

Luke: every system must be feature-ready before the Phase 11 review. macOS is not:

- **ffmpeg:** none for macOS, so imported media are not converted, Export Video does not work, and a deck's sound and video stay placeholders.
- **Not checked on macOS:** the app's e2e (the VM's SSH session has no desktop), text-to-speech (`say`), and the app drawing a deck's charts.
- **Apple Silicon (arm64):** nothing run; the VM is Intel.

## Luke's decisions (2026-11-23)

- **Build our own LGPL ffmpeg for macOS from source** in the VM: VP9 (libvpx), Opus, MP3 (LAME) and the royalty-free decoders; no H.264 or AAC. Ship it like the Windows and Linux build.
- **Log in the VM's hidden desktop session** (`wsm gui prewarm`, hiding any window at once), so the Electron e2e, WebKit and text-to-speech can run on macOS.

## What was done

- **ffmpeg for macOS, our own LGPL build** (`scripts/build-ffmpeg-macos.sh`; `npm run fetch:ffmpeg` runs it on a Mac).
  - **Sources**, each downloaded and checked against its SHA-256 before it is built: ffmpeg 8.1.3, libvpx 1.15.2, Opus 1.5.2, LAME 3.100, and nasm 2.16.03 and pkgconf 2.3.0 as build tools. The checksums were taken in the VM; LAME's and Opus's match their published values.
  - **Built:** LAME, Opus and libvpx static; ffmpeg shared, LGPL. It uses no system codecs, has no AAC encoder, and has no decoders for H.264, H.265, AAC, MPEG-4 Part 2, VC-1 or WMV. Libraries are found by `@rpath` beside the programs.
  - **The script checks its own result:** it encodes VP9 with Opus, and MP3, and probes the result.
  - **In the `full` VM (macOS 26.3 x64):** built in about 9 minutes, 25 MB.
    - The programs load only their own libraries and macOS's system frameworks.
    - `-decoders` and `-encoders` list no H.264, H.265 or AAC.
    - VP9, Opus, MP3 and PNG are there.
    - It reports the LGPL, built without the GPL or non-free options.
  - **Apple Silicon:** the same script builds natively there. It was not run (the VM is Intel).
- **Patented formats are refused on macOS, as on Linux** (`refusePatented: process.platform !== 'win32'`). The message names the system.
- The H.264 unit test is skipped on macOS: our build there has no encoder to make its sample with.

  - After that, `e2e/shell.spec.ts` passed on macOS (3 of 3), started from SSH.
  - The LibreOffice unit test's 120 s timeout had the same cause: once the session was finished, it drew the charts in 8.5 s.

## The VM's setup fix (`mac-finish-setup.sh`, run as `dev` over SSH)

```bash
D=com.apple.SetupAssistant
for k in DidSeeCloudSetup DidSeeSiriSetup DidSeePrivacy DidSeeScreenTime DidSeeAppearanceSetup \
  DidSeeTouchIDSetup DidSeeAccessibility DidSeeActivationLock DidSeeIntelligence DidSeeTermsOfAddress \
  DidSeeApplePaySetup DidSeeSyncSetup DidSeeSyncSetup2 DidSeeiCloudLoginForStorageServices \
  DidSeeLockdownMode DidSeeWallpaper; do defaults write $D $k -bool YES; done
defaults write $D LastSeenCloudProductVersion "$(sw_vers -productVersion)"
defaults write $D LastSeenBuddyBuildVersion "$(sw_vers -buildVersion)"
defaults write $D LastPreLoginTasksPerformedVersion "$(sw_vers -productVersion)"
defaults write $D LastPreLoginTasksPerformedBuild "$(sw_vers -buildVersion)"
defaults write $D SkipFirstLoginOptimization -bool YES
killall "Setup Assistant"; sleep 3; killall talagentd
```

`defaults write -g ApplePersistenceIgnoreState -bool YES` was also set while trying things; it is harmless and was left.

## A bug the Linux run found: an unhandled EPIPE from the speech runner

- **Seen:** the WSL unit run had every test passing but one "Uncaught Exception: write EPIPE" during the real espeak-ng test, so `npm test` failed.
- **Cause:** `run()` in `main/speech/providers.ts` writes the text to the program's standard input. When the program exits before reading it, the write fails, and nothing listened for that error. In the app's main process an uncaught error like that ends the app.
- **Fix:** the stdin error is handled. The exit code already says whether the program succeeded.
- **Test:** `speech.test.ts` runs a program that exits without reading 4 MB of input, once with exit code 0 and once with 3. Without the fix it gave two unhandled EPIPE errors in WSL; with it, it passes.

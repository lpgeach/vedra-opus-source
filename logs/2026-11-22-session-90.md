## What was done

- **The trim study,** Windows then Linux, on LibreOffice 26.8.3 with The Document Foundation's published checksums.
  - Windows: an administrative MSI extract, trial trims, and a reader of each DLL's import table. It found six libraries `mergedlo.dll` links at load time that must stay although they look removable.
  - Linux: the deb tarball's packages unpacked, and the same kinds of file dropped under Linux names, plus the GTK, Qt and KDE plug-ins. `readelf` showed what links what. The trimmed build's PNG of the smoke deck is byte for byte the full build's.
- **`npm run fetch:libreoffice`** (`scripts/fetch-libreoffice.mjs`):
  - downloads the pinned build (or takes `--archive=` a download on disk) and checks its SHA-256;
  - unpacks it without installing anything (Windows `msiexec /a`; on Linux the script reads each `.deb` itself, so `dpkg` is not needed);
  - copies all but the platform's drop list, and on Windows puts the Visual C++ runtime beside the programs;
  - checks no kept program or library loads a dropped one (PE imports and delay imports; ELF `DT_NEEDED`), which caught `pyuno.pyd` on its first run;
  - draws `fixtures/libreoffice/smoke.pptx` to SVG (it must hold "Smoke test", "March" and "Stop") and to PNG;
  - only then moves it into `vendor/libreoffice/<os>-<arch>`, with `SOURCE.txt`.
  - **Sizes:** Windows 402 MB of 1,605 MB; Linux 365 MB of 731 MB.
  - No macOS build yet: the script says so and exits cleanly.
- **The importer** (`drawing.ts`, `libreoffice.ts`, `png.ts`, `import-file.ts`):
  - the converter leaves a stand-in and a pending drawing for each chart, SmartArt, embedded object, and picture in a format courses do not show (EMF, WMF, …), on slides;
  - each gets a deck of its own: one slide the size of the content, the content alone at the top left, no background, the layout's and master's shapes emptied, and only the parts it reaches;
  - LibreOffice draws them as transparent PNGs, with a throwaway profile, at a set width: one run for each group of drawings of about the same width, so each comes out 2 to 2.8 times its frame's width (left to itself, LibreOffice follows the screen's density: 2× on this Windows machine, 1× on headless Linux, which the first Linux run caught);
  - each picture takes its stand-in's place, id, name, timing, animations and description, and the report says "drawn as a picture";
  - a picture that comes back fully transparent (content LibreOffice cannot read) is not used; the placeholder stays, reported. So it does without LibreOffice, or when it cannot start.
- **Wiring:** main looks in `VEDRAOPUS_LIBREOFFICE_DIR`, then `resources/libreoffice` when packaged, then the vendor folder. electron-builder ships the folder on Linux and Windows. `npm run package` fetches it.
- **Fixed on the way:** part C's sound and video lost their stand-in's animations; they keep them now.
- **Docs:** the brief, `docs/licences.md` (MPL 2.0, sizes, what is kept, the Visual C++ runtime), `docs/development.md`, `README.md`, the handover, and pitfalls #141 and #142.

## Tests

- **Unit:**
  - `drawing.test.ts`: what waits to be drawn, and the report left to the importer. Each drawing's deck: one slide, its size, the content alone at the top left with a DrawingML offset; nothing of the layout or master; only the parts the content reaches; SmartArt's drawing kept; a picture unturned. Our own reader reads the deck back. The smoke fixture is the builder's `smokeDeck()`.
  - `png.test.ts`: blank and not blank, through every PNG row filter; other kinds of PNG.
  - `libreoffice.test.ts`: finding LibreOffice in Windows, Linux and macOS layouts; the vendor folder; a program that will not start; the width groups and the size cap; the export asking for a set width.
  - `import-file.test.ts`: without LibreOffice, and with one that cannot start, the placeholders stay, reported. **With the real LibreOffice** (skipped where none is fetched): a chart and SmartArt become pictures in place, 1024 and 1448 wide for frames 500 and 600 wide, in their frames' shape, and a chart with no part stays a placeholder with its description.
  - `convert.test.ts`: updated, since the converter now leaves charts and EMF pictures to be drawn.
- **e2e** (`pptx-import.spec.ts`): the first deck's chart has no part, so it stays a placeholder whether or not LibreOffice is there. New: a deck's chart and SmartArt come across as pictures through Import PowerPoint…, and the pictures load (skipped without LibreOffice).

## Done

- **Brief:** `docs/briefs/P5.4-xapi.md`.
- **Player, `lms/xapi.ts`:**
  - Launch parsing: `endpoint`, `auth`, `actor` (the older array form too), `registration` (dropped with a warning if it is not a UUID), `activity_id`.
  - Statements: version 4 UUIDs made with `getRandomValues`, timestamps taken when the event happened, a parent context for slides and interactions. Status statements are sent only when the status changes.
  - A queue with retry: 1, 2, 4… seconds, at most 30. It drops a batch on a non-retryable `4xx`, with a warning.
  - State API resume through one document, with validated reading. If state cannot be read, it is not written that session.
  - `keepalive` sends on leaving.
- **Player, other files:**
  - `LmsDriver` gained optional `ready()` and `slideEntered()`.
  - `startCourse` takes `lms: 'xapi'` and `activityId`, shows "Loading…" until `ready()` resolves, and reports each slide entered.
  - Status reports now go out in a microtask, after the slide change that caused them. This changes the timing for SCORM too, but SCORM's values are the same.
- **Publish:**
  - `publishXapi` writes `tincan.xml`. The default activity id is `urn:vedraopus:course:<project id>`; an id that is not an IRI is refused.
  - The activity id reaches the page's script as an escaped JSON string.
  - The xAPI vocabulary moved into the player (`@vedraopus/player/xapi-vocabulary`), because the course now uses it. Publish re-exports it.
- **Tests:**
  - Player unit tests: 14 xAPI.
  - Publish unit tests: 4 xAPI.
  - LMS browser tests: a 6-test xAPI spec against a new mock LRS (`browser/mock-lrs.ts`). The mock runs on its own port, so the CORS preflight is exercised. It checks auth and version headers, validates every statement, keeps statements once per id and keeps state documents, and can fail on request.

## Mistakes this session, and what changed

- **Order of statements:** I assumed the engine reports a slide change before the completion it causes. It reports them the other way round, so the LRS got "completed" before "experienced slide 2". The browser test caught it. Fixed by reporting status in a microtask, and recorded in pitfall #82.
- **Fake timers in my unit test:** they ran the state-load timeout as if it were a retry. Fixed by making the fake's `clearTimeout` work and looking only at pending timers.
- **The driver read `window.location` and `window.crypto` eagerly**, even when tests supplied their own values. Fixed by applying each default only when no override is given.
- **Rule 1 (assert anchors) worked:** one scripted edit stopped on a missing anchor before writing anything, because Prettier had re-wrapped the line.

# P7.5 Feedback

**Work package:** P7.5, needs P7.4 (done, merged in PR #57).

**Plan line:** correct / incorrect / try again layers generated from feedback masters; Submit behaviour and `submit interaction` action; review mode showing the learner's and the correct answers.

**Luke's decisions (2026-11-19):**

1. **An editable feedback master.** Its layouts (Correct, Incorrect, Try Again and Thank You) are edited in Master View. Each question slide gets copies of them as its own overlay layers, which the author can change per question.
2. **The words live in the layers' text objects,** as P7.1 put the question's words in its objects. Form View's feedback boxes edit the message text on the slide's feedback layer. The old feedback strings move into the layers in the format migration, and the question drops them.
3. **Review mode is built in the engine and player now,** turned on by a `reviewQuiz` trigger action. P7.7's result slides will put that action on their Review Quiz button.
4. **Feedback by choice shows the picked choice's own words** in the message of the Correct or Incorrect layer. For multiple response, each picked choice's feedback goes on a line of its own. The choices keep their feedback strings.

**This changes none of the rules in plan §5.** A feedback layer is an ordinary overlay layer, shown and hidden by the existing layer rules. Only Submit's choice of what to do next is new.

**Delivery.** One branch, in three steps, each committed when it passes:

- **A.** The feedback master, generating feedback layers, and format 17 with its migration.
- **B.** Submit behaviour: showing the layer, `continueQuestion`, feedback by choice, and Form View's feedback.
- **C.** Review mode.

## Saved format version 17

**Masters gain a kind.** `SlideMaster.kind` is `'slide'` (every master so far) or `'feedback'`. There is exactly one feedback master.

- Its layouts each have a `role`: `correct`, `incorrect`, `tryAgain` or `answered` (the Thank You layout, for surveys). There is one layout per role.
- Slide layouts have `role: null`.
- A slide's `layoutId` cannot name a feedback layout. New Slide, the layout pickers and Overview list slide masters only.

**The feedback master's design.** Each layout's layer, together with the master's own layer beneath it, is what a generated feedback layer starts as:

- The **message** is the layout's text object with `placeholder: 'content'`.
- The **button** is the layout's first button. A layout may have no button.

The default feedback master (new projects, and the migration) is a panel across the bottom third of the stage, with a heading, the message and a button:

| Layout    | Heading     | Button    | Panel colour |
| --------- | ----------- | --------- | ------------ |
| Correct   | "Correct"   | Continue  | `accent3`    |
| Incorrect | "Incorrect" | Continue  | `accent2`    |
| Try Again | "Not quite" | Try Again | `accent4`    |
| Thank You | "Thank you" | Continue  | `accent1`    |

**A question's feedback.** The feedback texts are replaced by references to the slide's feedback layers:

```ts
FeedbackPart = { layer: id, message: id | null, button: id | null }
graded: feedback: { by, correct: FeedbackPart | null, incorrect: …, tryAgain: … }
survey: feedback: { by, answered: FeedbackPart | null }
```

- `by` is unchanged: `question`, `choice` (choice kinds) or `none`.
- `layer` is one of the slide's overlay layers.
- `message` is a text object on that layer, and `button` a button on that layer.
- Deleting the message or button sets it to null. Deleting the layer sets the part to null; `layer.remove` now updates the question, as `object.remove` does.

**Generating a feedback layer** (`createFeedbackLayer(master, role, words, stage)` in the model):

- a new overlay layer named after the role;
- the master's and the layout's objects, copied with new ids;
- the message's words set to `words`;
- properties: hide other layers, block clicks on the base, pause the base timeline;
- a trigger on the button: click → `continueQuestion`.

A new question slide, converting a slide, and the migration all generate the layers their kind needs:

- correct, incorrect, and try again when attempts are above 1 or unlimited;
- answered for a survey.

**Migration 16 → 17:**

- marks masters `kind: 'slide'` and layouts `role: null`;
- adds the default feedback master;
- for every question with feedback `question` or `choice`, generates its layers from the default master, carrying the old texts over as their words. A question with `none` keeps no layers.

Legacy fixture `v16-two-slides`.

The migration writes the default master out as plain data of its own, so later changes to the factory do not change what old projects become.

## Runtime

**Submit:**

1. The answer is marked as before.
2. If feedback is not `none` and the result's layer exists, that layer is shown, with its properties. The result is correct, incorrect, try again, or answered for a survey.
   - Nothing else happens yet: the branch waits for the learner.
   - With feedback by choice, the message shows the picked choice's feedback, or each picked choice's on its own line. A choice with no feedback falls back to the layer's own words.
3. With no layer to show, the branch is taken at once, as before.

**`continueQuestion`** is a new trigger action, put on each generated button:

- On a finished question, it hides the feedback layer and takes the branch for the result (correct or incorrect; a survey's `answered`).
- On a try again, it hides the layer, and the learner answers again. Their answer so far stays.
- Elsewhere, it does nothing.

**Required questions:** Next stays held until the question is finished, as before. While a finished question's layer is up, Next is allowed. It goes to the next slide and does not take the branch, as Next always has.

**The view's text override:** by-choice words reach the player as `ObjectView.text` (plain text, in place of the object's own words), drawn as a plain paragraph in the object's text style.

**Session state:** the open feedback layer is ordinary layer visibility, which revisit and resume already keep.

**Review mode (step C):**

- **`reviewQuiz`** is a new trigger action. It turns review on and goes to the project's first question slide.
- **While reviewing:**
  - every question is locked;
  - its Submit does nothing;
  - feedback layers are not shown on entry or on Submit.
- **What review shows:**
  - each answer object gets `ObjectView.review`: `'right'` for an object that is part of the right answer, `'chosen'` for one the learner chose that is not;
  - text entries show the learner's words, and a dropdown shows its choice;
  - the slide's view gains `review: 'correct' | 'incorrect' | 'answered' | 'unanswered'`;
  - the player shows a banner with that result, and draws the objects' review marks: a green outline for right, a red one for a wrong choice.
- **Not saved:** review is not kept in the session or the suspend data. Ending review is P7.7's, with the result slides.

## Editor

**Master View:**

- lists the feedback master after the slide masters, with its four layouts;
- they are edited as any layout is;
- the feedback master and its layouts cannot be deleted, and no layout can be added to it.

**Form View, Feedback row:**

- **by question:** a box for each layer the question has: Correct, Incorrect and Try Again feedback (Thank You for a survey). Each box edits that layer's message object.
- **a missing layer** (deleted, or feedback switched from None): a "Make the … layer" button generates it from the feedback master.
- **Try Again** appears only when attempts allow another try.
- **by choice:** the choice boxes edit the choices' feedback strings, as before.
- **switching to None** keeps the layers on the slide; they are simply not shown.

**Insert:** new question slides, and converted slides, come with their layers.

## Done when (step A)

- **Model:**
  - masters' kind and roles validate: one feedback master with one layout per role, and slides cannot use feedback layouts;
  - `FeedbackPart` references validate (layer on the slide, message a text on it, button a button on it);
  - generating a layer copies the master's and layout's objects with new ids, sets the words, and adds the trigger;
  - `layer.remove` and `object.remove` update the question;
  - migration 16 → 17 carries the words into the generated layers, with the `v16-two-slides` fixture and a fixture question;
  - the property test inserts each kind with its layers, and removes layers.
- **Editor:**
  - Master View shows the feedback master;
  - the layout pickers do not offer it.

## Done when (step B)

- **Engine:**
  - Submit shows the correct, incorrect or try-again layer and waits;
  - `continueQuestion` branches, or hides the layer for a retry;
  - with no layer, or `none`, Submit branches at once;
  - surveys show Thank You;
  - by choice, the message shows the choice's words, multiple response each on a line;
  - a layer left open is kept on revisit and resume.
- **Player browser (Chromium and Firefox):**
  - a wrong answer shows Try Again, its button closes it, and a right answer shows Correct, whose Continue moves on;
  - by-choice words are shown.
- **Editor and e2e:**
  - Form View edits a layer's words, and they are on the slide;
  - a deleted layer is made again;
  - a feedback master change shows on a newly inserted question;
  - save and reopen, publish, and see the feedback in the course.

## Done when (step C)

- **Engine:**
  - `reviewQuiz` turns review on and goes to the first question;
  - questions are locked, and Submit and the feedback layers stay quiet;
  - the review marks for choice, entry, drag and hotspot kinds;
  - the slide's review result, including unanswered.
- **Player browser:** after answering, a `reviewQuiz` button shows the banner and marks on each question.
- **e2e:** a course with a Review button (a trigger with `reviewQuiz`) is published and reviewed.

# P3.2 Player view

**Work package:** P3.2, needs P3.1 and P2.3 (done). **Status:** implemented on branch `wp/p3.2-player`.

`packages/player` mounts the engine, draws the current slide with `@vedraopus/render`, scales the stage to fit, runs the frame loop and forwards input. It ships inside published courses and preview.

## Surface

```ts
const player = mountPlayer(container, project, {
  assetUrl?,       // (hash, ext) => url; default `assets/<hash>.<ext>` beside the page
  restore?,        // SessionState
  clock?,          // () => ms; default performance.now
  autoStart?,      // run the rAF loop (default true); false = drive time with player.tick(ms)
  onInput?,        // click, doubleClick, rightClick, mouseEnter, mouseLeave (+ objectId), keyPress (+ key)
  onSlideChange?,  // called with the SessionState on each slide entry (for LMS drivers later)
});
player.engine; player.element; player.tick(nowMs?); player.destroy();
```

## Decisions

- **Build.** `npm run build:player` (Vite library mode) writes `packages/player/dist/player.js` (IIFE defining `window.VedraOpusPlayer`) and `player.css`: one script, one stylesheet, nothing fetched at run time. `process.env.NODE_ENV` is replaced at build time. The script is about 142 kB (44 kB gzipped) because the model package's schema code comes with `allSlides`; splitting the model's runtime helpers from its schema would shrink it (not done).
- **Drawing.** On each slide entry the whole slide is built once (master and layout layers beneath, then every layer's objects, via `toDom`). Each frame only toggles `display` from the engine view (`object.visible`, layer shown), and only when that changed. Object states beyond `hidden` are not drawn yet (P4.1).
- **Scaling.** The stage is scaled to fit the viewport (up or down), centred, tracked with a `ResizeObserver`.
- **Input.** Pointer events on objects and key presses go to `onInput`: that is the seam P4.3 triggers will use. Built-in keys: ArrowRight / PageDown next, ArrowLeft / PageUp previous. The engine has no input API yet.
- **Frame.** Project title, Previous and Next buttons, "Slide x of y". Menu, seekbar and the rest arrive with P8.1.
- **Fonts.** Text uses the project's theme font names with system fallbacks; bundling fonts into a published course belongs to P3.5.
- **Browser tests.** `npm run test:player` builds the bundle, then plays the `two-slides` fixture from a plain HTML page on disk (`file://`) in Chromium, Firefox and WebKit: timing, navigation, scaling, input, the real frame loop, and no failed requests or page errors.

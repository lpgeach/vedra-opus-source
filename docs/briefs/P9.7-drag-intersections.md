# P9.7 Intersection events, and drag and drop outside questions

**Work package:** P9.7. It needs P9.6 (PR #75).

**Plan line:** intersection events (`objects intersect` / `stop intersecting`) and drag-and-drop outside quiz slides.

**Plan §4.2's events this adds:**

- object dragged over;
- object dropped on;
- objects intersect;
- objects stop intersecting.

**Plan §5 already says** the drag states (`dragOver`, `dropCorrect`, `dropIncorrect`) come from the drag-and-drop interaction. P7.4 built them for freeform questions. §5 is not changed here.

**My design choices** (Luke asked to go through all of Phase 9), listed for him to change:

1. **Any object at the top of a layer can be made draggable**, on any slide, by a setting: `drag: { returnToStart } | null`.
   - With `returnToStart` off, it stays where it is dropped.
   - With it on, it goes back to where it was picked up from, and its "dropped on" triggers still run.

   Objects inside a group move with their group, so they cannot be dragged alone. A question's own tiles keep the question's rules (P7.2 and P7.4).

2. **"Over" and "on"** mean that the dragged object's middle is inside the other object's box. This is the same test as freeform drops.
   - While it is carried, the object under its middle is shown in its **Drag Over** state, if it has one.
   - "Dragged over" fires each time the object under it changes to a new one.
   - "Dropped on" fires when it is let go there.
   - The other object is the topmost one at the top of a shown layer; a group counts as a whole, so the wizard offers top-level objects only.
   - **Changed after the Phase 9 review (Luke, session 76):** only the objects that the dragged object's "dragged over" and "dropped on" triggers name count as targets. An object drawn above a target therefore cannot catch the drop, and with no such trigger nothing shows Drag Over.
3. **Intersect** means their boxes overlap, each where it is drawn now: moved by a drag, a motion path or a previous drop. Both must be on stage and shown.
   - The events fire when that changes: when they begin to overlap, and when they stop.
   - Whether two objects already overlap when the slide starts is noted without firing, so "intersect" means "came to overlap".
   - The check runs after each tick of the clock, each move of a carried object and each drop. Only the pairs that triggers name are checked.
4. **Where an object was dropped is kept**, as a motion path's end is (the slide's `m` memory). It is saved and resumed as that is.
5. **Keyboard dragging is not in this package.** Pointer and touch only, as for question tiles. A keyboard way to move objects belongs to the accessibility phase (P10).

## Saved format version 31

- `objectBase += drag: { returnToStart: boolean } | null`, on every object type.
- **Trigger events:**
  - `{ type: 'draggedOver', object, target }`;
  - `{ type: 'droppedOn', object, target }`;
  - `{ type: 'intersects', object, other }`;
  - `{ type: 'stopsIntersecting', object, other }`.
- **Validation:**
  - only a top-level object may be draggable;
  - the events' objects are the slide's.
- **Migration 30 → 31:** `drag: null` on every object, in groups, question banks and masters too.
- **Legacy fixture:** `v30-two-slides`.

## Runtime (engine)

- `carry(id, x, y)` and `drop(id, x, y)` (P7.4's calls) also take a draggable object that is not a question's tile.
- **Its drop:** its offset becomes where it was let go, or stays as it was with `returnToStart`.
- **Its view** says `draggable`, so the player's existing pointer dragging carries it.
- **Intersections:** a set of overlapping pairs kept per slide, and compared after every change.

## Editor

- **The Format panel's "Learners can drag it"** (top-level objects), with "Goes back after it is dropped".
- **The trigger wizard:**
  - "is dragged over" and "is dropped on" (an object and a target);
  - "intersects" and "stops intersecting" (two objects).

## Done when

- **Model:**
  - validation;
  - migration and fixture;
  - the property test sets drag and adds the events.
- **Engine:**
  - dragging and dropping a free object moves it and keeps it there (and resumes it);
  - `returnToStart` puts it back;
  - over and on fire for the right target only, with Drag Over shown;
  - intersect and stop fire on change only, not at the start, including when a motion path moves an object;
  - a question's tiles are unchanged.
- **Player browser (Chromium and Firefox):**
  - drag an object onto another: it stays, and the "dropped on" trigger runs;
  - one that goes back;
  - an intersect trigger while dragging.
- **e2e:**
  - make an object draggable, with a "dropped on" trigger and an "intersects" trigger;
  - save and reopen;
  - publish, and drag it.

# P8.2 Player tabs

**Work package:** P8.2. It needs P8.1 (the player frame, PR #62).

**Plan line:** resources (files and links), glossary, slide notes, custom tabs that open a lightbox slide or fire triggers.

**What it is.** The player frame gets tabs in its bar, each opening a panel over the course:

- **Resources:** links and files.
- **Glossary:** terms and definitions.
- **Notes:** the current slide's notes.
- **Custom tabs:** the author's own, which fire triggers.

**My design choices** (Luke asked to go through all of Phase 8), listed for him to change:

1. **The tabs are part of `project.player`**, edited in the Player dialog (P8.1).
   - Resources, Glossary and Notes are each on by default.
   - **A tab with nothing in it is not shown:**
     - Resources with no items;
     - Glossary with no terms;
     - Notes when no slide has notes.
   - Custom tabs are listed after the three, in the author's order.
2. **A custom tab fires triggers** through a new event: "the learner clicks the player tab X".
   - Its triggers are on slides, like key-press triggers, so a tab can do different things on different slides and act on that slide's objects.
   - Deleting a custom tab deletes the triggers that listen for it, as deleting an object does.
   - "Opens a lightbox slide" needs lightboxes, which are P8.4. P8.4 adds it as a second kind of custom tab. P8.2 builds only the trigger kind, so nothing is half-built.
3. **Links** must start with `http://`, `https://` or `mailto:`. Anything else could run script in the course (`javascript:`). Links open in a new tab or window.
4. **Files** are copied into the project, like media. They are published with the course and opened from it.
   - The types allowed: PDF; Word, Excel and PowerPoint; OpenDocument; RTF; plain text; CSV; ZIP; and pictures other than SVG.
   - HTML, SVG and scripts are refused, for the same reason as `javascript:` links.
5. **The glossary** is shown sorted by term, whatever order it was written in.
6. **Slide notes** become editable. The editor's Notes tab, a placeholder until now, gets a plain text box:
   - each line is a paragraph;
   - the text is saved as the slide's rich-text `notes`, as plan §4.1 has it.

   Formatting notes (bold, lists) is left for later.

7. **Labels** ("Resources", "Glossary", "Notes") are fixed here. Editable label words are P8.3.

## Saved format version 21

```ts
player.tabs: {
  resources: { show: boolean, items: { id, title: string, target: { kind: 'link', url } | { kind: 'file', asset: AssetHash } }[] },
  glossary: { show: boolean, terms: { id, term: string, definition: string }[] },
  notes: { show: boolean },
  custom: { id, label: string }[],
}
```

- **Trigger event:** `{ type: 'playerTab', tab: id }`, naming one of `custom`.
- **Validation:**
  - every id is unique across the project, as always;
  - a link's URL has an allowed scheme;
  - a file names an asset of the project;
  - a `playerTab` trigger names a custom tab.
- **Migration 20 → 21:** the defaults (all three shown, none filled, no custom tabs).
- **Legacy fixture:** `v20-two-slides`.
- **New commands:**
  - `slide.setNotes`;
  - `project.setPlayer`, which also deletes the triggers of a custom tab it removes.

## Runtime

- **Engine:** `engine.playerTab(tabId)` raises the `playerTab` event for the current slide's triggers.
- **Player:**
  - The tabs are buttons in the bar, after the title, each with `aria-expanded`.
  - One panel is open at a time: a region named after its tab. A tab's second click closes it, and so does Escape.
  - Notes follow the slide while their panel is open.
  - A custom tab is a button that fires its triggers and opens no panel.

## Editor

- **The Player dialog** gets a Tabs section:
  - **Resources:**
    - Show;
    - each item with its title, a Remove button, and its link or file name;
    - Add link (title and URL);
    - Add file… (the file dialog; documents and pictures).
  - **Glossary:** Show; each term with a term and a definition field; Remove; Add term.
  - **Notes:** Show.
  - **Custom tabs:** each tab's label; Remove; Add tab.
- **The Notes tab** of the bottom panel: the slide's notes, saved when the box loses focus.
- **The trigger wizard:** a new event, "the learner clicks the player tab", with the custom tabs to choose from. It is offered only when the course has custom tabs.
- **IPC:** a new call, `project:importFiles`. It shows the file dialog for resource files and copies them into the project as assets of kind `file` (pictures as `image`).

## Done when

- **Model:**
  - tabs validate (URL schemes, file assets, unique ids, tab triggers);
  - migration 20 → 21 and the fixture;
  - removing a custom tab deletes its triggers;
  - `slide.setNotes` and tab changes are in the property test.
- **Engine:** a `playerTab` trigger runs on its slide, and not for another tab.
- **Player (unit):** which tabs show, the sorted glossary, and notes as paragraphs.
- **Player browser (Chromium and Firefox):**
  - each panel opens and closes (click, and Escape);
  - links and file links are there, with their targets;
  - the glossary is sorted;
  - notes follow the slide;
  - a custom tab fires its trigger;
  - empty tabs are absent.
- **e2e:**
  - in the editor, add a link, a file, a glossary term and a custom tab;
  - write a slide's notes;
  - add a trigger on the custom tab;
  - save and reopen;
  - publish, and see each tab work in the course, the file included.

## Not in this package

- Lightbox tabs (P8.4).
- Label words and the tabs' look (P8.3).
- Rich formatting of notes.

# P3.4 Preview

**Work package:** P3.4, needs P3.2 and P1.3 (done); uses P3.5's export path. **Status:** implemented on branch `wp/p3.4-preview`.

## Decisions

- **Same output as Publish.** Main runs `publishWeb` on the current document (unsaved edits included) and keeps the files in memory. They are served from `vedraopus-preview://<random token>/…`. There is no second player or data path.
- **Scope.** `scopeProject` (`@vedraopus/publish`) cuts the project to one slide or one scene and drops triggers that point at slides left out. Home tab → Preview group: This Slide, This Scene, Entire Project. File → Preview Project (F12).
- **Sandbox.** The preview window has no preload (no bridge), `sandbox` and `contextIsolation` on, its own session partition, a content security policy with no network access, window-open denied, and every navigation refused. The scheme handler is registered on that partition's session (a handler belongs to one session).
- **Controls.** A bar above the course has Replay, Edit and Close. With no bridge, the buttons navigate to `/__action/<name>?slide=<current slide>`, which main intercepts: Replay reloads, Close closes, Edit closes and tells the editor to show that slide (`event:previewEdit`). One preview window at a time; opening again reuses it. It closes with the editor window.
- All custom schemes are declared in one `registerSchemesAsPrivileged` call (Electron allows one).

## Tests

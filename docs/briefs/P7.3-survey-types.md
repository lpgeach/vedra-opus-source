# P7.3 Survey question types

**Work package:** P7.3, needs P7.2 (done, merged in PR #53).

**Plan line:** Likert, pick one, pick many, which word, short answer, essay, ranking, how many.

**What a survey question is.** It asks for an opinion or a fact about the learner, so nothing is right or wrong:

- there is no correct answer, no score and one try;
- Submit finishes it as soon as it is answered;
- it has one piece of feedback (a thank-you) and one branch, both taken once it is answered.

Otherwise it follows P7.1 and P7.2:

- its parts are ordinary objects on the slide's base layer;
- Form View edits their words and the question's settings;
- the learner answers in the course.

Each survey kind reuses a graded kind's parts and runtime where there is one:

| Survey kind   | Built like                    | New                                         |
| ------------- | ----------------------------- | ------------------------------------------- |
| `pickOne`     | multiple choice               | —                                           |
| `pickMany`    | multiple response             | —                                           |
| `shortAnswer` | fill in the blank             | —                                           |
| `essay`       | fill in the blank             | a text entry of several lines (`multiline`) |
| `howMany`     | numeric                       | —                                           |
| `whichWord`   | word bank                     | —                                           |
| `ranking`     | sequence (drag and drop)      | shown in the author's order, not shuffled   |
| `likert`      | rows of multiple-choice marks | a grid: statements against a scale          |

**Delivery.** One branch, in three steps, each committed when it passes:

- **A.** Pick one, pick many, short answer, essay, how many. This step adds format 15.
- **B.** Which word and ranking (drag).
- **C.** Likert.

## Saved format version 15

**Survey kinds share** (instead of the graded kinds' `attempts`, `scoring` and right/wrong feedback):

- `prompt`, `submit` and `required`, as before;
- `feedback: { by: 'question' | 'none', answered: string }`, the thank-you;
- `branch: { answered: JumpTarget | null }`, where to go once answered (null is the next slide).

`surveyKinds` and `isSurveyQuestion` sit next to `choiceKinds` and `isChoiceQuestion`. Code that reads `attempts`, `scoring` or the right/wrong feedback narrows to graded questions first, and the compiler finds the places that must.

**Each kind's parts.** "Object" means an ordinary object on the slide's base layer.

| Kind          | Its parts                                                                                                               | Answered when                                  |
| ------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `pickOne`     | `choices: { id, object }[]` (choice objects, one `buttonSet`), `shuffle`                                                | one choice is chosen                           |
| `pickMany`    | `choices: { id, object }[]` (choice objects, no set), `shuffle`                                                         | at least one choice is chosen                  |
| `shortAnswer` | `entry` (a text entry)                                                                                                  | something other than spaces is typed           |
| `essay`       | `entry` (a text entry with `multiline: true`)                                                                           | something other than spaces is typed           |
| `howMany`     | `entry` (a numeric text entry)                                                                                          | what is typed reads as a number (`readNumber`) |
| `whichWord`   | `words: { id, object }[]` (tiles), `blank` (a drop target)                                                              | a word is in the blank                         |
| `ranking`     | `items: { id, object }[]` (tiles, in the author's order)                                                                | always: the order as it stands is the answer   |
| `likert`      | `labels: string[]` objects (text, the scale's heading), `statements: { id, text, points }[]` (`points`: choice objects) | every statement has a point chosen             |

- **Survey choices** are `{ id, object }` only: no `correct`, `points` or per-choice feedback.
- **Likert:**
  - `labels` are 2 to 10 text objects, the scale's points from left to right;
  - each statement has a text object and one choice object (a mark with no words) per label;
  - each statement's points share a `buttonSet`, so one per row is chosen;
  - validation checks every statement has as many points as there are labels;
  - the new slide has five points, "Strongly disagree" to "Strongly agree", and three statements.
- **Ranking items** are not shuffled: the author's order is where the learner starts. Dropping a tile on another's place swaps them, as in sequence (drag).

**Object change:** `textEntry.props` gains `multiline: boolean`.

- A multiline entry is drawn as a box with its placeholder at the top in the editor, and as a `<textarea>` in a course.
- Enter makes a new line there; it is not a key press for triggers, as with every entry.

**Migration 14 → 15:** every text entry gets `multiline: false`; questions are unchanged. Legacy fixture `v14-two-slides`.

**Length of what is typed:**

| Entry     | Most characters kept | Why                                                             |
| --------- | -------------------- | --------------------------------------------------------------- |
| one line  | 1000                 | as in P7.2                                                      |
| multiline | 4000                 | what SCORM 2004 keeps for a long-fill-in interaction's response |

SCORM 1.2's 4096-character suspend data cannot hold a long essay. The suspend codec already drops question answers last when the data does not fit (P7.2); this is noted, not changed.

## Runtime

**Choices.** The engine's "choice objects" become "the marks a question is answered with":

- the choices of the graded choice kinds, and of pick one and pick many;
- a Likert question's points, statement by statement.

The saved `c` (chosen, by position) and the restore on revisit work over that list. Shuffle applies to the choices only.

**Marking.** `markAnswer` gives a survey kind `{ answered, correct: false, score: 0 }`, by the table above.

- Likert passes its answer as `values`: for each statement, the position of its chosen point, or `''`.
- Ranking passes the tiles' object ids in the order they stand, like sequence (drag).

**Submit:**

- an unanswered survey raises `questionUnanswered`, as before;
- an answered one is finished at once: `SavedQuestion.r = 'a'`, no `s`;
- `questionSubmit` reports `result: 'answered'`, `score: 0`, `attempt: 1`;
- the learner goes to `branch.answered`, or the next slide.

**Session state.** `r: 'a'` is new.

- The suspend codec packs it as `3` in the result slot, and unpacks it.
- Rule 17: everything that reads `r` is checked with a round-trip test.

**Locking.** A finished survey locks its entries, tiles and marks as a finished graded question does.

**Tracking.** Survey questions do not add to any score. Reporting them to an LMS (`cmi.interactions`, `answered` statements, `likert` and `long-fill-in` types) is P7.7, not this package.

## Editor

**Insert → Question** gains a "Survey" group: Likert, Pick One, Pick Many, Which Word, Short Answer, Essay, Ranking, How Many.

**Form View** for a survey kind shows the same rows as for a graded one, except:

- **Type:** pick one and pick many can be switched to each other, as multiple choice and multiple response can; every other kind shows its name;
- **Answers:**
  - **pick one / pick many:** the choices' words (add, delete, move), with no correct ticks;
  - **which word:** the words (add, delete);
  - **ranking:** the items (add, delete, move);
  - **Likert:**
    - the scale's labels (add and delete points, 2 to 10, laid out again across the grid);
    - the statements (add, delete, words);
  - **short answer, essay, how many:** a note that any answer is accepted;
- **no Score or Attempts rows.** Shuffle (pick kinds) and Required stay, in a row called "Options";
- **Feedback:** by question or none, one "Thank-you feedback" text, kept until P7.5 shows it;
- **Then:** one select, "After answering".

## Done when (step A)

- **Model:**
  - the survey kinds validate their parts and object types, and refuse graded fields;
  - migration 14 → 15 with the `v14-two-slides` fixture;
  - the property test inserts, deletes and copies each step-A kind, keeping ids unique and references sound.
- **Engine:**
  - answered and unanswered for pick one, pick many, short answer (spaces only), essay and how many (not a number);
  - a survey finishes on its first answered submit, scores 0, reports `answered` and takes its branch;
  - entries and marks are locked after, and kept on revisit and resume;
  - the suspend codec round trip with `r: 'a'`;
  - an essay keeps 4000 characters, a one-line entry 1000.
- **Render:** a multiline text entry drawn in the editor and live (a `<textarea>`).
- **Player browser (Chromium and Firefox):** pick many chosen and submitted; an essay typed over two lines and submitted; locked after.
- **Editor and e2e:**
  - insert pick one and essay, edit them in Form View (choices; feedback; branch);
  - save and reopen;
  - publish, and answer both in the course.

## Done when (step B)

- **Model:** which word and ranking validate and pass the property test.
- **Engine:**
  - a word dropped in the blank answers which word;
  - ranking swaps tiles and its order is the answer, unmoved or moved;
  - both are locked after, and placements survive revisit, resume and the codec.
- **Player browser:** a ranking reordered by dragging and submitted.
- **e2e:** author which word and ranking; save and reopen; publish and answer both.

## Done when (step C)

- **Model:**
  - Likert validates its labels, statements and points, and refuses a statement with the wrong number of points;
  - the property test inserts it and deletes a statement and a point.
- **Engine:**
  - one point per statement (a row's points exclude each other, rows do not);
  - answered only when every statement is rated;
  - the chosen points are kept on revisit, resume and the codec.
- **Editor:** Form View adds and deletes statements and scale points, and the slide's grid follows.
- **Player browser and e2e:** a Likert question rated and submitted; author one, save and reopen, publish and answer it.

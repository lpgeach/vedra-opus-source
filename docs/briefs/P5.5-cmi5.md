# P5.5 cmi5

**Work package:** P5.5, needs P5.4 (done). cmi5 is xAPI with rules about launch, auth, statement order and context. Read `P5.4-xapi.md` first: the transport (queue, retry, State API, keepalive) is shared.

## Where the code lives

- **In the course:**
  - `packages/player/src/lms/xapi.ts` has `lrsDriver(window, warn, course, profile)`, the driver for any LRS-based standard. A **profile** says how a standard starts.
  - `xapiProfile` takes its auth from the launch.
  - `cmi5Profile` (`lms/cmi5.ts`) trades the fetch URL for a token, reads `LMS.LaunchData`, and returns the session rules below.
  - `startCourse` takes `lms: 'cmi5'` and `activityId` (the unit's id).
- **At publish time:** `packages/publish/src/cmi5.ts`.
  - `publishCmi5(project, { courseId? })` writes the web course and `cmi5.xml`.
  - The course id defaults to `urn:vedraopus:course:<project id>`, and the unit's id is the course id plus `/au`.
  - `moveOn` comes from the course's reporting pair: `completed-…` gives `Completed`, `passed-…` gives `Passed`.

## Launch (cmi5 section 8)

1. **Read the address.** `endpoint`, `fetch`, `actor`, `registration` and `activityId` are all required. If any is missing, the course plays untracked with a console warning.
2. **Trade the fetch URL for a token.** `POST` the fetch URL with no Authorization header; the answer is `{"auth-token": "…"}`, used as `Authorization: Basic <token>`.
   - The fetch URL answers only once, so the token is kept in `sessionStorage` (this tab only) under the fetch URL, and a reload reuses it.
   - An error answer (`{"error-code", "error-text"}`) means untracked, with the LMS's text in the warning.
3. **Read `LMS.LaunchData`** from the State API (activity, agent, registration). It must have a `contextTemplate` and a `launchMode`. The course also uses `moveOn` and `returnURL`. `masteryScore` is read but only matters once quizzes exist (P7).
   - If it is missing or unusable, the course plays untracked.
   - Nothing is sent before this step.
4. **Read the course's own saved state** (as for xAPI), then send `initialized`.

## Statements (cmi5 section 9)

- **Every statement's context** is built on the `contextTemplate`, so it carries the LMS's session id and grouping. The registration is the launch's.
- **cmi5-defined statements** are `initialized`, `completed`, `passed`, `failed` and `terminated`. Their object is the unit (`activityId`), and they carry the cmi5 category (`https://w3id.org/xapi/cmi5/context/categories/cmi5`).
  - `completed`, `passed` and `failed` also carry the `moveon` category and `result.duration`, the time since `initialized`.
  - `terminated` carries the session's length.
- **cmi5-allowed statements** (`experienced` per slide, `answered`) carry the template's context and the unit as parent, but **not** the cmi5 category.
- **Order:** `initialized` comes first and `terminated` last.
  - `completed` is sent at most once per registration. The status reached is in the course's state document, which is keyed by registration.
  - `failed` never follows `passed`.
- **Launch modes:** in `Browse` and `Review`, no `completed`, `passed` or `failed` is sent. The course still plays, and saves progress.
- **`moveOn`:** if the LMS's `moveOn` is `Passed` or `CompletedAndPassed` and nothing was graded, completing the course also sends `passed`. That is the same rule P5.1 applies for `passed-…` reporting. Otherwise a course with no quiz could never satisfy the LMS.

## Return URL and exit

- `startCourse` now returns a `CoursePlayer` with `exit()`. It tells the LMS the learner is leaving (the same final save and `terminated` as closing the page), then goes to the launch data's `returnURL` if there is one.
- Nothing in the course calls `exit()` yet. The "exit course" trigger is P8.6, and it will call this. The return URL only matters for an explicit exit: a learner who closes the window has nowhere to return to.

## Done when

- **Browser tests against the mock LRS**, which also plays the cmi5 LMS: a one-use fetch URL, and `LMS.LaunchData` left in the State API. They assert:
  - the token is fetched once, and the launch data is read before the first statement;
  - the statement sequence for a full session;
  - each statement's form (registration, session id, cmi5 and `moveon` categories, durations);
  - a reload reuses the token;
  - `exit()` sends `terminated` and lands on the return URL;
  - Browse mode sends no completion;
  - `moveOn: CompletedAndPassed` gets `passed`;
  - a used fetch URL leaves the course untracked.
- **Unit tests:** launch and launch-data parsing, token reuse, refusals, launch modes, `moveOn`, never failed after passed, the return URL, and `cmi5.xml`.
- **`cmi5.xml` validates** against the cmi5 `CourseStructure.xsd`. This is a one-off xmllint check, recorded in the log; the XSD is not bundled.

## Not in this package

- The learner-preferences agent profile (language, audio): optional in cmi5.
- `masteryScore` deciding pass or fail: P7.
- Multi-unit courses, zip output and the publish UI (P5.6), and a check against a real cmi5 LMS (Luke, later).

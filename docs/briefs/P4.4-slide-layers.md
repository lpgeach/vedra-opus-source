# P4.4 Slide layers

**Work package:** P4.4, needs P4.3 (done). **Status:** implemented on branch `wp/p4.4-layers`. No saved-format change: overlay layers and their properties were already in the schema; the engine and player already ran them (P3.1, P3.2).

## Decisions

- **Commands:** `layer.add` (with optional triggers, for a duplicate), `layer.remove` (overlays only; also removes the triggers it owns and those that refer to it or its objects), `layer.rename`, `layer.move` (among overlays), `layer.setProperties`. `cloneLayer` in the model copies a layer with new ids and copies of its triggers pointing at the copies.
- **Editing a layer** reuses the Master View approach: `editedSlide` gives the stage a stand-in slide whose `baseLayer` is the chosen layer, with `alsoBeneath` (the base layer and the overlays below it whose eye is open) drawn beneath, dimmed and not selectable. The stage, timeline (each layer's own), Format and States panels and text editing therefore work on the layer unchanged. Panels that need the slide as stored (Triggers, Layers) look it up by id.
- **Eye** (per-layer visibility in the editor) is editor state, not saved: it controls whether a layer is drawn beneath the one being edited.
- **Layers panel** (right panel): top layer first, base layer last; click to edit, double-click to rename, move up/down, duplicate, delete, New layer; the edited overlay's properties (hide other layers, hide base objects, pause base timeline, block base clicks, allow seeking, when shown again).
- Scrubbing the timeline of an overlay asks the engine with that layer shown (`visibleAt(…, layerId)`).
- The player marks each object with `data-state`, the state it is drawn in.

## Golden runs (the plan's parity rule)

`fixtures/projects/states-and-triggers`: three tabs in a button set showing three panel layers, a variable counting tabs seen (once each, using a condition checked before the next trigger marks the tab seen), and Continue that moves on only when all three are seen, otherwise showing a hint layer. `golden.json` beside it is the script (clicks by object name) and what must hold after each step: slide, shown layers, visible objects, some objects' states and text with variables filled in. It was written by hand from the design.

- `fixtures/golden.test.ts` plays it against the engine alone.
- `e2e/golden.spec.ts` plays it in preview and in the published course from disk, reading the same facts from the page.

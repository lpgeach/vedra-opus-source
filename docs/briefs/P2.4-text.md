# Brief: P2.4 — Text

> **Status: in progress (2026-11-16).** Branch: `wp/p2.4-text`, from `master` (includes P0–P2.3, P2.2).

Plan entry: `docs/PLAN.md` section 8, P2.4. Depends on P2.2 (done). Replaces the provisional plain-text renderer in `packages/render/src/text.ts` (P2.3).

## Goal

An author can edit rich text directly on the stage inside text boxes and inside shapes and buttons, and the same text renders identically in the editor, in preview and in published courses.

## Scope (from the plan)

- TipTap-based in-place editing on stage for text boxes and text inside shapes/buttons: font, size, bold/italic/underline, colour, alignment, lists, line and paragraph spacing, links, autofit modes (shrink text, grow shape, fixed).
- Static serializer in `render` producing identical output without the editor.
- Bundled open-licence fonts; system fonts allowed with a publish-time warning.

Out of scope: format painter and theme-slot UI beyond what text needs (P2.5), text states/variable references rendering beyond storing them, animation-by-paragraph (P6), spellcheck/IME polish beyond browser defaults, right-to-left (P10), publishing warnings implementation if publish pipeline is not yet present (record the rule; warn where the pipeline exists).

## Model

- Keep `RichText` as a ProseMirror-style JSON document (`schema.ts`): `{ type: 'doc', content: RichTextNode[] }`. The model does not enumerate mark/node types; the editor and `@vedraopus/render` own the supported subset. Unknown nodes/marks must round-trip through the model unchanged (schema already allows arbitrary node/mark types/attrs).
- Supported document subset for P2.4:
  - **Block nodes:** `paragraph` (attrs: `textAlign?: 'left'|'center'|'right'|'justify'`, `lineHeight?: string|number`, `spaceBefore?: number`, `spaceAfter?: number` as needed), `bulletList`, `orderedList`, `listItem`, `hardBreak`.
  - **Inline:** `text` with marks.
  - **Marks:** `bold`, `italic`, `underline`, `textStyle` (attrs for `fontFamily`, `fontSize`, `color`/theme-aware color reference as stored), `link` (attrs `href`, optional `target`/`rel` conventions; links are not followed while editing on stage except via explicit affordance later—store them).
- **Theme font roles:** resolve `fontFamily` values that reference theme slots (`heading`/`body`) consistently in serializer and editor. Default body text uses the theme body font (current behaviour) when no explicit font is set.
- **Autofit (text objects, `TextObject.props.autofit`):** `none` | `shrinkText` | `growShape`. Shapes/buttons keep fixed frames in P2.4 (text reflows within padding; no frame growth from text). Apply autofit deterministically in render and mirror in editor view; `growShape` updates the object's frame through a command/gesture only when committed (not every keystroke in a way that breaks undo) — final rule chosen during implementation and documented in code/comments/tests as appropriate.
- Factories/helpers: extend `plainRichText` as needed; add helpers only if they reduce duplication (avoid speculative API).

## Rendering (`@vedraopus/render`, pure)

- Replace provisional `renderTextBlock` in `packages/render/src/text.ts` with a real static serializer: `RichText` doc → `RenderNode` tree (HTML/CSS) with no editor dependency and no React/DOM side effects.
- **Visual parity is the priority.** The serializer and the editor's on-stage text view must produce the same pixels for the same document within the visual-test tolerance. To achieve this:
  - Define a single set of CSS rules/class/inline-style conventions for rich text content (font stacks, sizes, line-height, paragraph spacing, list styling, alignment, mark styling) used by the static output.
  - The editor's TipTap instance must render with the same structure and CSS (same wrapper classes/data attributes, same font assets). Prefer sharing constants/CSS snippets or a small style module from `@vedraopus/render` rather than duplicating values.
  - Text inside shapes/buttons remains centred/aligned as today’s `align` option requires; text boxes align from the top/start unless paragraph alignment overrides.
- Handle empty documents, trailing breaks, empty paragraphs, and lists in a way that matches TipTap/ProseMirror expectations.
- `renderObject` continues to call the rich-text renderer for shape text, button labels, and text objects. `plainParagraphs` may be kept/reworked if still useful; remove or adapt provisional assumptions that conflict with rich text.
- **Fonts:** bundle the default open-licence font(s) needed for parity (at minimum the project default body/heading family if it is open-licence, e.g. Inter OFL) so visual tests and the app do not depend on system fonts. Load them in the editor and ensure render visual tests can load them (via test page CSS/assets) for deterministic screenshots. System fonts selected by the author remain allowed; a publish-time warning is required by the plan — if no publish-time validation point exists yet, add a clearly located hook/TODO note tied to publish work rather than inventing a UI flow now.

## Editor (desktop renderer)

- Add TipTap (and required ProseMirror/extension packages) as dependencies of the desktop app (and any other package that truly needs them), checking installed/compatible versions. Keep `@vedraopus/model` and `@vedraopus/render` free of editor/editor-framework dependencies per boundaries.
- **In-place editing on stage:** double-click (or explicit enter gesture consistent with stage UX) a text-bearing object (text box, shape with text, button) to start editing its text in place on the stage, above/within the object's frame and transformed with it (position/rotation/scale as applicable) so WYSIWYG matches static render.
  - While editing: text caret/selection active, stage object drag/resize/rotate interactions that would conflict are suppressed for that object; Escape commits/cancels according to a clear rule (do not lose work unexpectedly) and existing stage Escape behaviour remains sensible when not editing.
  - Commit edits to the project via model commands/history so changes are undoable. Coalesce typing into reasonable history steps/gestures (not one undo per character if avoidable), consistent with existing gesture patterns (`beginGesture`/`commitGesture`).
  - Only the object's `text` (and for `growShape` text autofit, its frame) changes; other properties unchanged.
- **Formatting controls:** expose the required formatting in the UI available in this package (ribbon/Home or a text context affordance consistent with the shell) — at minimum font family, font size, bold, italic, underline, text colour, alignment, bulleted/numbered lists, line spacing, paragraph spacing (before/after), and link editing. Controls reflect current selection marks/attributes.
- **Autofit behaviour:**
  - `fixed`: text wraps/clips within the frame (overflow handling consistent with render).
  - `shrinkText`: reduce rendered/edited text size to fit the frame down to a sensible minimum; do not mutate authored sizes destructively except as needed for the mode’s definition (prefer derived/layout behaviour; document the choice).
  - `growShape` (text objects): frame height/size grows to fit content; persisted via command when applied.
- **Shape/button text:** editable and stored in the existing `props.text` fields; rendered centred as today unless overridden by alignment rules chosen here (keep parity with static serializer).

## Implementation notes / risks

- Avoid duplicating text layout logic between serializer and editor; share CSS/tokens where possible.
- Bundled fonts must have clear licensing recorded if `docs/licences.md` or existing conventions require it (follow repo practice).
- Keep package boundaries intact: no React/Node/Electron/DOM imports in `model` or `engine`; `render` stays framework-agnostic.
- `stage/RenderTree.tsx` currently maps `RenderNode` to React for the stage — text editing will likely require a special editable path for the active object; ensure non-editing display still matches static output.
- Changing `packages/model/src/schema.ts` requires a version bump, migration, and legacy fixture — avoid schema shape changes unless necessary; prefer using existing `RichText`/attrs extensibility.

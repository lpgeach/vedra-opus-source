# P11.2 Templates and reusable content

**Plan:** "Save project as template; import slides from another project or template; built-in starter templates of our own design."

An author who has made a course they like starts the next one from it, or takes a few slides from another course into this one. Starter templates give a new author somewhere to begin.

Built in three parts, each on its own branch and merged on its own. The plan's box is ticked after part C. There is no saved-format change.

## What a template is

**A template is an ordinary project file** (`.vedraopus`), kept in the templates folder. There is no separate format or extension:

- what opens as a project opens as a template, and the reverse;
- an author can share a template as they would a project.

- **The templates folder:** `Templates` in the app's user data folder (`app.getPath('userData')`). It is made when first needed.
- **Built-in templates** (part C) ship with the app, read-only, in `resources/templates/` (and `apps/desktop/resources/templates/` in development).

## Part A: save as template, new from template (`wp/p11.2a-templates`)

**File → Save as Template…**

- It asks for a name, suggesting the project's title, and writes the project, with its media, as `<name>.vedraopus` in the templates folder.
- A name already there is replaced after asking.
- The open project is not changed: its file, title and unsaved state stay as they were. Saving as a template is a copy.
- Characters a file name cannot hold are replaced, as Save As does.

**File → New from Template…** (and a "New from Template…" button on the Welcome screen) opens the template chooser:

- **The list:** the built-in templates first, then the author's own, each with its name, its slide count and its stage size. The author's own can be deleted from here, after asking.
- **Browse…** chooses any project file to start from.
- **Choosing one** opens a new, unsaved project made from it:
  - its slides, masters, variables, theme, player and media;
  - a new project id;
  - its title is the template's.
  - Nothing links the new project to the template afterwards.
  - Saving asks where, as for a new project.
- A template that cannot be read is listed with the reason, and cannot be chosen.

**IPC:**

- `template.list` returns the templates: built-in or own, path, name, slide count, stage size, or a reason it cannot be read.
- `template.saveCurrent` (name), `template.remove` (path; own templates only) and `template.open` (path, or none to browse) do the rest.

Main reads a template's details from its container without unpacking its media. The words go in the string catalogue (P10.4).

**Tests:**

- unit: listing (built-in and own, sorted, unreadable ones with their reason), saving (a copy; the session untouched; replacing), opening (a new id, unsaved, no source path, its media there), and refusing to remove a built-in template;
- e2e: save a project as a template, start a new project from it through the chooser, and find its slides and picture.

**As built (session 91):**

- `readContainerProject` reads only `project.json` from a file (with the same size limit and checks as opening), so listing templates does not unpack their media.
- `templates.ts`:
  - `listTemplates` returns built-in then own templates, each sorted by name; a folder not there yet is an empty list;
  - `templateFileName` makes the file name;
  - `isOwnTemplate` checks a path is a project file directly inside the own folder, so a built-in or any other file cannot be deleted through `template:remove`.
- A project from a template opens **unsaved** (`dirty: true`), so closing it asks. New Project, which starts empty, does not ask.
- The chooser shows over the Welcome screen or the editor (`App`), and Save as Template only in the editor.

## Part B: import slides (`wp/p11.2b-import-slides`)

**File → Import Slides…** chooses a project or template file, then lists its scenes and slides, with checkboxes. The chosen slides are copied in after the current slide, in their order, as **one step that Undo takes back**.

What comes with them, so the project stays whole:

- **Media:** the files the copies use are copied into the open project's media (main does this before the step).
- **Masters and layouts** the copies use are added. A master already in the project, with the same id and the same content, is not added twice.
- **Variables:** a variable the copies use is matched by name with one already in the project. If the types differ, or there is none of that name, the variable is added; on a clash its name gets a number.
- **Triggers:**
  - a jump between copied slides points at the copy;
  - one to a slide, layer, object or player tab that did not come is dropped;
  - a question's branch to a slide that did not come goes to the next slide, as when a slide is deleted.
- **Draw slides** bring the bank they draw from, as a new bank, with their locked questions.
- **Result slides** keep the included slides that came.
- Each copy has new ids throughout, as Duplicate gives (`cloneSlides`).

A short report says what was added (slides, masters, variables, media) and what was dropped.

**Tests:**

- unit, in the model: the copy and each rule above, and the project valid after (`findReferenceIssues` empty);
- e2e: import two of a saved project's slides, see them and their picture, undo.

**As built (session 92):**

- **The model:** `prepareSlideImport(target, source, slideIds)` (`packages/model/src/import-slides.ts`) returns the copies, banks, masters, variables, the media they use, and what was dropped. The `slides.import` command adds them all as one step, checking every id is new and no variable name is taken.
  - The masters already in the project come before the new ones, and the feedback master stays last.
  - A source's feedback master is never added: a copy using one of its layouts takes this project's feedback layout of the same role.
- **Ids:** `cloneSlides` gives the new ids. Each old id is then paired with its new one by walking the original beside the copy, and every string in the copies naming an old id names the new one.
- **Variables:**
  - matched by name, ignoring case, where the type is the same;
  - otherwise added, with a number on the name if it is taken, and `%Name%` in the copies' text follows;
  - a field bound to a variable that did not come is unbound.
- **Media:** any of the source's media hashes named anywhere in the copies, banks or masters. Main copies those files out of the source file (`extractAssets`), and only from the file the author last chose in Import Slides, before the command runs.
- **Found and fixed:** `cloneSlides` (used by Duplicate) did not follow a result slide's Passed and Failed layers or the Tab order into the copy. A duplicated result slide made the project invalid, so saving it would fail. It now maps every reference inside each copy.

## Part C: built-in starter templates (`wp/p11.2c-starter-templates`)

A few starter templates of **our own design**: our layouts, colours and wording. Their pictures come only from the CC0 illustrations and Lucide icons already in the app (P9.8). Nothing comes from other products' templates. Proposed:

- **Blank, 16:9:** a title slide and a title-and-content layout in our default theme.
- **Short course:** a title slide, three content slides, a knowledge check of two questions and a results slide.
- **Branching scenario:** a situation, three choices, a consequence slide for each, and a summary.
- **Quiz:** six questions of different types from a bank, drawn in random order, with a results slide tracked as completion.

They are made by code from the model's factories, so they always match the current format. A test checks each is valid, and the e2e opens one in the app.

**As built (session 93):**

- **Made in main when asked, not shipped as files** (`starter-templates.ts`). Each template is a function building a project from the model's factories. The chooser lists them as `builtin:<key>`, and New from Template builds one afresh with new ids. Being code, they always match the current format, and nothing needs packaging. The built-in templates folder still works for files placed there; none are shipped.
- **Our design:**
  - two palettes of our own (Harbour: blues; Meadow: greens), Inter for headings and body;
  - a master of our own with a band across the top;
  - titles at 40 px bold, text at 22 px;
  - no pictures, so nothing from any library or other product.
- **The four:**
  - **Blank course:** one title slide.
  - **Short course:** title, what you will learn, two content slides, a multiple-choice and a true-or-false check, and a results slide tracked as completion.
  - **Branching scenario:** a situation with three choice buttons, each to its consequence slide, each with Continue to the summary.
  - **Quiz:** an introduction; a bank of six questions of six kinds; a draw of all six at random; a results slide tracked as completion.

## Not in this package

- Thumbnails of templates' slides in the chooser: the list shows names and counts. Slide pictures can come with P11.5's performance work.
- Templates on a shared drive or a server: Browse… opens any file, which covers a shared folder.

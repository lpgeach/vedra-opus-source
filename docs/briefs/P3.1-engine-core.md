# P3.1 Engine core

**Work package:** P3.1, needs P1.1 (done). **Status:** implemented on branch `wp/p3.1-engine-core`.

`packages/engine`: a headless runtime for plan section 5. It imports `@vedraopus/model` types only and never touches the DOM, timers or Node. Triggers are not here (P4.3); the engine raises the events they will listen to.

## Surface

```ts
const engine = createEngine(project, { restore?: SessionState });
engine.tick(nowMs);                 // the only source of time
engine.next(); engine.previous(); engine.jumpToSlide(slideId);
engine.seek(layerId, seconds); engine.setPaused(layerId, paused);
engine.showLayer(layerId); engine.hideLayer(layerId);
engine.setObjectState(objectId, stateId);   // no-op if the object lacks that state
engine.getVariable(name); engine.setVariable(name, value);
engine.getView();                   // what a renderer needs: slide, layers, objects on stage and their state
engine.on(listener);                // EngineEvent stream; returns an unsubscribe function
engine.getState();                  // SessionState (JSON, short keys, only non-default values)
```

## Decisions

- **Time.** `tick(nowMs)` advances each running layer by the wall-clock delta since the previous tick (the first tick only sets the reference; a clock that goes backwards advances nothing). Playheads are seconds. A layer's timeline stops at its duration and fires `timelineEnd` once.
- **Object lifecycle.** An object is on stage while the playhead is in `[start, start + duration)`; `untilEnd` lasts to the end of the timeline, including the final instant. Crossing fires `objectEnter` / `objectLeave`. Only top-level layer objects have lifecycles (a group's children follow the group). A `hidden`-state object stays "on stage" but the view marks it not visible.
- **Slide entry.** `reset` rebuilds from the document; `resume` restores saved object states, shown layers and playheads; `auto` resumes only when a button on the slide is in a non-initial state. A fresh (reset) entry starts the base timeline at 0, emits `slideEnter`, `timelineStart` and an `objectEnter` for each object on stage at 0. A resumed entry restores silently apart from `slideEnter` (`resumed: true`). Leaving a slide saves its snapshot and emits `slideExit`.
- **Navigation** follows course order (scenes, then slides). `next` on the last slide and `previous` on the first do nothing and return false. A slide with `advance: 'auto'` moves on when its base timeline ends.
- **Layers.** The base layer is always shown. `showLayer` starts an overlay from 0 (or resumes its playhead when its `onRevisit` is `resume` and it was shown before on this entry) and applies `hideOtherLayers`; `pauseBaseTimeline`, `hideBaseObjects` and `blockBaseClicks` are exposed in the view for views and the later trigger work. `hideLayer` reverses it.
- **Events** are queued and delivered in order after the operation that caused them finishes, so a listener that navigates cannot see half-updated state.
- **SessionState** (`v: 1`): `s` current slide id, `x` variables that differ from their defaults (by variable id), `vis` visited slide ids, `sv` saved snapshots per slide (`o` non-initial object states, `l` shown overlay layer ids, `t` playheads, only non-zero). Restoring resumes the current slide. Compression is the publish drivers' job.
- **Variables** are project-scoped, looked up by name ignoring case, and type-checked on set; changes emit `variableChange`.

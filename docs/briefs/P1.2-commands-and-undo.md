# Brief: P1.2 — Commands and undo

> **Status: implemented 2026-11-15.** Kept for the reasoning. Where the code differs from this brief, the code and `skills/model-package.md` are right: `undo()` during a gesture cancels the gesture and stops; changes carry a fourth source, `cancel`; out-of-range indexes are errors; payloads inserted by a command are always schema-checked, while whole-project validation stays behind `validate: true`.

Plan entry: `docs/PLAN.md` section 8, P1.2, and section 4.3. Depends on P1.1 (done).

## Goal

Give `packages/model` the only write path to a project: named commands that produce patches, with undo and redo. The editor UI (Phase 2) will call nothing else to change the document.

## Where it goes

All in `packages/model/src/` — pure TypeScript, no React, no Zustand. The React/Zustand binding is **not** part of this package; it comes with P2.1.

```
commands/
  types.ts        Command, CommandMap, the registry type
  registry.ts     all command handlers, keyed by name
  scene.ts        scene and slide commands
  object.ts       object commands
  project.ts      project-level commands (rename, stage size)
history.ts        createHistory(): execute, undo, redo, gestures, subscribe
find.ts           lookups by id: findSlide, findLayer, findObject (with parent list and index)
```

## Dependency

Add Immer to the model package: `npm install -D immer -w @vedraopus/model`. Call `enablePatches()` once. Check the installed version's API in `node_modules/immer` before use.

## Design

**Command handler.** A handler is a function that mutates an Immer draft:

```ts
type Handler<P> = (draft: Draft<Project>, payload: P) => void;
```

A handler throws `CommandError` (new class, with a message meant for developers) if the payload refers to something that does not exist. It must not leave a half-applied change — Immer discards the draft when the handler throws, so this comes for free.

**History.**

```ts
interface History {
  readonly project: Project; // current immutable document
  readonly canUndo: boolean;
  readonly canRedo: boolean;
  execute<K extends CommandName>(name: K, payload: CommandMap[K]): void;
  undo(): void;
  redo(): void;
  beginGesture(label: string): void; // start coalescing
  commitGesture(): void; // everything since begin becomes ONE undo step
  cancelGesture(): void; // revert everything since begin, add no undo step
  subscribe(listener: (change: Change) => void): () => void;
}
interface Change {
  project: Project;
  patches: Patch[];
  source: 'execute' | 'undo' | 'redo';
}
```

- `execute` runs the handler through `produceWithPatches`, stores `{ patches, inversePatches, label }` on the undo stack, clears the redo stack, and notifies subscribers.
- A command that produces no patches adds no undo step and notifies nobody.
- Inside a gesture, each `execute` applies immediately (so the stage updates live while dragging) but its patches accumulate; `commitGesture` pushes one combined entry. Inverse patches are applied in reverse order of accumulation.
- `undo` with an open gesture cancels the gesture first.
- Cap the undo stack (default 200 entries).
- After every `execute`, in development and tests only, the result must still satisfy `findReferenceIssues(project).length === 0`. Put this behind an option on `createHistory({ validate: true })` and turn it on in all tests.

**First commands** (payloads take ids, never array positions except where a position is the point):

| Command                | Payload                       | Notes                                                                                                             |
| ---------------------- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `project.rename`       | `{ title }`                   |                                                                                                                   |
| `project.setStageSize` | `{ width, height }`           | Sets the size only; rescaling objects is P2.5                                                                     |
| `scene.add`            | `{ scene, index? }`           | Caller builds the scene with `createScene()`; default index = end                                                 |
| `scene.remove`         | `{ sceneId }`                 | Refuse to remove the last scene. Also removes or rejects triggers jumping to its slides — see below               |
| `scene.rename`         | `{ sceneId, title }`          |                                                                                                                   |
| `scene.move`           | `{ sceneId, index }`          |                                                                                                                   |
| `slide.add`            | `{ sceneId, slide, index? }`  |                                                                                                                   |
| `slide.remove`         | `{ slideId }`                 |                                                                                                                   |
| `slide.rename`         | `{ slideId, title }`          |                                                                                                                   |
| `slide.move`           | `{ slideId, sceneId, index }` | Moves within or between scenes                                                                                    |
| `object.add`           | `{ layerId, object, index? }` | Default index = top of z-order                                                                                    |
| `object.remove`        | `{ objectIds }`               |                                                                                                                   |
| `object.update`        | `{ objectId, changes }`       | `changes` is a partial of the top-level object fields; `frame`, `timing`, `a11y` and `props` merge one level deep |
| `object.reorder`       | `{ objectId, index }`         | Within its parent list                                                                                            |
| `object.rename`        | `{ objectId, name }`          |                                                                                                                   |

**Dangling references.** Removing a slide or object can leave triggers pointing at it, which `parseProject` would then reject. Rule: the removal command also removes every trigger on the affected slides whose owner, event, action, `otherwise` or conditions reference a removed id. This is what keeps the validate-after-execute check passing. Put the "which triggers reference this id" logic in one helper and unit-test it directly.

## Tests required

1. Each command: applies the change; rejects unknown ids with `CommandError` and leaves the document untouched.
2. **Property test** (fast-check is already installed): generate a random sequence of valid commands against a starting fixture; after executing them all then calling `undo` the same number of times, the project deep-equals the original; then `redo` the same number of times deep-equals the post-execute state. Run at least 200 cases.
3. Gestures: 20 `object.update` moves inside one gesture = one undo step; `cancelGesture` restores the pre-gesture document exactly.
4. Redo stack clears on a new `execute`.
5. Removing an object or slide removes triggers that reference it, and undo brings both back.
6. The project is never mutated in place: hold a reference to `history.project` before an `execute` and assert it is unchanged after.

## Done when

The tests above pass, the full check suite is green, and `packages/model/src/index.ts` exports `createHistory`, `CommandError`, and the command types. Then follow the Definition of done in `AGENTS.md`.

## Out of scope

Zustand store, React hooks, autosave, selection state, clipboard, any UI. Trigger, variable, state and layer editing commands arrive with the packages that need them (P4.x), following the same pattern.

# P2.5 Format and theme

**Work package:** P2.5 — Format and theme  
**Needs:** P2.3 (done)  
**Status:** implemented on branch `wp/p2.5-format-theme`

This brief resolves the design choices left open by the P2.5 line in `docs/PLAN.md` §8:

> “Format panel for the selected object(s); theme colours and theme fonts with objects referencing theme slots; format painter; stage size change with scale/crop options.”

The goal is authoring-time formatting and project theming that stays compatible with the existing schema/render engine: objects may reference theme colour slots and theme fonts, formatting applies through commands (undoable), and changing stage size can either scale content or crop/leave it in place.

---

## 1. Scope

In scope:

- **Format panel for selected object(s).** A right-side panel UI that edits visual properties of the current selection (one or many objects). Supports the object kinds present in v1 (`text`, `shape`, `image`, `button`, `group` as applicable) with controls relevant to each: position/size/rotation, fill/stroke/shadow/opacity for shape/button/image appearance, corner radius for buttons/round rect geometry where applicable, text-box padding/autofit for text objects, and image fit/crop controls where practical. For multi-select, show a mixed/indeterminate state when values differ and apply edits to every selected object.
- **Theme colours and theme fonts with objects referencing theme slots.** Project theme (`project.theme.colors` and `project.theme.fonts.heading/body`) is editable. Colour pickers in formatting controls can choose a **theme slot** or a **literal** colour; choosing a slot stores `{ theme: <slot> }` so the object follows theme changes. Text formatting can assign theme fonts (heading/body) as well as literal font families. Existing render/serializer behaviour for theme refs continues to work.
- **Format painter.** Copy formatting from a source object and apply it to target object(s) with a click. Painter can be single-use or locked (double-click/toggle) until cancelled (Escape/clicking the tool again). Applies compatible properties (appearance/fill/stroke/shadow/opacity/text styling where meaningful) without changing identity, position in z-order, or non-format content except as needed for text style.
- **Stage size change with scale/crop options.** UI to change `project.stage` size with a choice of how existing content adapts:
  - **Scale to fit/stage scale:** proportionally (or as chosen) scale and reposition object frames/timings-independent geometry to the new stage so layout is preserved relative to the stage.
  - **Crop / keep size:** change the stage bounds without scaling objects (objects keep their frames; content may be clipped or leave empty margins).
    The operation is undoable as a single user action.

Out of scope:

- New object types, masters/layout editing, gradients/fills editor beyond solid+existing schema support unless trivial, animation/transition formatting (P2.6+), player/publish theme application beyond existing data, accessibility audit of the panel (P10), and importing external theme files.
- Full rich-text style painting parity with every mark/paragraph attribute edge case beyond a reasonable “format” subset (font, size, bold/italic/underline, colour, alignment/spacing where representable) if copying full ProseMirror docs is not safe; prefer copying representable text style/appearance.

---

## 2. Model and commands

- **No schema bump required** if all persisted data uses existing shapes: `Color = hex | { theme: ThemeColorSlot }`, `Theme`, object `appearance`/`props`, and `project.stage` already exist. Theme slot names remain the fixed set in `themeColorSlots`. Theme fonts remain `heading`/`body` strings.
- **Theme edits** are document changes and must go through commands (new commands as needed), e.g. update theme colours/fonts, so they are undoable and trigger re-render.
- **Format edits** use existing `object.update`/batch commands where possible, or add focused commands if needed for clarity/multi-object application. All formatting changes must be undoable.
- **Stage size with options:** `project.setStageSize` currently sets size only (objects keep frames). Implement scale/crop either by (a) extending/replacing with a new command that also transforms objects in one atomic change, or (b) composing a single coalesced/transactional history step — prefer an explicit command that captures intent and produces one undo step. Migration/fixture impact: none if schema shape unchanged; update fixtures/tests as needed.
- **Theme font references in text:** support storing theme font intent (heading/body) in text marks/attributes in a way the serializer and editor understand, mapping to resolved font names at render time via `context.theme.fonts`. If the current editor stores literal family strings, add a stable encoding (e.g. sentinel values `__theme_body__`/`__theme_heading__` or an equivalent mark attribute convention) and teach render + editor to resolve/display them. Document the chosen encoding.

---

## 3. UI behaviour

- **Format panel location:** add a **Format** (or Properties) tab/section to the right panel alongside Triggers and Slide Layers so object formatting is discoverable without removing planned panels. The panel reflects the selection: nothing selected → helpful empty state; selection → editable controls.
- **Selection:** single selection shows exact values; multi-selection shows shared values or “Mixed”, and edits apply to all selected objects that support the property. Groups may expose group-level frame/appearance where supported; formatting children deeply is out of scope unless already supported.
- **Colour controls:** present theme swatches (slots) and a custom/literal picker. Indicate when a value is a theme reference. Changing a theme slot’s colour updates all objects referencing it on next render.
- **Format painter:** command/button in ribbon or format panel. Cursor/active state indicates armed painter. Applying copies supported format aspects; clicking stage background or pressing Escape cancels (locked mode cancels on toggle/Escape).
- **Stage size UI:** expose in Design tab and/or a project/slide size control. Dialog or inline control offers new dimensions (and common presets if easy) plus **Scale content** vs **Keep content/crop** (names TBD in UI copy) before applying.

---

## 4. Rendering and parity

- `@vedraopus/render` must continue to resolve theme colour refs and theme fonts identically for editor/static contexts. Any new theme-font encoding in rich text must serialize/resolve the same in `renderRichText`/text rendering as in the editor.
- Formatting changes must be visible immediately on stage and in thumbnails/overview renders that use the same render path.
- No DOM/Node/Electron imports in `packages/model` or `packages/engine`.

---

## 5. Tests (“Done when”)

Cover the plan’s P2.5 requirements with automated tests:

- **Format panel / formatting:** component/integration or e2e coverage that selecting object(s) exposes format controls and applying changes updates the document (and is undoable). Multi-select applies to all selected.
- **Theme colours and fonts:** unit/integration tests that objects can reference theme slots/fonts, editing a theme slot/font updates rendered output for referencing objects, and literal values remain supported.
- **Format painter:** test that copying/applies formatting between compatible objects works (and does not corrupt unrelated properties), including cancel/single-use behaviour as implemented.
- **Stage size scale/crop:** unit tests for the transform math/command semantics (scale vs crop) proving frames/stage update correctly and undo restores prior state; UI/e2e smoke that the option is offered and applied.

`packages/render` visual tests: if rendering/output changes, update/add snapshots as needed and ensure `npm run test:visual` passes for available browsers (WebKit may be CI-only locally).

---

## 6. Risks and notes

- **Text theme-font encoding:** must round-trip through save/load and match editor + static serializer; avoid breaking existing documents (default to current literal behaviour when unset).
- **Scale transforms:** scaling groups/rotated objects and non-rect geometry needs care; define behaviour clearly (scale frames about stage origin or proportionally within new bounds) and test it.
- **Mixed selection complexity:** keep v1 manageable—format only properties common/safe across selected types; disable or mark mixed where not applicable.
- **CI:** Actions minutes unavailable this month; do not claim CI green. Record CI as not run/unverified in session log. WebKit visual tests may be unverified locally on Arch.

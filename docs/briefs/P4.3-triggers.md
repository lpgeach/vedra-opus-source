# P4.3 Triggers

**Work package:** P4.3, needs P4.1 and P4.2 (done). **Status:** implemented on branch `wp/p4.3-triggers`. No saved-format change: triggers, events, actions and conditions were already in the schema.

## Engine (plan section 5)

- Every event the engine raises also goes on a trigger queue. `flush` works through it before listeners hear anything: for each event, the current slide's enabled triggers listening for it, object-owned first, then layer, then slide, each in list order (`inEvaluationOrder`).
- A trigger counts only while its owner is on a shown layer (an object on a hidden layer, a hidden layer's own triggers do not run).
- Conditions are checked as each trigger runs, so an earlier trigger's change is visible to a later one. Failing conditions run `otherwise`, if set. `and` / `or`; variable comparisons (numbers as numbers, `contains` ignoring case, `==i` and `!=i` as text ignoring case (B12), booleans as `true`/`false`) and object-state tests (the state as drawn).
- A jump ends the event's remaining triggers. Events raised by actions are queued one level deeper and handled breadth-first after the current event; levels past `MAX_CASCADE_DEPTH` (32) are dropped with one `warning` event.
- Input: `pointer()` now also raises `objectInput` (click, doubleClick, rightClick, mouseEnter, mouseLeave) after applying the automatic states, so a click trigger sees the object already selected. `key()` raises `keyPress` (letters match either case, named keys exactly). `timelineReaches` is raised when a playhead passes a time some trigger waits for.
- Actions: change state, show/hide layer, jump (slide, next, previous; nothing at either end), set variable (assign with conversion to the variable's type, add, subtract, multiply, divide (not by zero), append for text; from a value or another variable), toggle, pause/resume timeline, open URL (`openUrl` event: the player opens http, https and mailto addresses in a new window; preview sends them to the learner's browser). Execute JavaScript does nothing until P4.6.

## Model

`trigger.add`, `trigger.update`, `trigger.remove`, `trigger.move`. Add and update are refused when the trigger refers to objects, layers or cue points not on its slide (the project's own reference check, scoped to that trigger).

## Editor

- **Triggers panel** (right panel): grouped by owner (slide, each object, each layer) in document order; each trigger shown as a sentence, with enabled checkbox, move up/down within its owner, copy, delete; New trigger, Paste trigger (refused with a message on a slide that lacks what it refers to), Variables.
- **Trigger wizard**: one line per part, read as a sentence: action and its target; "when" the event and its target; "if" conditions (any number, all/any); "otherwise" an action. The finished sentence is shown below. A new trigger starts out about the selected object. Options that cannot apply (no variables, no layers) are disabled. The owner follows from the event.
- **Not here:** the plan's "player buttons" owner group: the saved format has no player owner yet, and the player's own buttons arrive with P8.1. Click-to-reveal in the tests uses a hidden state, because layers are edited from P4.4.

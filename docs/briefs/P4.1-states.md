# P4.1 States

**Work package:** P4.1, needs P3.1 and P2.5 (done). **Status:** implemented on branch `wp/p4.1-states`. No saved-format change: states, overrides and `buttonSet` were already in the schema.

## Engine (plan section 5)

`engine.pointer(kind, objectId)` with `enter | leave | down | up | click` drives the built-in states and returns whether the object took the input.

- The state an object is **drawn in** is, in order: `disabled` or `hidden` if set; `down` while pressed; `hover` while under the pointer; `selected` or `visited`, whichever was applied last; then the state it was last changed to (or its initial state). A state the object does not have is skipped.
- `selected` toggles on click. In a button set a click always selects and deselects the others in the set; a second click keeps it.
- `visited` is applied by the first click and stays. On that first click selected is applied first, then visited, so visited shows; selecting again later shows selected ("the last applied of the two").
- `disabled` and `hidden` refuse all input; hover and down are cleared when they are set. Objects off stage, or on the base layer under a layer that blocks base clicks, also refuse input.
- `setObjectState`: `selected` and `visited` apply the mark (button-set rule included); `normal` clears both; anything else becomes the object's own state.
- An object whose initial state is `selected` or `visited` starts with that mark over normal, so it can be deselected.
- Selected and visited marks are saved in `SessionState` (`f`, per slide, in application order); hover and down are not.
- `objectStateChange` fires whenever the drawn state changes.

## Model

- `resolveObjectState(object, stateId)`: normal plus the state's overrides (frame, appearance, text, asset); cached per object.
- Commands `state.add`, `state.remove` (not `normal`; resets the initial state if it was that one; removes triggers that used it), `state.update` (rename, replace overrides; `{}` resets). `object.update` accepts `initialState`, and with `stateId` writes frame, `props.appearance` (only keys that differ from normal), `props.text` and `props.asset` into that state; other fields apply to the object.

## Player

Pointer events go to `engine.pointer`; an object whose drawn state changed is redrawn in place. A click is recognised as press and release on the same object, because redrawing replaces the pressed node and browsers then fire no click.

## Editor

- **States tab** (bottom panel) for one selected object: a chip per state, Add state (missing built-ins or Custom…), Duplicate, Reset, Delete, Initial state, Button set.
- **Edit-states mode:** choosing a chip other than Normal shows the object in that state on the stage (`editedSlide` resolves it), and the history gives every `object.update` for that object the state id (one proxy in `adopt`), so the stage, Format panel, text editing and ribbon all edit the state without knowing. The mode ends on Done, on choosing Normal, or when the selection moves on.

## Not in this package

Triggers that change state (P4.3), states for groups' children, drag-and-drop states' behaviour (P9), per-state timing, state thumbnails, keyboard activation of buttons in the player.

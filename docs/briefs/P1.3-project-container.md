# Brief: P1.3 — Project container and asset store

> **Status: implemented 2026-11-15.** Kept for the reasoning. Differences in the code: dialogs are stubbed from tests with `answerDialogs` (no test-only code path in the app); the working copy records `dirty` rather than `cleanClose`; save and save-as take the document as an argument so they never depend on autosave timing; the bridge method for a new project is `project.create()`. `docs/development.md` ("Project files") describes what was built.

Plan entry: `docs/PLAN.md` section 8, P1.3, and section 3.4. Depends on P1.1 (done) and P0.2 (done). Best done after P1.2, because autosave listens to the history's change events.

## Goal

A project lives on disk as one `*.vedraopus` file. The author can create, open, save, save-as and reopen recent projects, never loses work to a crash, and can import media.

## Where it goes

Main process, under `apps/desktop/src/main/project/`. The renderer only calls IPC.

```
project/
  container.ts     read/write the .vedraopus zip
  workspace.ts     the unpacked working directory for an open project
  assets.ts        hash + copy on import, lookup by hash
  protocol.ts      vedraopus-asset:// handler
  recent.ts        recent-files list
  recovery.ts      detect and offer unclean working directories
```

## Dependency

Zip reading and writing: `yazl` and `yauzl` (pure JS, streaming). Install into `vedraopus-desktop` as devDependencies (everything is bundled — see `docs/development.md`). If either turns out not to bundle cleanly with the current build, pick another pure-JS zip library and record the choice in `docs/adr/`. No native modules.

## File format

```
project.json            the document
assets/<sha256>.<ext>   media, one file per unique content
meta.json               { "formatVersion", "appVersion", "createdAt", "modifiedAt" }
```

(`thumbs/` from the plan is added by P2.6; ignore unknown top-level folders when reading.)

## Behaviour

**Working directory.** Opening or creating a project makes a directory `<userData>/workspaces/<random>/` containing the unpacked files plus `workspace.json`: `{ sourcePath | null, openedAt, cleanClose: false }`.

**Open.** Unzip to a new working directory → read `project.json` → `parseProject` (from `@vedraopus/model`) → return the project to the renderer. On `ProjectValidationError`, delete the working directory and return the issues so the renderer can show them. Guard against zip-slip: reject any entry whose resolved path escapes the working directory. Reject entries over a sane size limit.

**Save.** Write `project.json` and `meta.json` in the working directory, zip the working directory (excluding `workspace.json`) to `<target>.tmp-<random>` in the **same directory** as the target, flush, then rename over the target. Only assets referenced in `project.assets` are included. A failed save must leave the previous file intact.

**Autosave.** The renderer sends the serialised project after changes, debounced (about 1 s). Main writes it to the working directory's `project.json` via temp-file-and-rename. This does not touch the `.vedraopus` file.

**Dirty state.** Main tracks whether the working copy differs from the last save. The window title shows the project name with a marker when dirty (follow each platform's convention; on macOS use `setDocumentEdited`). Closing a dirty window asks Save / Don't Save / Cancel.

**Clean close.** On normal close, set `cleanClose: true` then delete the working directory.

**Recovery.** At launch, any working directory without `cleanClose: true` is a crash leftover. Offer to recover each (project title, time). Recovering opens it as a dirty project still tied to its `sourcePath`. Declining deletes it.

**Assets.** Import = read the file, SHA-256 it, copy to `assets/<hash>.<ext>` if not already there, return `{ hash, meta }` for the renderer to add to `project.assets` through a command. Detect kind and MIME from the extension against an allow-list (png, jpg, jpeg, gif, webp, svg, mp3, m4a, wav, ogg, mp4, webm, woff2, ttf, otf). For images, read width and height. Reject files not on the list.

**Protocol.** Register `vedraopus-asset` as a privileged, standard, secure scheme before `app.ready`. `vedraopus-asset://<workspaceId>/<hash>` serves the file from that workspace with the right content type. Validate that `<hash>` is 64 hex characters and never build a path from anything else in the URL. Add `vedraopus-asset:` to `img-src` and `media-src` in the renderer's CSP (`apps/desktop/src/renderer/index.html`).

**Recent files.** Last 10 paths in `<userData>/recent.json`; drop entries whose file no longer exists; also call `app.addRecentDocument`.

**File association.** Add `fileAssociations` for `.vedraopus` to `electron-builder.yml`. Handle a path passed on the command line, the `second-instance` event (Windows, Linux), and `open-file` (macOS).

**Menu.** Enable File → New, Open, Save, Save As in `src/main/menu.ts`.

## Renderer

Minimal for this package: a welcome screen with New, Open, the recent list, and a recovery prompt; when a project is open, show its title and slide count. The real editor is Phase 2.

## Tests required

- Unit (Vitest, in `apps/desktop/src/main/project/*.test.ts`, using temp directories): container round trip; zip-slip entry rejected; failed save leaves the original intact; importing the same bytes twice stores one file; unreferenced assets are not written to the saved file.
- E2E: the three scenarios in the plan's "Done when" — (1) create, import an image, save, quit, reopen, image present; (2) kill the process mid-edit, relaunch, recovery restores the edit; (3) same file imported twice is stored once. Use `fixtures/projects/two-slides/assets/*.png` as the image.

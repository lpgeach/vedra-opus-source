# P7.7 Result slides

**Work package:** P7.7, needs P7.6 (done, merged in PR #59). The last package of Phase 7.

**Plan line:** graded and survey results; choose which questions or other result slides to combine; pass mark; timer; show score, review quiz, retry quiz, print results; built-in score variables; hook into P5 tracking and `cmi.interactions` / `answered` statements with correct interaction types.

**My design choices**, made without asking (Luke said to continue), listed for Luke to change:

1. **A result slide is an ordinary slide with a `result`.** New ones come with text that shows the score through built-in variables, Passed and Failed layers, and Review, Retry and Print buttons.
2. **A result is worked out when the learner reaches its slide.** It sums the included questions' saved scores, so an unanswered question scores 0, against the most they could score.
3. **Including questions:** all the course's graded questions, or the questions, draw slides and other result slides the author chooses. A draw slide stands for the questions it drew, and a result slide for the questions it includes.
4. **The built-in score variables** describe the current slide's result on a result slide, and the tracked result elsewhere:
   - `ResultScore`, `ResultMaxScore`, `ResultPercent`, `ResultPassPercent`;
   - `ResultPassed` (true or false);
   - `ResultTimeLeft`, in seconds.

   Variable names cannot have dots, so these are not called `Results.ScorePoints` or similar.

5. **Tracking.**
   - A new completion rule, "when the learner reaches a result slide", names one graded result slide.
   - Reaching it completes the course and sets success, passed or failed, from its pass mark.
   - The LMS is given the score, as raw, 0 and max.
6. **The timer** is a time limit on a result's questions:
   - it starts when the learner first reaches one of them;
   - when it runs out, the learner is taken to the result slide;
   - it is kept on resume.
7. **Interactions:** every finished question, graded or survey, is reported to the LMS. That means `cmi.interactions` for SCORM, and `answered` statements for xAPI and cmi5.
   - The types: true-false, choice, fill-in, numeric, matching, sequencing, likert and performance.
   - The response and the correct pattern are given as parts, and each driver writes them in its standard's form. Choices, items and steps are named by letter (a, b, c…), which SCORM 1.2 requires.

**Delivery.** One branch, in three steps, each committed when it passes:

- **A.** Result slides, the score, pass mark, built-in variables and tracking. This step adds format 19.
- **B.** Review, retry, print, and the timer.
- **C.** Interactions to the LMS.

## Saved format version 19

`slide.result: Result | null`:

```ts
Result = {
  kind: 'graded' | 'survey',
  include: { kind: 'all' } | { kind: 'chosen', slides: id[] }, // question, draw or result slides
  passPercent: 0…100,                 // graded only
  timer: { seconds: 10…86400 } | null,
  layers: { passed: id | null, failed: id | null },    // overlay layers of this slide
}
```

- A slide is at most one of: a question, a draw, or a result.
- `include` may name only scene slides, and not the result slide itself.
- A cycle of result slides including each other is refused.

**Tracking:** `completion` gains `{ kind: 'result', slide: id }`, which must name a graded result slide.

**Migration 18 → 19:** `result: null` on every slide. Legacy fixture `v18-two-slides`.

## Runtime

**A result's questions** (`resultQuestions`): the included slides, worked out in course order:

- a question slide is itself;
- a draw is its drawn questions;
- a result is its own questions.

For `all`, that is every graded question slide in the course order (survey questions for a survey result). Each question counts once.

**Scoring a graded result:**

- `score` is the sum of the questions' saved `s`, which is 0 when unanswered;
- `max` is the sum of `bestScore`;
- `percent` is `round(100 × score / max)`, or 0 when `max` is 0;
- `passed` is `percent ≥ passPercent`.

**A survey result** counts what was answered, `answered` out of `total`.

**On entering a result slide:**

- its result is worked out and kept in the session (`SessionState.res[slideId]`);
- the Passed or Failed layer is shown;
- if it is the tracked result, tracking gets `success` and the score, and the course completes.

**Actions:**

- **`reviewQuiz`** (P7.5): on a result slide, it reviews that result's questions only. Review starts at the first of them, and Next and Previous move among them; leaving review is P7.7's `exitReview`, which goes back to the result slide.
- **`retryQuiz`:**
  - clears the result's questions' records, and what is saved of their slides;
  - draws its draws again;
  - starts the timer again;
  - takes the learner to the first question.
- **`printResults`:** the player opens a printable summary of the result in a new window: the course, the result, and each question's result.

**The timer:**

- `SessionState.tm[resultSlideId]` holds the course time it started at.
- `ResultTimeLeft` counts down.
- At 0, the learner is taken to the result slide.
- The player shows the time left in its bar while the timer runs.

## Editor

- **Insert → Question → Result Slide** adds a graded result after the current slide. A survey result is a choice in its form.
- **The Result form:**
  - kind;
  - which questions: all, or a checklist of the question, draw and result slides;
  - pass mark;
  - timer, on or off, with its minutes;
  - its Passed and Failed layers' words.
- **The Tracking dialog** offers "When the learner reaches a result slide", with a picker of the graded result slides.

## Done when

- **Model:**
  - results validate: kind, include, no cycles, no self-inclusion, and one role per slide;
  - tracking names a graded result;
  - migration 18 → 19 and the fixture;
  - the property test adds and removes result slides.
- **Engine:**
  - a result's questions for all and for chosen slides, with draws and other results, each question once;
  - score, max, percent and pass;
  - a survey result's count;
  - the Passed and Failed layers;
  - the built-in variables;
  - the tracked result completing the course with success and score;
  - review of the result's questions, and exitReview;
  - retry, which clears, redraws and goes to the first question;
  - the timer running out and resuming;
  - the session and suspend round trip (`res`, `tm`).
- **LMS:**
  - an interaction per finished question for each kind's type, with response and correct pattern, in SCORM 1.2, SCORM 2004 and xAPI forms;
  - tested against the in-repo mock LMS and LRS;
  - the score reported.
- **Player browser:** answer two questions, reach the result slide, and see the score; Retry, then Review.
- **e2e:**
  - author two questions and a result slide (pass mark, timer);
  - set tracking to the result;
  - publish as SCORM 2004;
  - in the mock LMS, the interactions, the score and passed are recorded.

## Not in this package

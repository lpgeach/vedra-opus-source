# P10.3 Translation

**Plan:** "Export all text (slides, states, layers, notes, player labels, quiz content) to XLIFF and to a two-column document; re-import; right-to-left support; per-language player label sets."

A course is translated by sending its words out, to a translator or a tool, and bringing them back. The author keeps one project per language: translating replaces the words of the open project, as one undo step, and the author saves it under a new name. There is no saved-format change. The player's words are already kept by language (P8.3, `labels.words`).

This package is built in three parts, each on its own branch and merged on its own. The plan's box is ticked after part C.

## The translation units (all parts)

`translationUnits(project)` in `packages/model/src/translation.ts` lists every piece of text a learner can meet. Each unit has:

- `id`: a stable path, such as `object/<id>/text/2` (the third paragraph) or `slide/<id>/title`;
- `source`: the words, with inline formatting as numbered tags;
- `note`: where it is, for the translator ("Slide 3 · Text Box 2").

**What is included:**

- the course title, scene titles and slide titles;
- slide notes;
- layer names, which the course announces when a layer shows (P10.1);
- every object's rich text, and each state's own text;
- table cells;
- alt text;
- a field's placeholder;
- a dropdown's options;
- a marker's title and body, and a 360° image's spot names, titles and bodies;
- a web object's title;
- captions;
- the player's menu entry titles;
- resources' titles;
- glossary terms and definitions;
- custom tabs' labels;
- every player word (`LABEL_KEYS`), as the course shows it now.

Questions' words are objects (prompts, choices, feedback), so they are included as objects.

**What is left out:** object names (the author's own), variable names, `%Name%` references (kept in the text as they are), file names and addresses.

**Rich text** is one unit per paragraph or list item, so a translator never sees the document's structure.

- Inline formatting is kept as numbered tags round the words it covers: each different set of marks (bold, a colour, a link) gets a number.
- A hard line break is a tag of its own.
- On the way back, the tags put the same marks on the translated words.
- The paragraph's own settings (alignment, spacing) are not the translator's: they stay as they were.

`applyTranslation(project, translated)` puts translated units back, as the `project.translate` command (one undo step).

- A unit whose source no longer matches the project (the author changed it after exporting) is skipped and counted.
- So is a unit the project no longer has, and a tag the source did not have.
- The player's language becomes the target language, and the translated player words are saved for it.

The result says how many units were translated, skipped as changed, missing, or left untranslated.

## Part A: the units and XLIFF (`wp/p10.3a-xliff`)

- **XLIFF 1.2,** which translation tools read most widely: one `<file>` with `source-language` and `target-language`, and one `<trans-unit>` per unit, with its `<source>`, an empty or filled `<target>`, and its `<note>`. Formatting tags are `<g id="n">…</g>`, and a line break is `<x id="br"/>`.
- **Reading** is tolerant: entities, CDATA, and targets with or without tags. Anything that is not a well-formed XLIFF 1.2 file is refused with a reason.
- **In the editor:** File → Translation…, or Design → Translation… beside Player…, opens a dialog:
  - the source language (the course's) and the target language (a language tag);
  - **Export XLIFF…** saves the file;
  - **Import translation…** opens one and shows the result.
- **IPC:** `project.saveTranslation` and `project.openTranslation`, as the captions calls do (P6.4). The renderer makes and reads the text; main shows the dialogs and writes and reads the file.

**Done when:**

- every kind of unit is extracted and applied back, by model tests;
- export then import of an untranslated file changes nothing (a round trip, also over every fixture);
- changed, missing and unknown units are skipped and counted;
- undo restores the source;
- the e2e exports, edits the file's targets, imports, and sees the translated words on the slide and in the published course's player.

## Part B: the two-column document (`wp/p10.3b-document`)

A Word document (`.docx`), for translators who do not use XLIFF tools:

- a table with three columns: the unit's id (small and grey), the source, and an empty translation column;
- the source language and target language at the top.

It is written and read in main with `yazl` and `yauzl`, which the app already uses for projects. No new dependency is needed.

- Formatting tags are written as `[1]…[/1]` and `[br]`.
- **Reading** takes each table row's id cell and translation cell, joining a cell's runs, so a document Word has saved again still reads.

**Done when:** a document round trip, and a document in the shape Word saves (split runs, proofing marks, revision ids, tracked insertions and deletions, more namespaces), read back, both by tests; the e2e exports and imports a filled one.

**As built (session 83):** no copy of Word was available, so the Word-shaped document is made by hand in the test, from what Word writes, and says so. Saving one in Word and importing it is for Luke. Import takes XLIFF or a document from the same button.

## Part C: right to left (`wp/p10.3c-rtl`)

- **Right-to-left languages:** a course whose language is Arabic, Hebrew, Persian, Urdu and the like (`isRightToLeft(tag)`).
  - The player frame is `dir="rtl"`: the controls, the menu side, the tabs and the text view run right to left.
  - The slide's layout is not mirrored. Where objects are placed is the author's.
- **Text direction:** every paragraph in a course and in the editor is drawn with `dir="auto"`, so Arabic words in an English course, and English words in an Arabic one, each run their own way.
- **Per-language player words:** the Player dialog's Words section already edits the words of the course's language. It gains a language chooser, to see and edit the words kept for each language (from an import, or typed in) without changing the course's language.

**Done when:** render and player tests for `dir`; a browser test of an Arabic course's frame; the Player dialog's per-language words, saved and reopened.

# P7.4 Freeform questions

**Work package:** P7.4, needs P7.3 (done, merged in PR #56).

**Plan line:** convert any slide into a question: pick one, pick many, drag and drop (with drop targets, snapping, return-to-start options, and the three drag states), text entry, hotspot, shortcut key.

**What a freeform question is.** P7.2 and P7.3 build a question slide from the factory's own parts: choice objects, tiles and so on. A freeform question is the other way round:

- the author designs an ordinary slide, with any pictures, shapes, buttons and text;
- they convert it into a question;
- they say in Form View which of the slide's objects play which part.

Freeform questions are graded: they have a right answer, attempts, a score by question, right/wrong feedback and right/wrong branches, like the P7.2 kinds.

**Delivery.** One branch, in three steps, each committed when it passes:

- **A.** Converting a slide; pick one, pick many, text entry and shortcut key. This step adds format 16.
- **B.** Drag and drop, with its drop options and the three drag states.
- **C.** Hotspot.

## Saved format version 16

Each freeform kind is a new member of the `Question` union and has the graded kinds' shared fields: `prompt`, `submit`, `attempts`, `branch`, `required`, `scoring` by question, and `feedback` by question or none.

- **`prompt` and `submit` may be null.** The author chooses them from the slide's objects, or has none.
- **Converting** adds a Submit button with its `submitInteraction` trigger, except for shortcut key, which needs none.

| Kind              | Its parts                                                                                                                     | Correct when                                                                  |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `freePickOne`     | `choices: { id, object, correct }[]`: any objects on the stage, sharing one `buttonSet`                                       | the one correct object is selected                                            |
| `freePickMany`    | `choices: { id, object, correct }[]`: any objects on the stage, no set                                                        | exactly the correct objects are selected                                      |
| `freeText`        | `entry` (a text entry), `answers: string[]`, `caseSensitive`                                                                  | as fill in the blank                                                          |
| `freeKey`         | `key: { key, ctrl, alt, shift, meta }`                                                                                        | the learner presses that key with exactly those modifiers                     |
| `freeDrag` (B)    | `items: { id, object, target }[]` (`target`: the object it belongs on, or null), `targets: string[]`, `snap`, `returnToStart` | every item with a target is on it, and every item without one is on no target |
| `freeHotspot` (C) | `spots: { id, object, correct }[]`: any objects on the stage                                                                  | the learner's mark is inside a correct spot                                   |

- **"Any objects on the stage"** means any object type except audio and zoom regions, which the learner cannot see or click.
  - `QuestionObject.type` becomes either a type or `'onStage'`.
  - Validation checks that a part is an object on the slide's base layer, used once.
- **Pick choices** are selected and unselected by the engine's ordinary rule (P4.1): an object with a Selected state is selected on a click, exclusively within a button set.
  - Choosing an object as a choice in Form View gives it a Selected state if it has none.
  - For pick one, it also joins the question's button set.
- **Shortcut key.** `key` is a key's name as browsers give it (`KeyboardEvent.key`), for example `s`, `Enter` or `F2`. A single character is compared without case.

**Migration 15 → 16:** nothing changes. Legacy fixture `v15-two-slides`.

## Runtime

**Pick one, pick many and text entry** answer and submit as their P7.2 counterparts do.

**Shortcut key:**

- `engine.key(key, modifiers)` now takes the modifiers held, and says whether the key press answered a question.
- On an unfinished shortcut-key slide, each key press is an answer and is marked at once, with the usual attempts, feedback and branching. These presses do not count:
  - a modifier alone;
  - Tab, so keyboard users can still move around;
  - a key pressed while typing in a field (as before).
- A press that answered the question does nothing else: no key-press triggers, and no slide change.
- **Limits.** The player stops the browser's own action for an answered press, such as saving the page on Ctrl+S. It cannot stop the presses browsers keep for themselves, such as Ctrl+W, Ctrl+T or Ctrl+N; the brief notes this rather than working around it.

**Drag and drop (step B):**

- Any item can be carried (`ObjectView.draggable`, as in P7.2).
- `engine.carry(objectId, x, y)` tells the engine where a carried item's middle is; `engine.carry(null)` ends it. The target under that point is drawn in its **Drag Over** state, if it has one.
- **Dropping on a target** (the point inside its frame; the last target in `targets` that contains it):
  - with `snap`, the item's middle moves to the target's middle;
  - without, it stays where it was let go.
- **Dropping elsewhere:**
  - with `returnToStart`, the item goes home;
  - without, it stays where it was let go.
- A target holds any number of items, unless the question keeps one on each (`onePerTarget`, B11: `docs/briefs/B11-drag-and-retry-options.md`).
- **Drop states.** An item on a target is drawn in its **Drop Correct** state if that is the target it belongs on, otherwise in **Drop Incorrect**. Each state is used only if the item has it.
  - These states come from where the items are, not from marks, so they are right again after revisit and resume.
  - Their order among the states: disabled and hidden, then down, hover, drag over, drop correct or incorrect, then selected or visited, then the state it was changed to.
- **Saved answer.** `SavedQuestion.v[i]` is item _i_'s place: `''` (home), or `target|x|y`, with `target` possibly empty and `x`, `y` the item's middle in stage units. The suspend codec carries `v` already.
- **Answered** when at least one item has been moved.

**Hotspot (step C):**

- The whole slide is the picture.
- A click anywhere on the stage places the mark (`engine.mark(x, y)`); the spot under it is the first listed spot whose frame contains the point.
- Spots are the author's own objects and stay visible; to make a hidden region, the author uses a transparent shape.

## Editor

**Insert → Question gains "Convert This Slide".** Its menu items are Pick One, Pick Many, Drag and Drop, Text Entry, Hotspot and Shortcut Key.

- It acts on the current slide when that slide is not a question yet.
- As one undo step, it gives the slide the question, adds a Submit button with its trigger (not for shortcut key), and opens Form View.

**Form View for a freeform kind:**

- **Type:** the kind's name; pick one and pick many can be switched to each other.
- **Question:** a select of the slide's text objects, or "None". The words are edited on the slide.
- **Submit button:** a select of the slide's buttons, or "None".
- **Answers**, by kind:
  - **pick one / pick many:** every object on the stage is listed by name, with "Choice" and "Correct" checkboxes;
  - **text entry:** a select of the slide's text entries (with "Add a text entry"), the acceptable answers, and case-sensitive;
  - **shortcut key:**
    - a field that records the next key pressed in it, with its modifiers;
    - the key is shown as, for example, `Ctrl+Shift+S`;
  - **drag and drop (B):**
    - every object listed with a role (none, item, target), and for an item the target it belongs on (or nowhere);
    - "Snap to the target's middle" and "Return to start when dropped elsewhere";
    - a note that the items' and targets' drag states are set in the States panel;
  - **hotspot (C):** every object listed with "Spot" and "Correct" checkboxes.
- **Score, Attempts, Feedback and Then:** as for the graded kinds.
- **"Stop Being a Question":** takes the question away and leaves the objects (undoable).

## Done when (step A)

- **Model:**
  - the freeform kinds validate; any on-stage object is accepted as a part, and audio and zoom regions are refused;
  - migration 15 → 16 and the fixture;
  - the property test converts slides into each step-A kind and deletes parts.
- **Engine:**
  - pick one and pick many by selection, with button-set exclusivity, right, wrong, and attempts;
  - text entry marked as fill in the blank;
  - shortcut key:
    - right and wrong presses, attempts;
    - modifiers must match;
    - Tab and modifier-only presses ignored;
    - an answered press runs no key-press trigger and does not change slide;
  - locked after finishing, and kept on revisit and resume.
- **Player browser (Chromium and Firefox):**
  - pictures clicked as pick-many choices and submitted;
  - a shortcut key answered with Ctrl held, after a wrong try.
- **e2e:**
  - draw shapes on a slide;
  - convert it to Pick One;
  - choose the choices and the right one in Form View;
  - convert another slide to Shortcut Key and record the key;
  - save and reopen;
  - publish and answer both.

## Done when (step B)

- **Model:** `freeDrag` validates its items, targets and the target each belongs on (one of `targets`, or null).
- **Engine:**
  - snap and free placement, return to start or stay;
  - Drag Over on the target under a carried item, and off again when it leaves or is dropped;
  - Drop Correct and Drop Incorrect from where items are;
  - right only when every item is right (decoys on no target);
  - placements and states survive revisit, resume and the codec.
- **Player browser:**
  - an item carried over a target shows its Drag Over state;
  - dropped, it snaps and shows its drop state;
  - with return-to-start off, an item stays where it was let go.
- **e2e:** convert a slide to Drag and Drop, choose items and targets, save and reopen, publish and answer.

## Done when (step C)

- **Model:** `freeHotspot` validates its spots.
- **Engine:** a mark anywhere on the slide; the spot under it; right and wrong; kept on revisit and resume.
- **Player browser and e2e:** convert a slide with a picture to Hotspot, tick the right spot, publish, and mark it right after a wrong try.

## Not in this package

- Feedback layers (P7.5).
- Freeform survey questions: these freeform kinds are graded only.
- "Allow only one item per target" and delaying drop states until Submit (later, if wanted).

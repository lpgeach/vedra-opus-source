# P9.6 Web objects

**Work package:** P9.6. It needs P9.5 (PR #74).

**Plan line:** web objects (URL or local folder embedded in a sandboxed iframe; in-slide or new window).

**What it is:** a web page on a slide, either from the web (a URL) or from a folder of the author's own (an HTML5 game, a simulation, a page they built). It shows in the slide, or as a button that opens it in a new window.

**My design choices** (Luke asked to go through all of Phase 9), listed for him to change:

1. **Nothing leaves the machine from Vedra Opus itself.** AGENTS.md says to ask before anything that sends data off the machine, so:
   - **a URL is never loaded by the editor or by Preview.** Both show a placeholder that names the address. Preview's placeholder has an "Open in browser" button, so the author chooses to visit it (as "open web page" already works);
   - **the published course loads it in the learner's browser.** That is the course doing what its author asked, as with "open web page" (P4) and an LRS (P5.4).
2. **A folder is copied into the project:**
   - every file under it, keeping its paths, up to 2,000 files and 200 MB;
   - it needs an `index.html` at its top, or the author picks the page to start at;
   - it runs in Preview, from the project's copy, and in the published course;
   - the editor shows a placeholder, so nothing runs while editing.
3. **Always sandboxed:**
   - the frame is `sandbox="allow-scripts allow-forms allow-popups"`, with no same origin, so the page cannot reach the course, its variables or the LMS;
   - a URL must be `https://` (or `http://`);
   - a folder's files may be HTML and script, because they run only inside that sandbox, never as the course.
4. **"In the slide" or "In a new window":**
   - **in the slide:** the frame fills the object's box;
   - **in a new window:** the slide shows a button labelled with the object's title, and clicking it opens the page in a new tab (`noopener`).
5. **Folder files are kept as assets of kind `file`,** listed by path in the object. They are not shown in the Media panel (they would bury the author's pictures). They are published under `content/web/<object id>/`, keeping their paths, and not again under `content/assets/`.

## Saved format version 30

```ts
WebObject { …objectBase, type: 'web', props: {
  source: { kind: 'url', url: string }
        | { kind: 'folder', files: Record<path, AssetHash>, entry: path },
  display: 'inline' | 'window',
  title: string,     // the window button's words and the frame's accessible name
} }
```

- **Validation:**
  - a URL is http or https;
  - a folder's paths are relative, with `/` between parts, and no `..`, leading `/` or `\`;
  - its entry is one of its files;
  - every file is an asset of the project.
- **Migration 29 → 30:** nothing to change.
- **Legacy fixture:** `v29-two-slides`.

## Runtime

- **Render:**
  - **in a course** (`liveMedia`), inline: an `<iframe>` with the sandbox, `src` from the URL or from `context.webUrl(objectId, path)`;
  - **in a course,** a window object: a button;
  - **elsewhere:** a placeholder naming the URL or the folder.
- **Publish:** the folder's files go to `content/web/<id>/<path>`, and SCORM manifests list them.
- **Preview:** serves the same paths; a URL shows the placeholder with "Open in browser" (`shell.openExternal`, only http and https).
- **Player:** the window button opens the page in a new tab.

## Editor

- **Insert → Web Object**, a menu:
  - **From a web address…:** inserts one at `https://example.com`, and the Format panel takes the real address (Electron has no `prompt`);
  - **From a folder…:** the folder dialog, through a new IPC call `project:importWebFolder`.
- **The Format panel:** the title, in the slide or in a new window, and the URL (for a URL source) or the folder's entry page (for a folder).

## Done when

- **Model:**
  - validation (URL schemes, paths, entry, assets);
  - migration and fixture;
  - the property test adds a web object.
- **Main:**
  - `importWebFolder` copies a folder's files with their paths;
  - it refuses a folder over the limits or with no page to start;
  - paths are safe.
- **Render:** each display and source, in a course and elsewhere; the sandbox attribute.
- **Publish:** folder files at `content/web/<id>/`, listed in a SCORM manifest, and not also under assets.
- **Player browser (Chromium and Firefox):**
  - a folder page runs inline in its sandbox (its script runs; it cannot read the course's window);
  - a window object's button opens the page;
  - a URL frame gets its `src` and sandbox.
- **e2e:**
  - insert a web object from a folder (an `index.html` with a script) and one from a URL shown in a new window;
  - save and reopen;
  - publish, and see the folder page run and the button open.

## Not in this package

- Talking between the page and the course (a script bridge).
- Fitting a page to its box automatically.

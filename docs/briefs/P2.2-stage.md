# Brief: P2.2 — Stage and direct manipulation

> **Status: done (2026-11-15).** All three steps are built and tested on `wp/p2.2-stage`. See "Remaining work" at the end for what was decided while building them, and `logs/2026-11-15-session-9.md` for the handover.

Plan entry: `docs/PLAN.md` section 8, P2.2. Depends on P2.1 and P2.3 (both done).

## Goal

The author can put objects on a slide and work with them directly: select, move, resize, rotate, line them up, group them, copy them.

## Built in three steps, on one branch

The package is large, so it is built and committed in steps. Its box is ticked only when all three are done.

1. **Stage basics.** The slide drawn with `@vedraopus/render`; zoom and pan; click, shift-click and marquee selection; move; resize from eight handles; rotate; arrow-key nudge; delete; inserting shapes, text boxes, buttons and pictures.
2. **Precision and arranging.** Snapping and smart guides; rulers, grid, draggable guides; align, distribute, z-order; group and ungroup; lock.
3. **Clipboard and menus.** Cut, copy, paste, duplicate (across slides and across app instances through the system clipboard); context menu.

## Where it goes

```
apps/desktop/src/renderer/stage/
  geometry.ts      pure maths: rotation, hit testing, bounds, move/resize/rotate, snapping, align. Unit tested.
  RenderTree.tsx   draws a RenderNode with React
  Stage.tsx        viewport, zoom, pan, pointer and keyboard handling
  Selection.tsx    selection outline and handles
  actions.ts       what the ribbon, menu and keyboard call: insert, delete, nudge, align, …
```

## Decisions

- **Geometry is pure and separate.** `geometry.ts` knows nothing of React, the DOM or the store. Pointer handlers turn events into stage coordinates and ask it what the new frames are.
- **Every change is a command.** A drag opens a history gesture, sends `object.update` on each move, and commits on release, so a drag is one undo step. Escape cancels the gesture and restores the frames. Autosave waits until the gesture ends.
- **Only the base layer is edited** for now. Choosing a layer to edit arrives with slide layers (P4.2).
- **Selection** is a list of top-level object ids on the current slide, kept in the editor store, not in the project. Clicking an object inside a group selects the group. Ids that no longer exist (after undo, say) are dropped when read.
- **Marquee** selects every object whose bounding box the rectangle touches. Shift adds to the selection.
- **Handles and outlines are drawn in screen pixels** in an overlay above the scaled stage, so they stay the same size at any zoom.
- **Resizing** keeps the opposite handle (or, with Alt, the centre) fixed in stage space, including for rotated objects. Shift keeps proportions; corner handles of pictures keep proportions by default (Shift releases). Minimum size 1 stage unit; lines may have zero height.
- **Resizing several objects** scales them about the selection's box. If any of them is rotated, proportions are always kept, because a rotated box cannot be stretched along the stage axes and stay a box.
- **Rotating** turns about the selection's centre. Shift snaps to 15° steps. Rotating several objects (or a group) moves each about the common centre and turns each by the same amount.
- **Groups** hold children with stage-unit frames. Moving, resizing or rotating a group transforms its children; the group's own frame is then recomputed as the box around them.
- **Nudge**: arrow keys move 1 stage unit, 10 with Shift.
- **Zoom**: Fit (default), fixed percentages, Ctrl+wheel about the pointer, Ctrl+0 for Fit, Ctrl+plus / minus. Range 10%–800%. **Pan**: scroll, middle-button drag, or Space+drag.
- **Inserting** places the new object in the centre of the stage and selects it. Pictures are inserted at their natural size, scaled down if larger than 80% of the stage.
- **Snapping** (step 2) happens in stage units against other objects' edges and centres, the stage edges and centre, and guides, within 6 screen pixels. Ctrl suspends it (see "Remaining work").
- **Clipboard** (step 3) carries objects as JSON under an Vedra Opus-specific marker in the system clipboard, read and written through IPC. Pasted objects get new ids. Pictures paste only if the receiving project has the same media; otherwise the author is told.

### Step 2

- **Group / Ungroup.** `object.group` and `object.ungroup` exist in the model. Add `stage.group()` and `stage.ungroup()` to `actions.ts`: group needs two or more selected top-level objects, builds the container with `createGroupObject([])`, then selects the new group. Ungroup applies to every selected group and selects the freed children. Home → Arrange buttons, and Ctrl+G / Ctrl+Shift+G in the stage's key handler.
- **Lock.** `object.update` with `{ locked }`. In `Stage.tsx`, `objectAt` and the marquee skip locked objects, exactly as they already skip `hiddenInEditor`. Because a locked object cannot be clicked, offer **Unlock All** (Home → Arrange) until the timeline panel (P3.3) gives each object a lock toggle.
- **Z-order.** `object.reorder` takes the index the object should end up at. For several selected objects keep their relative order: process them top-first when bringing forward and bottom-first when sending back. Shortcuts: Ctrl+] forward, Ctrl+[ backward, with Shift for front and back.
- **Align and distribute.** Pure functions in `geometry.ts` returning a move for each object, applied through `transformObjects` and `stage.applyFrames` as one undo step. Align works on each object's upright bounds (`boundsOf`), not its raw frame, so rotated objects line up by what is seen. One object aligns to the stage; several align to the box around them. Distribute needs three or more and evens out the gaps between bounds, leaving the outer two where they are.
- **Snapping.** A pure function: given the moving box, candidate lines (other objects' bounds — left, centre, right, top, middle, bottom — the stage's edges and centre, guides, and grid lines if the grid is on) and a threshold in stage units (6 screen pixels ÷ zoom), return the adjusted move and the lines snapped to. Draw those lines in `Selection.tsx`. Apply in the `move` case of `onPointerMove`, and to the dragged edges in `resize` when the box is not rotated. **Ctrl (Cmd on macOS) held suspends snapping.** (An earlier line in this brief says Alt; Alt is already "resize about the centre", so use Ctrl.)
- **Rulers.** Strips along the top and left of the stage area, outside the scrolling viewport, redrawn on scroll and zoom, with tick spacing chosen so labels never crowd.
- **Grid.** Lines every N stage units drawn over the slide and under the selection overlay. Default 20.
- **Guides.** Drag from a ruler onto the stage to make one; drag an existing one to move it; drag it back onto the ruler to delete it.
- **Where rulers, grid, snap and guides are stored: decided.** They live in application settings (`shared/settings.ts`, a `view` section the lenient parser tolerates in old files), so the saved project format is unchanged and guides are shared across projects. Luke agreed on 2026-11-15.
- **View tab.** Toggles for Rulers, Grid, Guides and Snap.

### Step 3

- **Clipboard.** Two new IPC calls (`clipboard:write`, `clipboard:read`) using Electron's `clipboard` module in main, following "Adding an IPC call" in `docs/development.md`. The payload is JSON text: `{ "vedraopus": 1, "objects": [...] }`. Read validates with `sceneObjectSchema` and ignores anything else on the clipboard. The sandbox test in `e2e/shell.spec.ts` lists the bridge's keys and must be updated on purpose.
- **Paste.** Give every pasted object, and every child of a pasted group, a new id. Offset by 16 units if pasting onto the slide it was copied from, so the copy is visible. Drop references that cannot hold on the new slide. If a pasted picture's file is not in the receiving project's media, do not paste that object and tell the author (`editor.showError`).
- **Duplicate** (Ctrl+D) is copy and paste without touching the clipboard.
- **Menu.** Edit → Cut / Copy / Paste currently use the built-in roles, which only act on text. Replace them with menu commands the way Undo was (`menu.ts`, the `event:menuCommand` union in `shared/ipc.ts`, the switch in `App.tsx`), keeping the browser's own behaviour when a text field has focus.
- **Context menu.** Right-click on the stage: select what is under the pointer if it is not already selected, then offer Cut, Copy, Paste, Duplicate, Delete, the z-order commands, Group / Ungroup and Lock. Build it in the renderer (a positioned list, like the shape gallery in `Ribbon.tsx`) so it can be tested; do not use a native menu.

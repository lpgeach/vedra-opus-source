# P10.1 Published-output accessibility to WCAG 2.2 AA

**Work package:** P10.1. It needs Phase 9 and its follow-ups (PRs #81 and #82).

**Plan line:** semantic roles for every object type, alt text, a focus-order editor, visible focus, full keyboard operation including a keyboard alternative for drag-and-drop, skip navigation, live-region announcements for layer and feedback changes, reduced-motion support, learner-adjustable text (accessible text mode), contrast checks.

**Done when (the plan):** axe-core runs clean on every fixture in CI, and a manual screen-reader pass (NVDA, VoiceOver) is logged. The screen-reader pass needs a person with NVDA and VoiceOver, so it is **for Luke**. I can't run it. The log will list what to try.

The package is large, so it is done in **three parts**, each on its own branch and pull request. The plan's box is ticked after the third.

## Part A: names, roles, focus and announcements (`wp/p10.1a-roles-focus`)

1. **Every object type gets a role and a name in a course,** or is hidden from screen readers when the author marks it decorative ("visible to assistive technology" off). Today only graphics and tables honour that setting.
   - **text:** its words, as text; a decorative text box is hidden.
   - **shape:** with words, read as text; without, a decorative shape is hidden, and a shape with alt text is an image named by it.
   - **image:** an image named by its alt text, or hidden when decorative.
   - **button, hotspot, marker:** buttons named by their words or alt text (P9.1 already does markers and hotspots).
   - **audio, video:** their controls named by the object's name.
   - **choice, field, dropdown, slider, dial:** already named (P7, P9); checked.
   - **web object:** its frame titled.
   - **graphic, table, 360° image:** already done (P9.8 to P9.10); checked.
   - **zoom region:** never read.
   - **group:** a group with alt text is a named group; otherwise it is transparent.
2. **Visible focus:** a clear outline, 3 px in the course's focus colour, on every focusable object, the player's controls and the slide. It meets 3 : 1 against the colours around it (WCAG 2.4.7, 2.4.11 and 1.4.11).
3. **Skip navigation:** the first Tab stop in a course is "Skip to slide", which moves focus to the slide's first object (WCAG 2.4.1). Its words are a label key.
4. **Live announcements** in a polite live region:
   - a layer's name when it is shown;
   - feedback: "Correct", "Incorrect", "Try again", with the feedback's own words;
   - a lightbox opening;
   - the slide's title on a new slide.

   Each is a label key, so it follows the course's language.

5. **The slide is a region** named by its title. The player's controls are a toolbar.
6. **axe-core on every fixture.** A test publishes each project in `fixtures/projects/`, plus a course using every object type, and runs axe-core (WCAG 2.0, 2.1 and 2.2 A and AA rules) on each slide in Chromium and Firefox. It must find nothing.
   - axe-core (MPL 2.0) is added as a **development dependency for tests only**. It is never shipped in the app or in courses.

## Part B: keyboard operation and the focus order (`wp/p10.1b-keyboard-order`)

1. **Dragging by keyboard** (WCAG 2.1.1 and 2.5.7), for question tiles (P7.2, P7.4) and draggable objects (P9.7):
   - Space or Enter picks up the focused object;
   - for questions and targets, the arrow keys move it from target to target (each announced), and for a free object they move it 10 pixels (Shift: 1);
   - Space or Enter drops it, and Escape puts it back.

   The same engine calls (`carry`, `drop`) run, so triggers and states behave exactly as with a pointer.

2. **A focus-order editor:** the Slide panel's "Tab order" lists the slide's focusable objects, in the order Tab reaches them. It can be "follow the layout" (top to bottom, then left to right; the default) or the author's own order, set by dragging or with up and down buttons.
   - **Saved format:** `slide.properties.focusOrder: string[] | null` (format 35, with the other slide settings, so `slide.setProperties` sets it as one undo step). Migration `null`.
   - **As built (session 79):** the list has up and down buttons ("Move … earlier/later"), not dragging: buttons work by keyboard and screen reader as they are. Objects not in the author's list follow it by layout, so a new button is never left out.
   - **Validation:** only the slide's objects, each once. Removing an object takes it out.
   - **In a course,** the stage's objects are reached in that order. The player moves focus itself on Tab and Shift+Tab within the slide, so the drawing order is unchanged.
3. **Tab order without an author's order** follows the layout, not the drawing (z) order, as now.

## Part C: accessible text mode and contrast (`wp/p10.1c-text-mode`)

1. **Accessible text mode** (the player's accessibility menu): a panel beside the slide (below it when narrow) with the slide's text in reading order. It holds headings, paragraphs, lists, alt texts, table cells, field labels and the current layer's text, in a size the learner chooses (100 to 200 %), and it reflows (WCAG 1.4.4, 1.4.10 and 1.4.12). It updates with layers and states. The setting is remembered with the learner's other player settings.
2. **Contrast checks:**
   - the player's own colours (every built-in look, light and dark) meet 4.5 : 1 for text and 3 : 1 for controls and focus, tested;
   - a custom look that fails is corrected in the course (`textOnAccent` already does this for accent text), and the Player dialog warns about it.
   - Authors' own slide colours are P10.2's checker.

### Part C as designed (session 79)

**Text view.** The accessibility panel (P8.3) gets two settings: "Text view" (a checkbox, off) and "Text size" (100, 125, 150, 175 or 200 %).

- **Where:** the view is an `aside` named "Slide text", beside the viewport, or below it when the player is narrow.
- **What it holds,** in this order:
  - the slide's title, as a heading;
  - each shown layer in turn (base first, then the overlays shown, in the slide's layer order);
  - within a layer, the objects in reading order: the slide's Tab order (`tabOrder`) where the author set one, else by layout;
  - inside a group, its parts by layout.
- **Each object, by kind:**
  - an object's words become paragraphs and lists as the text has them;
  - a picture, or a wordless shape with alt text, gives its alt text, labelled as a picture;
  - a table gives a table, with the header rows as headers;
  - a field gives its label (its alt text, or its name), and the text in it;
  - a choice gives its words;
  - a decorative object, a hidden one, and a hidden layer give nothing.
- **It is a copy for reading.** Nothing in it is pressed; the slide itself stays the place to act. It is redrawn when what it shows changes: layers, states and field text.
- **Reflow:** it wraps at any width, with no sideways scrolling at 320 CSS pixels, and allows the WCAG 1.4.12 spacing.

**Remembering.** The player had no remembered settings. The accessibility panel's settings (caption size, text view, text size) are kept in the browser's `localStorage` under the course's id, and read back at start. That never leaves the learner's machine. When storage is refused (private windows, some LMS frames), the settings last for the visit only.

**Contrast.**

- The player's colours for each scheme move into the model (`PLAYER_SCHEMES` in `player-look.ts`), and a test checks that `player.css` defines the same.
- `accentFor(accent, scheme)` gives the accent as courses show it. The author's accent is kept when it reaches 3 : 1 against the scheme's background, chrome and sheet. Otherwise it is mixed toward the scheme's text colour, step by step, until it does. The text on it is `textOnAccent` of that shade.
- The player sets one shade for the dark scheme and one for the light. The `auto` scheme picks between them in CSS, as it picks its other colours.
- The Player dialog warns when `accentFor` changed the accent for either scheme, and names the shade used.
- **Tests:**
  - every text pair of both schemes reaches 4.5 : 1, and every border and focus colour 3 : 1;
  - `accentFor` reaches 3 : 1, and the text on it 4.5 : 1, for a sweep of accents;
  - a browser test reads the drawn focus ring's colour for a faint accent.

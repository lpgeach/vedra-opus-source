# P5.6 Publish UI

**Work package:** P5.6, needs P5.2 (done; P5.3–P5.5 are done too). The Publish dialog gains every target the publish package can build, the settings each one uses, zip output, and remembers the choices.

## What the author sees

**File → Publish… (F10)** and the ribbon's **Publish** open one dialog. The dialog used to be "Publish to Web"; it is now "Publish". From top to bottom:

| Field                          | Shown for             | Notes                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------ | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Publish to**                 | all                   | Web, SCORM 1.2, SCORM 2004, xAPI, cmi5                                                                                                                                                                                                                                                                                                                                                                            |
| **Edition**                    | SCORM 2004            | 2nd, 3rd, 4th (default). The 3rd shows that its schema files are not included (P5.3).                                                                                                                                                                                                                                                                                                                             |
| **Course title**               | all                   | Starts as the project title.                                                                                                                                                                                                                                                                                                                                                                                      |
| **Identifier**                 | all LMS targets       | Empty means the default, shown as a placeholder. SCORM: the manifest identifier, an XML name (letters, digits, `-`, `_`, `.`, starting with a letter or `_`). xAPI: the activity IRI. cmi5: the course IRI (the unit is the course IRI plus `/au`). Checked as typed, with the reason shown beside the field.                                                                                                     |
| **Version**                    | SCORM 1.2, SCORM 2004 | The manifest's `version`. Default `1.0`.                                                                                                                                                                                                                                                                                                                                                                          |
| **Description**                | Web, xAPI, cmi5       | Web: the page's `<meta name="description">`. xAPI and cmi5: the description in `tincan.xml` / `cmi5.xml`. SCORM has no place for it without metadata files, so it is not shown.                                                                                                                                                                                                                                   |
| **Tell the LMS the course is** | all LMS targets       | The course's reporting pair (P5.1), changed through `project.setTracking`, so it is the same setting as Design → Tracking. It is applied when Publish is pressed, in the same undo step as the publish settings. A note points to Design → Tracking for completion and resume. (A Tracking… button inside this dialog was dropped while building it: the two dialogs would have edited the same setting at once.) |
| **Output**                     | all                   | "Folder" or "Zip file". Choosing an LMS target switches to Zip file, since LMSs take zips; the author can change it back.                                                                                                                                                                                                                                                                                         |
| **Output folder**              | all                   | "Choose folder…", as before.                                                                                                                                                                                                                                                                                                                                                                                      |

**Publish** builds into `<folder>/<course name>/`, or `<folder>/<course name>.zip` with the package files at the zip's root (where LMSs look for `imsmanifest.xml`, `tincan.xml` and `cmi5.xml`). The result line names the folder or zip. "View published course" opens a folder's `index.html`. For a zip, "Show zip file" shows it in the file manager. Warnings from the publish (a suspend-data estimate over the limit) are listed under the result.

## Where the settings live

- **In the project** (format v5), `project.publish`:

  ```ts
  {
    target: 'web' | 'scorm12' | 'scorm2004' | 'xapi' | 'cmi5';
    scorm2004Edition: 2 | 3 | 4;
    title: string; // '' = the project title
    identifier: string; // '' = the default for the target
    version: string; // SCORM manifest version, default '1.0'
    description: string;
    zip: boolean;
  }
  ```

  - Migration 4 → 5 adds the defaults: web, 4th edition, empty strings, version `1.0`, folder output.
  - It is saved when the author presses **Publish**, through a new command `project.setPublishSettings`, but only if something changed. A title equal to the project title is saved as empty, so it follows later renames. The command is undoable like any other edit, and marks the project changed. Cancelling the dialog changes nothing.
  - The settings are part of the course, so they travel with the `.vedraopus` file.

- **On this machine:** the output folder, per project id, in `publish-folders.json` in the app's user-data folder. A path belongs to one computer, and saving it in the project would also put the author's folder names into a file they may share.
  - Main writes it after a successful publish.
  - `publish:lastFolder` reads it.
  - At most 100 projects are remembered, oldest dropped.
  - This is not in `settings.json`, because the renderer saves that file whole and would overwrite what main wrote.

## Code

- **`packages/publish`:**
  - `publishCourse(project, settings, io)` picks the target and passes the settings on. It returns `{ files, warnings }`.
  - `scorm12Manifest` and `scorm2004Manifest` take `identifier` and `version`.
  - `publishXapi`, `publishCmi5` and the web page take `description`.
  - `checkPublishSettings(settings)` returns field-by-field problems: an identifier that is not an XML name or an IRI, an empty version. The dialog uses it to show reasons, and `publishCourse` refuses a setting it rejects.
- **`apps/desktop/src/main/publish.ts`:**
  - `publishToFolder` becomes `publishProject`, with the target and `zip`.
  - Folder output keeps the staging folder and move-into-place, and the refusal to overwrite a folder that is not an earlier publish.
  - Zip output streams entries into a hidden temporary file beside the target with `yazl`, the library `.vedraopus` files already use, then renames it into place. Text files are deflated; images, audio and video are stored as they are. An existing file of the same name is replaced only if it is a zip.
- **IPC:**
  - `publish:web` becomes `publish:run` (`workspaceId`, `projectJson`, `folder`, checked by Zod). The settings come from the project sent, which the dialog has just updated, so they are not sent twice. It returns `{ status: 'done', path, files, warnings, kind: 'folder' | 'zip' }` or `{ status: 'cancelled' }`.
  - `publish:view` takes the result's path and kind.
  - `publish:lastFolder` takes a project id.

## Done when

- **e2e:**
  - Publishing to Web still plays over HTTP and from `file://`; the existing test is updated to the new dialog.
  - Publishing SCORM 1.2 as a zip gives a file whose entries include `imsmanifest.xml` at the root and the course, read back with `yauzl`.
  - Reopening the dialog shows the remembered target, identifier and folder. Saving and reopening the project keeps the settings.
  - An invalid identifier disables Publish and says why.
- **Unit tests (main):** zip output (entries, deflated or stored, replaced only if it is a zip, no temporary file left on failure or cancel); the remembered-folder store (round trip, damaged file, the cap).
- **Unit tests (model):** migration 4 → 5 with a legacy fixture; the command, with validation and undo; the property-test step.
- **Unit tests (publish):** `publishCourse` for each target; `checkPublishSettings`; identifier, version and description reaching the files.

## Not in this package

- Publishing to the network (an LMS upload, a web server), or to video or Word.
- Per-target player settings (player colours, menus; Phase 8).
- AICC (left out by the plan).

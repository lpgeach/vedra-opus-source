# P9.3 Checkboxes and radio buttons

**Work package:** P9.3. It needs P9.2 (PR #71).

**Plan line:** checkboxes and radio buttons as stock stateful objects.

## What is there already

- **The choice object (P7.1):** a round or square mark beside its words, drawn filled in its `selected` state. Questions are built from them.
- **Plan §5's state rules:** `selected` toggles on a click. In a button set, a click always selects and deselects the others. The engine has done this for any object since P4.
- **The player (Phase 7 review):** a question's choices are radios or checkboxes to the keyboard and to screen readers.

## What P9.3 adds

The same objects, on any slide, for an author's own interactions.

**My design choices** (Luke asked to go through all of Phase 9), listed for him to change:

1. **No new object type and no format change.** A checkbox is a choice object with a square mark and no button set. A radio button has a round mark and a button set, which is its group. Saved courses are unchanged; no migration.
2. **Insert → Data Entry** gains Checkbox and Radio Button. Their states are Normal and Selected, as a question's choices have. Triggers, conditions ("Radio 2 is Selected") and the States panel work as for any object.
3. **Radio groups:**
   - A new radio button joins the group of the radio button selected when it is inserted, if there is one. Otherwise it starts a group of its own.
   - The Format panel names the group, and another radio can join it by typing that name.
4. **Starting checked:** the Format panel's "Starts checked" makes Selected the initial state.
5. **In the course, every choice is a control** (like a question's):
   - `role` is checkbox or radio, with `aria-checked`, named by its words (or its alt text);
   - it is in the tab order, and Space or Enter presses it;
   - the arrow keys move between the radio buttons of a group and select the one moved to, as a native radio group does, instead of changing slides.
6. **Choosing words:** a choice's words are edited on the stage, as a text box's are.

## Saved format

Unchanged: version 27.

## Done when

- **Model:** `createCheckboxObject` and `createRadioObject` (a group id given or made).
- **Player browser (Chromium and Firefox):**
  - a checkbox toggles by click and by Space, with `aria-checked`;
  - radio buttons in a group select one at a time, by click and by the arrow keys;
  - arrow keys do not change slides from a radio;
  - a "state becomes selected" trigger runs;
  - choices on a question slide still work as before (the existing suite).
- **e2e:**
  - insert two radio buttons (one group) and a checkbox, set one radio to start checked, and add a trigger on a radio's Selected state;
  - save and reopen;
  - publish, and use them by mouse and keyboard.

## Not in this package

- Binding a checkbox to a true/false variable. Triggers can do it; a later package may add it as data-entry fields have.

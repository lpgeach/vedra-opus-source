# P6.1 Audio

**Work package:** P6.1, the first of Phase 6. Plan line: import (mp3, m4a, wav, ogg); waveform row in the timeline; audio as time master; volume; play/pause/stop media actions and the `media completes` event; record narration from the microphone.

Plan section 5 already gives the clock rule this package implements: "If a layer has audio or video that spans the timeline, that media element is the time master and the view reports its `currentTime` into the engine; otherwise wall-clock deltas advance the playhead." The plan does not say what play, pause and stop do to audio that sits on a timeline. This brief defines that, below, without changing any existing rule.

## Saved format version 6

- **A new object type, `audio`:**

  ```ts
  {
    ...objectBase,              // frame: where its marker sits in the editor
    type: 'audio',
    props: {
      asset: AssetHash,         // an asset of kind 'audio'
      length: number,           // seconds, measured when it was inserted
      volume: number,           // 0–1
      startOn: 'timeline' | 'trigger',
    },
  }
  ```

  `timing` works as for any object: it is on the timeline from `start` for `duration`, which defaults to `length`.

- **New trigger actions:** `playMedia`, `pauseMedia` and `stopMedia`, each `{ object }`.
- **New trigger event:** `mediaCompletes { object }`.
- Validation checks that these name an audio object on the trigger's slide, the same reference rules as other object triggers. Removing the object removes the triggers that use it.
- **Migration 5 → 6** changes nothing: it only adds types. The version still goes up, so an older Vedra Opus refuses a file it cannot draw. Legacy fixture `fixtures/legacy/v5-two-slides`.

## Runtime (engine)

Each audio object on the current slide has a **media state**:

| Mode      | Plays                                   | Its position                       |
| --------- | --------------------------------------- | ---------------------------------- |
| `follow`  | while on stage and its layer is running | the layer's playhead minus `start` |
| `free`    | while its layer is running              | its own, moving on with time       |
| `paused`  | no                                      | where it was paused                |
| `stopped` | no                                      | 0                                  |

- **Start:** `startOn: 'timeline'` starts in `follow`, and `'trigger'` starts in `stopped`.
- **Reset:** entering the slide, or showing its layer, resets every audio object on it to its start mode.
- **`playMedia`:**
  - a `follow` object that is playing is left alone;
  - any other object goes to `free` from its position, or from 0 if it had stopped or finished.
- **`pauseMedia`** goes to `paused`, keeping the position. **`stopMedia`** goes to `stopped`.
- **"Its layer is running"** means the layer is shown and not paused, whether by `pauseTimeline` or by an overlay that pauses the base. Pausing a timeline pauses its media too, and resuming it resumes them.
- **`mediaCompletes`** fires when an object playing in `follow` or `free` reaches `length`. A `follow` object whose time on the timeline ends before `length` stops when it leaves the stage, without completing. Once completed, an object stops; it plays again only by `playMedia` or a reset.
- **Time master** (the plan's rule):
  - On each layer, the playing `follow` object with the earliest start is that layer's master; ties go to document order.
  - The player reports every playing audio element's `currentTime` with `engine.mediaTime(objectId, seconds)`.
  - For the master, the layer's playhead becomes `start + seconds`, forward only, and that layer does not also advance by wall-clock time in that tick. If the audio stalls, for example while buffering, the timeline waits for it, for at most 2 s (added in P6.2; see that brief).
  - For a `free` object, the report sets its position.
  - Layers with no master advance by wall-clock time, as now.
- **`LayerView.media`** lists `{ id, playing, time, volume }` for every audio object on the layer, inside groups too. While building I moved it here from `ObjectView`, so a player never has to walk groups to find sound. A player makes its audio elements match it: play or pause, and seek when the element is more than 0.3 s off.
- **Not saved for resume:** media state. A resumed slide's `follow` audio picks up from the restored playhead. `free` audio starts again in its start mode.

## Drawing

- **Editor:** an audio object draws as a speaker marker at its frame (default 48×48), so the author can select and move it. It draws only when the render context says so (`mediaMarkers: true`); only the editor's stage turns that on.
- **Player and thumbnails:** nothing is drawn.

## Player

- **The audio itself:** one `HTMLAudioElement` per audio object on the current slide (not in the page's tree), with `src` from `assetUrl`. Elements are dropped when the slide changes, and volume comes from the view.
- **Each frame:** report the playing elements' times, `tick`, then bring the elements into line with the view.
- **Browsers that block sound until the learner interacts:** if `play()` is refused, the player pauses the slide's timelines and shows "Play" over the stage. Pressing it resumes and plays. Otherwise narration would be lost silently, or the timeline would wait for audio that never starts.
- **Preview** windows allow sound without a gesture (Electron `autoplayPolicy`).

## Editor

- **Insert → Audio…** imports mp3, m4a, wav or ogg through the existing media import. The Media panel can insert an imported audio asset too.
  - The renderer decodes the file with Web Audio to measure its length and work out a waveform.
  - The new object goes on the current slide's base layer (or the layer being edited) at the timeline's start, with `duration = length`.
- **Waveform row:** an audio object's row in the Timeline draws its waveform in the object's bar.
  - The waveform is 1 point per 10 ms, max and min absolute amplitude, drawn as a filled shape.
  - It is worked out once per asset and kept in memory, not saved. P6.3 may produce waveforms in the media pipeline later.
- **Audio properties** (Format panel, when an audio object is selected): Volume (0–100%) and Start ("With the timeline" or "When a trigger plays it").
- **Triggers:** the wizard offers Play, Pause and Stop media for audio objects on the slide, and the event "Media completes". `describe.ts` gives their sentences ("Play media Narration when …").
- **Record narration** (Insert → Record Audio…):
  - A dialog with Record and Stop, the time recorded and a level meter. Listen, then Insert or Discard.
  - It records with `getUserMedia({ audio: true })` and `MediaRecorder`, in WebM/Opus, the format Chromium records.
  - The recording goes to main through a new IPC call that stores it as an asset (hash, `webm`, `audio/webm`) and returns its metadata. It is then inserted like an imported file.
  - **Permissions:** main grants microphone access only to the app's own window, for audio only. Camera and screen are refused. On macOS it asks the system first (`systemPreferences.askForMediaAccess`), and the packaged app declares `NSMicrophoneUsageDescription`.
  - WebM audio plays in current Chromium, Firefox and Safari. P6.3 will turn recordings into mp3 for older players.

## Done when

- **Engine unit tests:** every row and rule above, including:
  - the start modes;
  - play, pause and stop from each mode;
  - pausing a layer pauses its media;
  - completion once, including the left-the-stage case;
  - master selection, a stalled master holding the timeline, and forward-only reports;
  - resets on slide entry and on showing a layer;
  - `mediaCompletes` triggers.
- **Model:** the new object, actions and event validate; reference checks; trigger clean-up when an audio object is removed; migration 5 → 6 through the frozen fixture; the property test inserts and removes audio objects.
- **Player browser tests** (Chromium and Firefox, with a generated WAV):
  - the timeline follows the audio's `currentTime`;
  - Pause media and Play media from triggers, and Media completes firing a trigger;
  - volume reaches the element;
  - a blocked autoplay shows "Play", and pressing it starts the sound and the timeline.
- **e2e:**
  - insert a WAV: the object is on the timeline with the WAV's length and a drawn waveform;
  - change volume and start mode;
  - add a Play media trigger;
  - save and reopen;
  - publish and play the course with sound;
  - record narration with Chromium's fake microphone (`--use-fake-device-for-media-stream`): the recording is inserted with a non-zero length.
- **Visual test** for the editor's audio marker, and the player drawing nothing.

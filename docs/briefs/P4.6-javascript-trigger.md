# P4.6 JavaScript trigger

**Work package:** P4.6, needs P4.3 (done). **Status:** implemented on branch `wp/p4.6-javascript`. No saved-format change (`executeJavaScript { code }` was already an action).

## Decisions

- **The engine never runs code.** `createEngine(project, { runScript })` takes the runner from its host and calls it at the action's place among the triggers, with a `ScriptApi` bound to the current slide. An engine without a runner (the editor's, used for timeline scrubbing) skips the action, so course code never runs in the editor process.
- **The player is the host.** It runs the code as the body of `new Function('player', code)`, in the course page.
- **The API** (`docs/player-api.md`, stable): `getVar(name)` (built-ins included), `setVar(name, value)` (type-checked; built-ins refused), `object(name)` with `name`, `state`, `visible`, `setState(id)`, `show()`, `hide()`. Script-hidden objects take no input and are saved in the slide's resume snapshot (`SavedSlide.h`).
- **Errors** (thrown or unparseable) become one `warning` event each; the triggers after it still run.
- **Preview** allows `'unsafe-eval'` in its content security policy so scripts can run there; the window still has no bridge and cannot fetch. Published courses have no policy of their own (an LMS may add one).
- **Wizard:** Run JavaScript with a code box (Tab indents) and a reminder of the API; the trigger's sentence shows the first line of code that is not a comment.

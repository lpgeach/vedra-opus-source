# P5.2 SCORM 1.2

**Work package:** P5.2, needs P5.1 and P3.5 (done). **Status:** done (PR #31). Schema files added in session 30. The SCORM Cloud check is outstanding (Luke, later).

## Where the code lives

- **In the course (browser):** `packages/player/src/lms/`: the driver interface the plan names, the SCORM 1.2 driver, API discovery, the suspend-data codec, and `startCourse()`, which connects a course to its LMS and mounts the player. It ships in the player bundle, since it runs in the course page (the player may not import `publish`).
- **At publish time:** `packages/publish/src/scorm12.ts`: `publishScorm12()` writes the web course (same files as P3.5), `imsmanifest.xml` and the four schema files it names, with an `index.html` that starts the course with the SCORM 1.2 driver. The publish UI comes with P5.6; this package is tested at the API level.

## Driver interface (plan section 8, Phase 5)

`init()`, `getBookmark()` / `setBookmark()`, `getSuspendData()` / `setSuspendData()`, `setCompletion()`, `setSuccess()`, `setScore()`, `recordInteraction()`, `commit()`, `terminate()`. Score and interactions come from quizzes (P7); the SCORM 1.2 driver implements them (`cmi.core.score.raw/min/max`, `cmi.interactions.n.*`) but nothing calls them yet.

## SCORM 1.2 run

1. **Find the API:** `window.API`, walking up `parent` (at most 500 frames), then `opener` and its parents. No API: the course plays untracked and says so in the console.
2. `LMSInitialize("")`. Read `cmi.core.entry`, `cmi.suspend_data`, `cmi.core.lesson_location`, `cmi.core.lesson_status`.
3. Decode the suspend data into a `SessionState` and mount the player with it (the course's resume rule from P5.1 applies). A fresh attempt sets `lesson_status` to `incomplete` if the LMS reports `not attempted`.
4. **On each slide change:** `lesson_location` (the slide's number), `suspend_data`, `lesson_status` from `reportStatus`, then `LMSCommit`.
5. **On completion change:** `lesson_status`, `LMSCommit`.
6. **On leaving the page** (`pagehide`, once): `suspend_data`, `session_time` (`HHHH:MM:SS.SS`), `exit` (`suspend` while incomplete, else empty), `LMSCommit`, `LMSFinish`.
7. Every call's error code is checked; failures are reported as warnings, never thrown into the course.

## Suspend data (at most 4,096 characters)

- **Compact form first:** ids become positions in the published course (slide index, object index on its slide, state index on its object, layer index on its slide). The visited list becomes a bitset. Playheads are tenths of a second. A short fingerprint of the course's slide ids is included: if a learner returns to a course republished with different slides, the resume detail is ignored (completion and variables still count, variables being keyed by name).
- **Then compression:** LZW over the JSON text, written in a URL-safe base64 alphabet (characters every LMS stores safely), with a version prefix.
- **Size guard:** if it is too long, drop in this order until it fits: other slides' resume detail, the current slide's resume detail, the visited list, then variables. Completion and the current slide are always kept. What was dropped is reported as a warning.
- **At publish time** a worst case is estimated (every slide visited and resumable, every object in a non-initial state, every variable set): if that exceeds 4,096 the publish result carries a warning.

## Schema files

`imscp_rootv1p1p2.xsd`, `imsmd_rootv1p2p1.xsd`, `adlcp_rootv1p2.xsd` and `ims_xml.xsd` sit at the package root, and the manifest names the first three in `xsi:schemaLocation`. They come from the SCORM 1.2 schema bundle published by Rustici Software (CC BY 3.0); the schemas are ADL's and IMS's. They are kept as strings in `packages/publish/src/scorm12-schemas.ts`, with the source and the original files' SHA-256 hashes in its header, and are unchanged apart from line endings. They belong to the package, not to the SCO, so the resource's file list leaves them out.

# P3.5 Web publish

**Work package:** P3.5, needs P3.2 (done). **Status:** implemented on branch `wp/p3.5-web-publish`.

`packages/publish` writes a web course; the desktop app adds a Publish dialog.

## Output

```
<folder>/<course name>/index.html
                       player/player.js, player/player.css      (the P3.2 bundle)
                       content/data.js                           (window.VEDRAOPUS_COURSE = <project JSON>)
                       content/assets/<sha256>.<ext>
```

It runs from `file://`, from any web server and from inside an LMS, because the data is a script that assigns a global (no `fetch`). `data.js` escapes `<`, U+2028 and U+2029 so nothing in the project can end the script early.

## Decisions

- **`publishWeb(project, options)`** in `@vedraopus/publish` is pure: output goes through `options.write(path, data)`, assets come from `options.readAsset`, progress through `onProgress`, cancellation through `signal`. Asset names from the project file are untrusted; a name that is not a 64-hex hash plus a short alphanumeric extension is refused before anything is written.
- **Safe folders (main, `publish.ts`).** The author chooses a parent folder; the course goes in `<parent>/<slug of the title>`. It is built in a hidden staging folder beside it and moved into place only when complete, so a failure or cancel leaves nothing behind and an earlier publish of the same course is replaced whole. An existing folder of that name that is not an earlier publish (no `content/data.js`) is never touched; the author is told to choose another folder.
- **Not a utility process.** The plan says "worker or utility process". Publishing runs asynchronously in the main process (file writes yield between files, with progress events and cancel), which keeps the UI responsive for course-sized output without a second process to ship. Revisit if large media makes main busy.
- **Player location.** `npm run build` builds the player first and `scripts/copy-player.mjs` copies it to `apps/desktop/out/player`, so the packaged app carries it; in development the app falls back to `packages/player/dist`.
- **UI.** File → Publish to Web… (F10) and a Publish button in the top bar open a dialog: course title (default: project title), Choose folder…, Publish, progress with Cancel, then the result with "View published course" (opens `index.html` in the default browser) and Close.
- IPC: `publish:chooseFolder`, `publish:web`, `publish:cancel`, `publish:view`, event `event:publishProgress`. The bridge test now lists `publish`.

## Tests

- `web.test.ts`: files written, data round trip through a script, escaping, hostile asset names, cancel.
- `publish.test.ts` (main): folder naming, staging and replacement, foreign folder untouched, cancel and failure leave nothing, progress, player lookup.
- `e2e/publish.spec.ts`: opens the `two-slides` fixture, publishes through the dialog, then plays the folder in a headless Chromium over HTTP and from `file://` (timing, Next, Previous, no failed requests); and refuses to overwrite a foreign folder.

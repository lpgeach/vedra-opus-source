# P9.2 Data-entry fields

**Work package:** P9.2. It needs P9.1 (PR #69) and the Vedra Opus rename (PR #70).

**Plan line:** data-entry fields (text and numeric entry bound to variables; `control loses focus` event).

**What is there already:** the text-entry object of P7.2, a field a question reads its answer from (one line, a number, or an essay). It keeps what the learner types on its slide, and nothing else can use it.

**What P9.2 adds:**

- a text entry, on any slide, can be **bound to a variable**: it shows the variable, and what the learner types is written to it;
- a **"control loses focus"** trigger event;
- **Insert → Data Entry**, to place one outside a question.

**My design choices** (Luke asked to go through all of Phase 9), listed for him to change:

1. **When the variable is written:** when the field loses focus.
   - For a one-line field, Enter also writes it, by taking focus away; an essay field (several lines) keeps Enter for new lines.
   - Writing on every key would fire "variable changes" triggers mid-word.
2. **What the field shows:**
   - the variable's value when the slide starts;
   - what the learner is typing, while they type;
   - the variable again after it is written, and whenever a trigger changes the variable while the learner is not typing in the field.
3. **Which variable:**
   - a text field binds to a **text** variable;
   - a numeric field binds to a **number** variable.

   Validation holds to this.

4. **Numbers:**
   - A numeric field may have a least and a greatest value. A number outside them is written as the nearest one allowed.
   - What does not read as a number (`3x`) is not written, and the field goes back to the variable's value.
   - A blank numeric field writes 0. A blank text field writes the empty text.
   - Numbers are read locale-neutrally (`1234.5`), as plan §5 says text shows them.
5. **"Control loses focus":**
   - an event of a text entry or dropdown, raised after its variable (if any) is written, so its triggers see the new value;
   - it fires when focus leaves the field, by Tab, a click elsewhere or Enter;
   - it fires whether or not the value changed.
6. **Questions keep working as before.** A question's own text entries can be bound too; the question still reads what was typed.
7. **Where a field may be:** on any layer of the slide. P7.2's fields were base-layer only, because questions live there.

## Saved format version 27

```ts
TextEntryObject.props += {
  variable: id | null, // a text variable, or a number variable for a numeric field
  min: number | null, // numeric fields only
  max: number | null,
};
TriggerEvent += { type: 'controlLosesFocus', object: id }; // a text entry or dropdown
```

- **Validation:**
  - the variable exists and is of the field's type;
  - `min`/`max` only on numeric fields, with `min ≤ max`;
  - the event's object is a text entry or dropdown of the slide.
- **Migration 26 → 27:** `variable: null, min: null, max: null` on every text entry.
- **Legacy fixture:** `v26-two-slides`.
- **Deleting a variable:** a bound field is unbound (as the variables panel already does for variable references).

## Runtime

- **Engine:**
  - `engine.blur(objectId)`: write a bound field's variable as rule 4 says, forget the typed text, and raise `controlLosesFocus`;
  - the view's `value` for a bound field follows rule 2;
  - `takeInput` takes fields on any layer.
- **Player:**
  - `focusout` on a field calls `engine.blur`;
  - Enter in a one-line field blurs it.

## Editor

- **Insert → Data Entry:** a menu of Text Entry and Numeric Entry.
- **The Format panel for a text entry:**
  - placeholder;
  - the variable it is bound to (the variables of its type, or none);
  - for a numeric field, least and greatest.
- **The trigger wizard:** the event "a control loses focus", with the slide's text entries and dropdowns.

## Done when

- **Model:**
  - binding and number limits validate;
  - migration 26 → 27 and the fixture;
  - deleting a variable unbinds;
  - the property test binds a field.
- **Engine:**
  - a bound field shows its variable;
  - blur writes it (text, number, clamped, rejected, blank) and raises the event after the write;
  - a trigger's change shows when not typing;
  - fields on overlay layers.
- **Player browser (Chromium and Firefox):**
  - typing and Tab writes the variable and runs a "loses focus" trigger;
  - Enter does the same in a one-line field;
  - `%Variable%` text on the slide updates;
  - a numeric field clamps and rejects.
- **e2e:**
  - insert a text entry and a numeric entry, bind them, and add a "loses focus" trigger;
  - save and reopen;
  - publish, and use them.

## Not in this package

- Formatting numbers for show (decimal places, units).
- Input masks and validation messages.

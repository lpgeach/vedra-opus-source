# P6.3 Media pipeline

**Work package:** P6.3. The plan asked to confirm with Luke before bundling ffmpeg. He confirmed ("go for it", 2026-11-17) and chose:

- **Formats: WebM video (VP9 picture, Opus sound) and MP3 audio,** instead of the plan's H.264/AAC mp4. An LGPL ffmpeg has no x264, which is GPL. Its only H.264 encoder is OpenH264 compiled in, which Cisco's patent licence does not cover. VP9, Opus and MP3 are royalty-free; MP3's patents have expired.
- **Claude may download and run pinned LGPL builds,** for development and tests.

## The binary

- **Source:** BtbN's FFmpeg-Builds, release `autobuild-2026-11-13-12-43`, ffmpeg `n8.1.3-35-gf1acb0a266`, the LGPL **shared** variant. It is about half the size of the static one, and the shared libraries can be replaced, as the LGPL expects.
  - Linux x64: `ffmpeg-n8.1.3-35-gf1acb0a266-linux64-lgpl-shared-8.1.tar.xz`, SHA-256 `67b307fb2b07d2510a8d61cda583695560af1c76e355969e37133e66f98db7c4`.
  - Windows x64: `ffmpeg-n8.1.3-35-gf1acb0a266-win64-lgpl-shared-8.1.zip`, SHA-256 `57cb10e4703b88edf55aa49e94dee19fd12f555f82ed3493a8cd70c847699996`.
- **macOS:** BtbN publishes no macOS build. The pipeline is off on macOS (media are kept as imported, with a notice in the log) until a Mac build exists. That build would be ours, made on a Mac runner once CI resumes in December.
  - **Since session 103 (2026-11-23):** that build exists, VP9, Opus and MP3 from pinned sources, no H.264 or AAC, and the patented formats refused as on Linux (`docs/licences.md`). The "without ffmpeg" notes below now apply only when `vendor/ffmpeg` is missing.
- **Since session 105 (2026-11-23): our own build on every system,** replacing BtbN's (`docs/briefs/R1-own-ffmpeg-builds.md`). `npm run fetch:ffmpeg` runs `scripts/build-ffmpeg.sh`, natively on macOS and Linux and through WSL for Windows, and patented formats are refused everywhere. The BtbN details above and below are history.
- **Fetching:** `npm run fetch:ffmpeg` downloads the build for this machine, checks its SHA-256, and keeps only what is run into `vendor/ffmpeg/<os>-<arch>/`, which git ignores:
  - `bin/ffmpeg`, `bin/ffprobe`;
  - the shared libraries (`lib/*.so.*` on Linux, `bin/*.dll` on Windows);
  - `LICENSE.txt`.
- **Packaging:** electron-builder copies that folder to `resources/ffmpeg` on Linux and Windows. In development, main uses `vendor/ffmpeg`. `VEDRAOPUS_FFMPEG_DIR` overrides both (for tests).
- **Licence obligations:** in `docs/licences.md`. LGPL v3 (the build uses `--enable-version3`): ship the licence text, offer the corresponding source, and keep the libraries replaceable.
  - **Before public release:** this prebuilt build contains far more than we use, including the OpenH264 encoder and the H.264 and AAC decoders, and its libraries are 170 MB. Installers for users should ship a minimal LGPL build of our own: VP9, Opus and MP3 encoders, and decoders for what authors import. That is a CI job for December. This package makes the pipeline work with any ffmpeg it is given.

## What it does (main process, `src/main/media/`)

- **Probe** every imported audio or video file with `ffprobe` (JSON): container, streams, codecs, duration, picture size.
- **Normalise:**

  | Kind of file                                                        | What happens                                                                                                                                         |
  | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
  | MP3 audio                                                           | Kept as it is.                                                                                                                                       |
  | Any other audio (WAV, M4A, OGG, and our WebM narration recordings)  | Converted to MP3 (`libmp3lame`, VBR quality 2).                                                                                                      |
  | WebM video already in VP8 or VP9 (sound in Opus or Vorbis, or none) | Remuxed without re-encoding (`-c copy`), so the file gets its seek index and duration. Recordings lack both, and Firefox cannot seek in them (P6.2). |
  | Any other video (mp4, mov, …)                                       | Converted to WebM: VP9 (`crf 33`, `cpu-used 5`, row multithreading) and Opus 96 kb/s.                                                                |

  The asset stored is the result, named by its own SHA-256, with the new extension and type. The file name shown keeps the author's name with the new extension ("narration.wav" becomes "narration.mp3"). The metadata gets `duration`, and `width` and `height` for video, from the probe.

- **Posters:** for each video, a frame at `min(1 s, a tenth of its length)` is saved as PNG and added as an image asset. The import result carries it with the video (`poster`), so Insert → Video… sets it as the poster. A video inserted later from the Media panel shows its first frame, as before.
- **Waveforms** stay in the renderer (Web Audio, P6.1). After normalisation every sound decodes there, so the pipeline need not make them; the plan listed waveforms in case decoding failed.
- **Recordings:** `project:storeRecording` converts the take to MP3 before storing it.
- **Progress:** long conversions report through a new event, `event:mediaProgress` (`{ fileName, fraction }`), and the status bar shows "Converting film.mp4… 42%". ffmpeg runs as a child process (`child_process.spawn`, not a native module), with `-progress pipe:1`.
- **Without ffmpeg** (macOS for now, or a missing `vendor` folder): media are stored as imported, exactly as before P6.3, and main logs once that the pipeline is off.
- **Failure:** if ffmpeg cannot read a file, the import is refused with the reason ("could not be converted"), as unsupported files are.
- **On Linux, only royalty-free formats are read** (added after the package, by Luke's decision): anything that needs a patent licence to decode is refused through an allow-list. The import names the format and asks for a WebM, MP3, WAV, Opus or FLAC file instead. On Windows and macOS they are to be read through the operating system's licensed decoders, with our own ffmpeg build (see `docs/licences.md`).

## Done when

- **Unit tests** (main, pure): the decision for each kind of probe result; parsing probe output and progress lines.
- **Integration tests** (main) with the real binary. They run wherever `vendor/ffmpeg` exists, which CI makes sure of on Linux and Windows, and fail there if it is missing. On macOS they are skipped with that reason.
  - WAV to MP3, with the right duration;
  - mp4 to VP9/Opus WebM;
  - a WebM without cues or duration (ffmpeg writes those to a pipe) remuxed so it has both;
  - a poster frame;
  - a recording stored as MP3;
  - a file ffmpeg cannot read refused.
- **Player, Firefox:** a WebM that has been through the pipeline plays from its trim start. In P6.2, Firefox stuck on a recorded WebM.
- **e2e:**
  - importing a WAV gives an MP3 asset;
  - Insert → Video… with an mp4 gives a WebM with a poster set, which plays when published;
  - a recorded narration is stored as MP3.

## Not in this package

- Our own minimal ffmpeg builds for each platform (CI, December), and the macOS pipeline.
- Cancelling a long conversion (progress is shown; cancel later).
- Keeping originals beside the converted files, quality settings, and H.264 output.

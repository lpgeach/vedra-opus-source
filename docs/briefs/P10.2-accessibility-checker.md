# P10.2 The authoring-side accessibility checker

**Plan:** "Authoring-side accessibility checker listing missing alt text, focus-order problems, low contrast, missing captions."

The course side of accessibility is P10.1 (`P10.1-accessibility.md`). This package tells the author, while they work, what a learner who uses a screen reader, the keyboard or captions will miss. It uses the same rules as the course, so the checker and the player cannot disagree.

## The check

`accessibilityIssues(project)` in `packages/model/src/a11y-check.ts`: a pure function, and no saved-format change. It goes through every scene slide and every bank slide, base layer and overlays, groups included. Each issue:

```ts
interface A11yIssue {
  kind: 'altText' | 'focusOrder' | 'contrast' | 'captions';
  slideId: string;
  objectId: string | null;
  /** Plain words for the author, naming the object. */
  message: string;
}
```

Issues come in course order: slide by slide, and on each slide by layer and then by position.

### Missing alt text

Only objects a screen reader reads (`visibleToAssistiveTech`), and not a question's answers, which have their own words:

- a picture, an icon or illustration (graphic), or a 360° image with no alt text;
- a button, or anything a click trigger names, with no words and no alt text: the learner hears only its object name.

A shape with no words and no alt text is not listed. It reads as nothing, as decoration does, and most such shapes are backgrounds and panels: a first version listed every feedback layer's panel.

### Focus-order problems

On each slide, among the objects Tab reaches (`tabbableObjects`):

- two or more with the same name, as the course names them (alt text, then words, then object name), so the learner cannot tell them apart. Only objects the learner meets together count: on the base layer, or on one overlay and the base beneath it. Two feedback layers' Continue buttons never show at once;
- one that lies wholly outside the slide: Tab reaches it, but nobody sees it;
- the author's own Tab order (`focusOrder`) leaves some out: they come after the listed ones, by layout. That may be what the author wants, so it is said once per slide, naming them.

### Low contrast

For each run of text in a text box, shape, button, choice or table cell, its colour against what is behind it:

- the object's own solid fill;
- for a text box, the topmost shape with a solid fill beneath it on the same layer that holds its middle;
- otherwise the slide's background (the theme's).

The colours are theme references or literal colours, the text's own colour mark first. A colour with alpha is laid over what is behind it.

- **Thresholds:** 4.5 : 1, or 3 : 1 for large text (24 pixels and up, or 18.66 bold and up), as WCAG 1.4.3 has it.
- A gradient or picture behind the text cannot be judged: it is skipped, not guessed.
- One issue per object: its lowest ratio, and the ratio needed.
- Shapes drawn by a master or layout behind the slide are not considered (said in the panel's help line).

### Missing captions

- A video with no captions.
- A sound with no captions. Text-to-speech sounds are included: the words are known, but a deaf learner still needs them shown.

## The panel

The right panel gets a fourth tab, **Check**, beside Format, Triggers and Layers:

- a line saying how many problems were found, or "No problems found";
- the issues, grouped under each slide's title, each with a **Show** button that goes to the slide and selects the object;
- the list follows the project as it changes, so a fix takes its line away.

The panel lists problems only. Fixes are made where they belong: the Tab order in the Slide panel, captions in the media's panel, and alt text and decoration in the Format panel.

**Found while writing this:** the editor had no way to set alt text or mark an object decorative. The model has had both since Phase 0, and the course has read them since P10.1 part A, but no panel edited them, though P10.1's plan line names alt text. This package adds an **Accessibility** section to the Format panel for a single selected object: "Alt text", and "Decorative: screen readers skip it". Without it, the checker's advice could not be followed.

## Done when

- **Model tests** for each kind: what is found, and what is not (decoration, question parts, gradients, large text at 3 : 1).
- **e2e:** a project with problems shows them in the Check tab. Show selects the object; fixing the alt text removes the line.

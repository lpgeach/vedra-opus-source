# Brief: P2.1 — Application shell

> **Status: implemented 2026-11-15.** Kept for the reasoning. `docs/development.md` ("The editor window") describes what was built. Luke has not yet reviewed the look and layout.

Plan entry: `docs/PLAN.md` section 8, P2.1. Depends on P0.2 and P1.2 (both done).

## Goal

The window an author works in: a command area at the top, panels around a central stage, and two top-level views. Panels hold placeholder content for now; later packages fill them. Panels can be resized and collapsed, and the arrangement comes back after a restart.

## Layout

```
┌──────────────────────────────────────────────────────────────────────┐
│ Top bar: save · undo · redo │ project title │ Overview | Slide View │
├──────────────────────────────────────────────────────────────────────┤
│ Ribbon tabs: Home  Insert  Design  Transitions  Animations  View     │
│ Ribbon commands for the active tab, in labelled groups               │
├───────────┬──────────────────────────────────────────┬───────────────┤
│ Slides    │                                          │ Triggers      │
│ Media     │              Stage                       │               │
│ (tabs)    │                                          ├───────────────┤
│           ├──────────────────────────────────────────┤ Slide Layers  │
│           │ Timeline | States | Notes                │               │
├───────────┴──────────────────────────────────────────┴───────────────┤
│ Status bar: slide n of m · saved state · file path                   │
└──────────────────────────────────────────────────────────────────────┘
```

- **Slide View** is the layout above. **Overview** replaces everything between the ribbon and the status bar with the scenes and their slides as cards; double-clicking a card opens that slide in Slide View. Cards show titles only until thumbnails arrive in P2.6.
- The bottom panel sits under the stage only, so the side panels keep their full height.
- With no project open, the welcome screen fills the window and the ribbon is not shown.

## Decisions

1. **Panels are fixed in place.** They resize and collapse but do not float, dock elsewhere or detach. This covers the plan's wording and avoids a docking system nobody has asked for.
2. **Resizing.** A splitter sits on the inner edge of each panel. Drag it with the pointer, or focus it and use the arrow keys (Shift for bigger steps). Sizes are clamped so no panel shrinks below a usable minimum and the stage always keeps at least 320×200. The clamping is a pure, unit-tested function (`renderer/layout.ts`).
3. **Collapsing.** Each panel has a collapse button in its header; a collapsed panel leaves a thin rail with a button to bring it back. The View tab has a toggle for each panel and "Reset Layout".
4. **What is remembered.** Panel sizes, which panels are collapsed, the active tab in the left and bottom panels, and the theme. Not remembered: the ribbon tab and the view (every project opens in Slide View on Home).
5. **Where it is remembered.** `settings.json` in the app's user-data folder, read and written by the main process through two new IPC calls (`settings:load`, `settings:save`). A missing or damaged file falls back to defaults. This is application state, not project state, so it does not go in the `.vedraopus` file.
6. **Themes.** Light, Dark, or Follow System (the default), chosen on the View tab. Main applies the choice with `nativeTheme.themeSource`, so native menus and dialogs match, and the page sets `color-scheme` from the same choice. All colours are CSS custom properties defined once with `light-dark()`.
7. **Look.** Our own: neutral greys, one indigo accent, 13 px system font, 4 px spacing grid, flat panels separated by hairlines. Icons are drawn for this project as inline SVG (no icon library, nothing borrowed).
8. **Existing features keep a home.** Save, Undo and Redo move to the top bar; the project title is edited there; Import Media is on the Insert tab and the imported files list under the left panel's Media tab.
9. **Small real behaviour, so the shell is not hollow.** The Slides list shows the project's scenes and slides and selecting one makes it current; Insert → New Slide adds one after the current slide (the `slide.add` command already exists). Renaming, reordering, duplicating and deleting slides belong to P2.6.
10. **Menu.** View → Overview / Slide View and Insert → New Slide become live. Everything else disabled stays disabled until its package.

## Out of scope

Drawing objects on the stage (P2.2, P2.3), text (P2.4), the format panel (P2.5), thumbnails and slide management (P2.6), real timeline/states/triggers/layers content (P3–P4). Their panels say what will go there.

## Tests

- Unit: layout clamping; settings parsing falls back to defaults for missing or invalid input.
- End to end: every panel shows its placeholder; dragging a splitter and using the keyboard both resize; collapse and expand; after a restart, sizes, collapsed state, tabs and theme are as they were left; switching views; New Slide adds and selects a slide; dark theme changes the page's colours.
- The project-file tests from P1.3 are updated for where the controls now live, with the same assertions.

## Done when

Panels render placeholder content, resize, and restore after restart (the plan's line), and all checks are green on the three systems.

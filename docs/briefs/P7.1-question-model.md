# P7.1 Question model and Form View

**Work package:** P7.1, the first of Phase 7 (Quizzing).

**Plan line:** question slides with a form editor alongside Slide View: prompt, choices, correct answers, score (by question or by choice), attempts, shuffle, feedback (by question, by choice, none), branching per feedback, required/optional.

## Luke's decisions (2026-11-18)

- **Linked objects.** The form makes ordinary objects on the slide: the prompt (a text box), a **choice** object for each answer, and a Submit button. Authors move and restyle them in Slide View; the form edits their words and the question's settings.
- **First types:** multiple choice and multiple response. P7.2 adds the rest of the graded types on the same model.
- **Answer and submit in the course.**
  - Submit checks the answer, counts the attempt, records the score and takes the branch.
  - The feedback _text_ is kept now. The layers that show it, try-again, and review come in P7.5.

## Saved format version 13

### The question, on its slide

`slide.question: Question | null`:

```ts
Question {
  kind: 'multipleChoice' | 'multipleResponse',
  prompt: Id | null,            // a text object on the slide's base layer
  submit: Id | null,            // a button on the base layer that submits
  choices: Choice[],            // in the author's order
  scoring: { by: 'question', points: number } | { by: 'choice' },   // points 0–1000
  attempts: number | null,      // 1–10, null for unlimited
  shuffle: boolean,
  feedback: {
    by: 'question' | 'choice' | 'none',
    correct: string,
    incorrect: string,
    tryAgain: string,
  },
  branch: { correct: JumpTarget | null, incorrect: JumpTarget | null },   // null: the next slide
  required: boolean,
}
Choice {
  id,
  object: Id,          // a choice object on the base layer
  correct: boolean,
  points: number,      // −1000–1000, used when scoring is by choice
  feedback: string,    // used when feedback is by choice
}
```

- **Validation:**
  - the prompt is a text object, the submit a button, and each choice a choice object, all on the slide's own base layer, each used once;
  - a multiple-choice question has at most one correct choice;
  - at most 20 choices;
  - choice ids are unique project-wide.
  - A question may have no correct answer yet; the form says so.

### Choice objects

- **The type:** `choice`, with `props: { text: RichText, mark: 'radio' | 'checkbox', padding }`. It is drawn as a round or square mark beside its words. Every choice object has a built-in `selected` state, and the mark is filled when it is drawn in that state.
- **Drawing by state:** `renderObject(object, context, state)` gains an optional state, used only by choices. The player and the editor pass the state they draw.
- **Picking answers:**
  - multiple choice gives its choices one `buttonSet` (the question's id), so picking one unpicks the others, as `selected` already works;
  - multiple response leaves them in no set, so each toggles.

### The action

`submitInteraction`, which submits the slide's own question. The form puts it on the Submit button's click.

- **Migration 12 → 13** adds `question: null` to every slide. Legacy fixture `v12-two-slides`.

### Commands

- **`slide.setQuestion { slideId, question }`** sets the question or removes it (null), validated.
- **`object.remove`:** removing a linked object takes it out of its question (a choice is dropped; a prompt or submit becomes null).
- **Copies:** duplicating a slide gives its question new choice ids, pointing at the copies, through `renewObjectIds` and the slide clone.

## Runtime (engine)

- **The answer:** the choices whose objects are drawn in `selected`.
- **Submit (`submitInteraction`):**
  - **Nothing chosen:** nothing happens, and a `questionUnanswered` event is raised for P7.5's message.
  - **Correct:**
    - multiple choice: the one correct choice is chosen;
    - multiple response: exactly the correct ones are.
  - **Score:**
    - by question: the points if correct, otherwise 0;
    - by choice: the sum of the chosen choices' points, never below 0.
  - **Attempts:** each submit uses one. If the answer is wrong and attempts remain (or attempts are unlimited), the result is `tryAgain`, and the learner can change the answer.
  - **Otherwise the question is finished** (`correct` or `incorrect`):
    - its choices take no more input;
    - the response is recorded;
    - the branch is taken: the branch's slide, or the next slide when it is null.
  - A `questionSubmit` event is raised with the result, the score and the attempt number.
- **Shuffle:** on entering a slide afresh, the choice objects swap places in a random order. The engine takes `random?: () => number` (default `Math.random`) so tests can fix it. This is drawn through the same offsets as motion paths. It is kept on resume.
- **Required:** while a required question is unfinished, Next is off (`canNext` false) and `next()` does nothing. Triggers can still jump.
- **Revisiting** a finished question shows it finished, with its answer, whatever the slide's revisit setting. A fresh visit only resets an unfinished one.
- **Session state:** `SessionState.q`, by slide: the chosen choice indexes, the result, the score, the attempts used and the shuffle order.
  - It goes through the LMS suspend codec (rule 17), with a round-trip test.
  - Reporting answers to the LMS (`cmi.interactions`, xAPI `answered`) is P7.7.

## Editor

- **Insert → Question…** (multiple choice or multiple response) adds a new question slide after the current one. It has a prompt text box, three choices (the first correct), a Submit button with its trigger, and the question in Form View.
- **Form View and Slide View.** A question slide has a _Form_ / _Slide_ switch above the stage. Form View holds:
  - **Type:** multiple choice or multiple response. Switching keeps the choices, sets their marks and button set, and keeps at most one correct choice for multiple choice.
  - **Question:** the prompt's words, plain text, which set the prompt object's text.
  - **Choices:** one row each, with its words (setting the choice object's text), Correct (a radio or checkbox by type), Points (when scoring is by choice) and Feedback (when feedback is by choice); Add, Delete, and up and down to reorder.
    - A new choice is placed under the last one.
    - The form's order is the question's order, and shuffle aside, the order the choices are read in.
  - **Score:** by question (points) or by choice.
  - **Attempts:** a number, or unlimited.
  - **Shuffle** and **Required**.
  - **Feedback:** by question, by choice, or none, with the correct, incorrect and try-again texts for by question.
  - **Branching:** after correct and after incorrect, the next slide or a chosen slide.
  - **A warning** when there is no correct answer.
- **Undo:** every change is one undo step: `slide.setQuestion`, plus `object.update` for words, and `object.add` or `object.remove` for choices.
- **Slide View:** the objects are ordinary. Deleting a choice object drops it from the form.
- **Trigger wizard:** the "Submit the question" action.
- **Slide list:** question slides show a small mark.

## Done when

- **Model:**
  - the question schema and validation;
  - choice objects;
  - `slide.setQuestion`;
  - `object.remove` dropping links;
  - copies renewing choice ids;
  - migration 12 → 13 and the legacy fixture;
  - the property test making question slides, changing them and deleting their choice objects.
- **Engine:**
  - multiple-choice and multiple-response answers marked correct and incorrect;
  - score by question and by choice (with negatives floored at 0);
  - attempts and try-again, then finishing;
  - branching, including the defaults;
  - unanswered submits;
  - required blocking Next;
  - a finished question locked, and kept on revisit and resume;
  - shuffle with a fixed `random`, kept on resume;
  - the session state through the suspend codec.
- **Render:** a choice in each mark style, selected and not (unit tests, and a visual test).
- **Player browser (Chromium and Firefox):** a multiple-choice question answered correctly takes the correct branch; a multiple-response question answered wrongly twice, with two attempts, ends incorrect; required blocks Next.
- **e2e:** Insert a multiple-choice question; in Form View change the prompt, a choice's words, the correct answer, attempts and the branch; switch to Slide View and see the words; save and reopen; publish, answer in the course, and see the branch taken.

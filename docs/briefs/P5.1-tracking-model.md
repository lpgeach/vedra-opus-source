# P5.1 Tracking model

**Work package:** P5.1, needs P3.1 (done). **Status:** implemented on branch `wp/p5.1-tracking`.

Plan line: completion by number of slides viewed, a result slide (from P7; stub until then), or a "complete course" trigger; reporting status pair options; resume always, never, or prompt. The plan gives no "Done when"; this brief sets one.

## Saved format version 4

```ts
project.tracking = {
  completion: { kind: 'slidesViewed'; count: number | null }   // null: every slide
            | { kind: 'trigger' },                              // only a "complete course" action
  reporting: 'completed-incomplete' | 'passed-incomplete' | 'passed-failed' | 'completed-failed',
  resume: 'always' | 'never' | 'prompt',
}
```

Default (and what migration 3→4 adds): `{ completion: { kind: 'slidesViewed', count: null }, reporting: 'completed-incomplete', resume: 'prompt' }`.

New trigger action `{ type: 'completeCourse' }` (the plan's "complete course"). Additive, no migration needed.

**Result slide:** not in the format yet. It arrives with quizzes (P7), which add it and their own format bump. Until then the engine's success is always `unknown`; that is the stub and the extension point.

## Engine

- `engine.getTracking()`: `{ complete: boolean; success: 'unknown' | 'passed' | 'failed'; progress: number }` (progress is slides visited / slides, 0 to 1).
- Completion: by slides viewed (visited count reaches `count`, or every slide when null) or by a `completeCourse` action. Either way it never goes back to incomplete. The completeCourse action also completes a course set to slides viewed.
- A `trackingChange` event when `complete` (or later `success`) changes; drivers commit on it.
- Saved in `SessionState` (`c: 1`), so a resumed course stays complete.
- `reportStatus(reporting, tracking)` (pure, exported): what to tell an LMS:
  - `completion: 'completed' | 'incomplete'`, `success: 'passed' | 'failed' | 'unknown'`, and `lessonStatus` for SCORM 1.2's single field.
  - Per pair, while incomplete: `incomplete`. Once complete: `completed-*` → `completed`; `passed-*` → `passed` (with no quiz, completing the course is passing it). `failed` is reported only when success is `failed` (P7) and the pair includes failed; with `-incomplete` pairs a failure reports `incomplete`.

## Player

- `resume: 'never'` ignores a saved session; `'always'` continues it; `'prompt'` shows "Continue where you left off?" with Continue and Start over before anything plays. Only asked when there is a saved session to continue.
- `options.onTrackingChange(tracking)` for drivers.

## Editor

- Design tab → Course group → **Tracking…** dialog: complete when (slides viewed: all or a number / only by a trigger), report to the LMS as (the four pairs, in plain words), when a learner returns (resume always / never / ask).
- Trigger wizard: **Complete the course** action.

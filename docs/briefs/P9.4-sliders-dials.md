# P9.4 Sliders and dials

**Work package:** P9.4. It needs P9.2 (variables bound to fields, PR #71).

**Plan line:** sliders and dials bound to number variables, with range, step and their move events.

**What they are:** two new objects the learner moves to choose a number:

- a **slider** is a track with a thumb, across or upright;
- a **dial** is a knob turned through three quarters of a circle.

Each has a least and greatest value and a step. Each may be bound to a number variable, and has a "moves" trigger event.

**My design choices** (Luke asked to go through all of Phase 9), listed for him to change:

1. **The variable follows the control as it moves**, not on letting go: `%Variable%` text and triggers on "variable changes" see each step. A trigger that changes the variable moves the control to match.
2. **Values:**
   - always a multiple of the step from the least value, within the range;
   - a value from the variable that is not one is shown at the nearest one, but the variable is left alone until the learner moves the control;
   - **unbound,** a control starts at its initial value. That value is not saved in the session.
3. **"A slider or dial moves":**
   - one event for both, raised each time the value changes to a new step, after the variable is written;
   - not raised when a trigger sets the variable.
4. **Keyboard and screen readers:**
   - both are `role="slider"` with `aria-valuemin`, `aria-valuemax` and `aria-valuenow`, named by their alt text or name;
   - the arrow keys move one step; Page Up and Page Down move ten; Home and End go to the ends.

   A slider is a native range input in the course; a dial is drawn by us and given the same semantics.

5. **A dial's sweep:** from 135° left of straight up to 135° right of it, the least value at the left.
6. **Looks:** a colour (the thumb, the filled part, the dial's pointer and arc) and a track colour, as theme colours or any colour. A slider runs across or upright, by a setting rather than by its shape.

## Saved format version 28

```ts
SliderObject { …objectBase, type: 'slider', props: {
  variable: id | null, min: number, max: number, step: number, initial: number,
  orientation: 'horizontal' | 'vertical', color: Color, trackColor: Color } }
DialObject { …objectBase, type: 'dial', props: {
  variable: id | null, min: number, max: number, step: number, initial: number,
  color: Color, trackColor: Color } }
TriggerEvent += { type: 'controlMoves', object: id }   // a slider or dial
```

- **Validation:**
  - `min < max`;
  - `0 < step ≤ max − min`;
  - `initial` within the range;
  - the variable is a number variable;
  - the event's object is a slider or dial of its slide.
- **Variables:** removing a variable, or changing its type, unbinds these controls, as it does fields (P9.2).
- **Migration 27 → 28:** nothing to change.
- **Legacy fixture:** `v27-two-slides`.
- **Model helpers:** `snapToStep(props, value)` and `createSliderObject` / `createDialObject`.

## Runtime

- **Engine:**
  - `engine.moveControl(objectId, value)`: snap and clamp; if the value is new, write a bound variable and raise `controlMoves`;
  - the view gives each slider and dial `value`, from the variable when bound, or else from the control.
- **Render:**
  - in the editor and thumbnails, a picture of the control at its initial value;
  - in a course (`liveMedia`), a slider is an `<input type="range">` and a dial an element with slider semantics.
- **Player:** follows the view; a slider's input and a dial's drag and keys call `moveControl`.

## Editor

- **Insert → Data Entry** gains Slider and Dial.
- **The Format panel:** variable (number variables only), least, greatest, step, initial, orientation (sliders), and the two colours.
- **The trigger wizard:** the event "a slider or dial moves".
